# Формати вихідних зображень

Chloros експортує оброблені результати у чотирьох форматах файлів. Виберіть формат у налаштуваннях проєкту (графічний інтерфейс), за допомогою `--format` (CLI) або `export_format` (SDK). CLI та SDK приймають саме наведені нижче рядки.

| Форматний рядок | Розширення | Тип пікселя | Діапазон пікселів | Примітки |
| --- | --- | --- | --- | --- |
| `TIFF (16-bit)` *(за замовчуванням)* | `.tif` | цифрове число типу uint16 | 0 – 65535 | Рекомендується для фотограмметрії / ГІС. |
| `TIFF (32-bit, Percent)` | `.tif` | float32 | 0,0 – 1,0 | 1,0 = 100% відбивання. Деякі програми не можуть читати TIFF-файли з плаваючою комою; такі файли мають більший розмір. |
| `PNG (8-bit)` | `.png` | цифрове число типу uint8 | 0 – 255 | Стиснення без втрат, підходить для перегляду в Інтернеті та візуалізації. |
| `JPG (8-bit)` | `.jpg` | цифрове число типу uint8 | 0 – 255 | Стиснення з втратами, найменші файли. |

## Де зберігаються вихідні файли

Файли записуються у папці проєкту, згруповані за камерами, а потім за форматами файлів:

```
<project>/
└── LATT-M3M-L41-F550/                  # one folder per camera (model+lens+filter)
    ├── tiff16/                          # follows --format: tiff16, tiff8, png8, jpg8, or tiff32
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one <INDEX>_Index_Images/ folder per requested index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

Папка камери має назву `LATT-<sensor>-<lens>-F<filter>` для LATTICE та `<model>_<filter>` (наприклад, `Survey3N_RGN`) для Survey3. **Кожен експортований продукт зберігає ім’я вихідного файлу — папка ідентифікує продукт, а не розширення імені файлу.** Повні правила див. у розділі [Де зберігаються результати](reference/cli-reference.md) у Довіднику CLI.

## Продукти LATTICE (рівні захоплення та експорту)

Один необроблений кадр LATTICE розгалужується на всі запитувані продукти за один прохід. Кожен тип продукту має власний перемикач (прапорці в графічному інтерфейсі або CLI `--debayered` / `--preview` / `--radiance` / `--reflectance`, за замовчуванням усі увімкнені):

| Рівень | Вміст | Тип даних |
| --- | --- | --- |
| `raw` | Дані Байєра безпосередньо з сенсора (монохромні камери: одна смуга). Обробка завжди починається з необроблених даних. | Як записано |
| `debayered` | Лінійна демозаїка — 3-канальна для M3C, 1-канальна у відтінках сірого для M3M. | Лінійна DN |
| `radiance` | Абсолютна спектральна яскравість з повного радіометричного ланцюга, у **Вт/м²/ср/нм**. Завжди записується як 32-бітний TIFF (`tiff32/Radiance_Images/`), незалежно від обраного формату експорту. | float32 |
| `reflectance` | Коефіцієнт відбиття ρ, де **DN 32768 = ρ 1,0 (100%)** із запасом до ρ 2,0. Готовий для Pix4D. | uint16 |
| `preview` | Рендеринг, готовий до відображення: RGB = баланс білого + гамма; мультиспектральний = розтягнення у фальшивих кольорах. | 8-бітне відображення |

## Зчитування значень пікселів відбивної здатності

Відбивна здатність зберігається у вигляді цілого цифрового числа, і **DN, що відповідає ρ = 1,0 (100 % відбивної здатності), залежить від вихідної камери**:

| Вихідна камера | ρ = 1,0 відповідає DN | Як визначити |
| --- | --- | --- |
| LATTICE (M3C / M3M) | `32768` (діапазон до ρ 2,0) | У файлі вказано тег XMP `Chloros:PixelScale=32768`. |
| Survey3 | `65535` (обрізано при ρ 1,0) | Тегів XMP `Chloros:*` немає — саме ця відсутність є ознакою. |

**Прочитайте тег XMP `Chloros:PixelScale` і розділіть на нього**, замість того щоб припускати, що це константа. Тег визначений у домені uint16, тому він залишається незмінним `32768` у всіх форматах виводу, що змінюють масштаб — спочатку нормалізуйте збережений тип даних назад до uint16 (×257 від 8-бітного, ×65535 від float32).

{% hint style="warning" %}
**Один випадок за задумом не передбачає масштабування.** Коли знімок із 8-бітним джерелом (BayerRG8) записується як 8-бітний TIFF, конвеєр обрізає значення до діапазону 0–255 замість перемасштабування, тому файл не має масштабу — Chloros навмисно опускає `Chloros:PixelScale` у цьому випадку. Якщо тег відсутній у файлі відбиття LATTICE, не слід припускати наявність масштабу; натомість переекспортуйте файл у 16-бітному або 32-бітному форматі.
{% endhint %}

Повні правила (включно з тегами, сумісними з MicaSense) див. у розділі **«Зчитування пікселів відбиття»** у [Довіднику CLI](reference/cli-reference.md).
