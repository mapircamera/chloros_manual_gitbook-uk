# Початок роботи

<div data-full-width="false"><figure><img src=".gitbook/assets/chloros_logo_transparent.png" alt=""><figcaption></figcaption></figure></div>

Chloros — це програмне забезпечення від [MAPIR](https://www.mapir.camera), призначене для обробки мультиспектральних знімків, управління обладнанням MAPIR у режимі реального часу та запису даних з датчиків. Chloros 1.3.0 підтримує всю лінійку продуктів MAPIR:

* **Камери Survey3** — обробка знімків у форматі RAW+JPG для отримання каліброваних карт відбиття та індексів рослинності. Див. [Підтримувані камери](supported-cameras.md).
* **Камери LATTICE** — підключення мультиспектральних камерних модулів GigE у режимі реального часу, поодинці або у вигляді синхронізованих мультикамерних масивів: попередній перегляд, зйомка та обробка з отриманням каліброваних продуктів випромінювання та відбиття. Див. [розділ LATTICE](lattice/README.md).
* **Світлові датчики DAQ** — спектральні датчики DAQ-U (USB), DAQ-M (Bluetooth), а також DAQ-E та DAQ-E-S (Ethernet): калібровані спектри в режимі реального часу, `.daq` записи та освітлення, що падає зверху, для обробки коефіцієнтів відбиття. Див. [розділ про DAQ](daq/README.md).

{% hint style="success" %}
**Що нового в Chloros 1.3.0**: AI-асистенти можуть керувати Chloros через `chloros-mcp`, а CLI, SDK та `chloros-mcp` пропонують ті самі функції. Продукти з індексом LATTICE вдосконалено, масиви повних датчиків працюють швидше та сумісні з будь-якою мережею, а серверна частина продовжує працювати між командами. Ознайомтеся зі списком нововведень нижче та [завантажте](download.md) інсталяційні файли.
{% endhint %}

## Що нового в Chloros 1.3.0

* **Штучний інтелект може керувати Chloros.** `chloros-mcp` — сервер MCP, встановлений разом із Python SDK, дозволяє Claude Desktop, Claude Code, Cursor та іншим клієнтам MCP обробляти зображення та керувати камерами LATTICE, масивами та світловими датчиками DAQ. Див. [Використання Chloros із штучним інтелектом](ai-assistants.md).
* **CLI, SDK та `chloros-mcp` пропонують однакові функції.** З міркувань безпеки лише вхід у систему, налаштування DAQ-E та прямі сервери DAQ залишаються у CLI. Деякі скрипти версії 1.2.0 потребують змін: див. розділ **Зміни у версії 1.3.0** у верхній частині [Довідки щодо CLI](reference/cli-reference.md) та [Довідки щодо SDK](reference/sdk-reference.md).
* **Покращено індексні продукти LATTICE.** Показник NDVI та інші індексні продукти, експортовані з знімків LATTICE, покращено в усіх режимах обробки.
* **Параметри інсталятора для Windows.**У розділі**Системні налаштування**інсталятор пропонує параметри**Увімкнути довгі шляхи Windows**та**Виключити бекенд Chloros зі сканування Microsoft Defender**; обидва параметри за замовчуванням увімкнені. Перша опція дозволяє розміщувати папки проектів у каталогах, довжина шляху до яких перевищує 260 символів; друга запобігає уповільненню зйомки камерою внаслідок сканування в режимі реального часу (при високій частоті зйомки це становить близько 30 % від швидкості зйомки). Тепер інсталятор також додає папку CLI до `PATH` лише один раз і видаляє дублікати записів, залишені попередніми версіями інсталятора. Див. [Завантажити](download.md).
* **Глибокі папки проектів відхиляються на самому початку.** Якщо довгі шляхи в Windows вимкнені (за замовчуванням у Windows), папка проекту, яка занадто глибока для обмеження шляху в 260 символів, відхиляється ще до початку виконання, при цьому вказується найдовша папка проекту, яка відповідає вимогам, та інструкція щодо увімкнення довгих шляхів. Раніше під час такого запуску продукти не записувалися. При увімкнених довгих шляхах продукти у дуже глибоких папках тепер зберігають свої метадані (теги GPS та XMP).
* **Маски обмеження значень.** Коли розкладання по смугах продукту яскравості або відбиття LATTICE дає від’ємне значення смуги, це значення обмежується до нуля, а маска для кожного пікселя у папці `clamp_masks/`, розташованій поруч із папками продуктів, фіксує, які пікселі та смуги зазнали змін. Продукт вказує назву своєї маски у тезі `Chloros:UnmixClampMask`. Потокові перегляди тепер обрізаються точно так само, як і під час експорту. Див. [Формати вихідних зображень](output-image-formats.md).
* **Продукти містять опис самих себе.** Індексні продукти мають власні теги обробки (`Chloros:ProcessingLevel=index`, індексний вираз та інформацію про те, чи були вони обчислені на основі випромінювання чи відбиття) замість тегів вихідних необроблених даних. Продукти Survey3 містять теги обробки Chloros у кожному режимі обробки. Необроблені файли LATTICE та файли після дебейєрингу зберігають рідну орієнтацію сенсора та записують її в XMP; програма перегляду зображень повертає їх лише для відображення.
* **Пакеті для Linux постачаються в розпакованому вигляді.** Бекенд та CLI встановлюються як папки в каталозі `/usr/lib/chloros/`, тому вони більше не розпаковуються самостійно під час кожного запуску. На x86_64 бекенд більше не витрачає близько 100 секунд на запуск, а розмір `.deb` становить приблизно половину від попереднього. Вбудований ExifTool тепер працює на чистій установці Ubuntu. `.deb` тепер також встановлює Python SDK для системи `python3` (встановіть його за допомогою `sudo apt install ./chloros_1.3.0_<arch>.deb`), збільшує розмір буферів прийому сокетів ядра, необхідних для потоків з камери, та додає службу бекенду, яка працює під вашим обліковим записом. Пакет для Jetson, `chloros_1.3.0_arm64_jp6.deb`, створено для JetPack 6 і виконується на графічному процесорі Jetson із CUDA-версією PyTorch від JetPack. У Linux кожне експортоване зображення тепер потрапляє на диск один раз (записується та позначається в пам’яті, а потім копіюється на місце): на Jetson, де швидкість визначається диском, запуск LATTICE з 288 зображеннями займає 14 хвилин замість 24. Див. [Встановлення в Linux](linux/linux-installation.md).
* **Камери LATTICE з технологією OCN забезпечують точніше зчитування під сонячним світлом.** Яскравість, відбивна здатність та індекси отримують швидку корекцію після розкладання спектральних смуг, завдяки чому сіра мітка під сонцем зчитується з показником NDVI, близьким до нейтрального. Камери RGN залишилися без змін.
* **Повідомлення про помилки в додатку.** Іконка помилки у верхній частині вкладки «Журнал налагодження» надсилає до MAPIR опис, до 10 зображень, журнали та деталі системи. Див. [GUI: Навігація](navigation.md).
* **Масиви LATTICE.**За замовчуванням масиви зберігають повний датчик, а упакований 12-бітний транспорт (`--packed`, за замовчуванням `auto`) підвищує частоту кадрів для повного датчика приблизно на третину; масив працює в будь-якій мережі з тією частотою кадрів, яку вона дозволяє (повільний канал знижує частоту кадрів, а не відхиляє масив або зменшує розмір його кадрів); масив, камери якого перезавантажуються, відновлює роботу самостійно, з повторним увімкненням PTP; автоматична експозиція більше не знижує цю частоту при слабкому освітленні (вона заповнює період, а потім підвищує підсилення); Режим безперервної зйомки встигає за швидкими масивами; регулятор**Highlights** для камер RGB; а також `ArraySession` у SDK отримує `grab()`, `frame_stream()` та `continuous()`. Див. [розділ LATTICE](lattice/README.md).
* **Стабільніша автоматична експозиція.** Експозиція залишається незмінною при постійному освітленні та стабілізується протягом кількох секунд після зміни; невеликі яскраві ділянки більше не затемнюють сцену; при ручному налаштуванні експозиції коефіцієнт підсилення залишається в режимі «Авто»; а камера, яка перестає реагувати під яскравим сонцем, підтримується на рівні, відповідному її освітленню, яке зчитується датчиком освітленості або, якщо його немає, за допомогою власних кадрів камери. Див. [Налаштування камери](lattice/camera-settings.md).
* **Датчики освітленості.** **Підтримка DAQ-E-S:** її фіксований дифузор не потребує корекції кришки, а кожне зчитування містить дані про нахил, крен та кут нахилу пристрою. Запис вказує, чи було обрано кришку, чи її значення було припущено, а система обробки видає попередження у разі припущеного значення: моделі DAQ-U, DAQ-M та DAQ-E постачаються без кришки, тому вкажіть назву встановленої кришки. Записи Live `.daq` зберігаються навіть після відключення живлення (зберігайте файл `.daq-journal` разом із його `.daq`), а DAQ-E, що припинив передачу даних, підключається знову з позначенням пропуску у записі. Проєкт, що містить лише записи датчиків освітленості, відображає їх список та обробляє дані через додаток і CLI, а запис, зроблений за допомогою `chloros_scripts`, відображається як DAQ, що його створив, із обмеженням, яке ви можете встановити. Кожен запис зберігає значення DAQ, яке було використано. Див. [розділ DAQ](daq/README.md).
* **Обробка.**Кадри LATTICE починають оброблятися під час виявлення об’єкта. Посилання на об’єкт та DAQ визначаються для кожного діапазону окремо. При переміщенні проєкту його файли перепосилаються. Експортовані дані 8-бітного збору мають 8-бітну глибину з новим форматом**TIFF (8-біт)**. Запуск Survey3 без калібрувальної мітки зберігається як резервний продукт (`Vignette_Corrected_Images` або `Sensor_Response_Images`), а не як зображення відбиття. Теги DLS для кожного діапазону зображення відбиття завжди належать до його власного кадру. Функція Texture Aware не підтримується для знімків LATTICE, які завжди обробляються за допомогою стандартного дебейєра.
* **CLI та SDK.** Відносні шляхи до вихідних файлів тепер ведуть до папки, з якої ви запускаєте команду або скрипт (раніше встановлений бекенд намагався вирішувати їх у власній папці інсталяції, що призводило до помилок). Бекенд продовжує працювати між командами та скриптами і самостійно зупиняється після 30 хвилин бездіяльності; цим керують `chloros-cli backend status` та `backend stop`. Команди захоплення вказують імена всіх файлів, які не вдалося записати, і завершують роботу з кодом 1, а повторні захоплення зупиняються, коли диск заповнений. Успішне виконання `process` повідомляє про `Image products written: N (plus M clamp masks)`. У Windows `ChlorosLocal` з SDK / `process_folder` знаходять встановлений бекенд (або використовують той, що вже працює), а `read_image_audit_tags` працює з простого `pip install`.

## Що нового в Chloros 1.2.0

* **Управління камерами в режимі реального часу — нова вкладка «Камери».** Підключайте камери LATTICE по одній або у вигляді синхронізованих масивів з декількох камер (синхронізація часу PTP, зйомка з апаратним тригером), з накладенням попереднього перегляду в реальному часі, гістограмами для окремих діапазонів, інтелектуальною автоматичною експозицією, калькулятором індексу в реальному часі та оновленнями прошивки камер безпосередньо в додатку.
* **Світлові датчики — нова вкладка «Світлові датчики».** Підключайте датчики DAQ-U (USB), DAQ-M (Bluetooth) та DAQ-E (Ethernet); переглядайте відкалібровані спектри в режимі реального часу (Вт/м²/нм), записуйте файли `.daq` у свій проєкт, обирайте профілі корекції капа та оновлюйте прошивку DAQ-E через мережу.
* **Режими зйомки та реєстратори.** Одноразова / безперервна / інтервальна зйомка, а також режим «Найшвидша зйомка» (лише у форматі RAW); вибір для кожного проєкту, які камери та типи експорту створює функція «Зняти все»; масивні реєстратори для індексного відео моніторингового рівня та серій RAW-кадрів аналітичного рівня з офлайн-збіркою відео.
* **Конвеєр обробки LATTICE.** Імпортуйте папки з даними, зібраними LATTICE, та розбивайте кожен необроблений кадр на продукти: з дебейєрингом, попередній перегляд, яскравість у форматі float32 (Вт/м²/sr/нм) та коефіцієнт відбиття з перемикачами для кожного продукту. Значення відбиття можуть походити від калібрувальної мішені в кадрі або від даних DAQ про надходження світла; до експортованих даних застосовується вирівнювання масиву; відсутня заводська калібровка завантажується автоматично за серійним номером камери.
* **Проєкти запам’ятовують апаратне забезпечення.** Підключені камери та датчики освітленості зберігаються разом із проєктом (`cameras.json` / `sensors.json`) і підключаються знову зі збереженими налаштуваннями при повторному відкритті проєкту. Див. [GUI: Проєкти](projects.md).
* **Оновлення переглядача зображень.** Зчитування пікселів/індексів курсором із правильним масштабуванням відбивної здатності для кожного файлу, гістограми шарів, повзунок бінінгу GSD, режими сітки «На тригер» / «На камеру», перегляд продуктів LATTICE та експорт індексів/LUT у пісочницю на диск.
* **Значно розширено CLI та SDK.** Нові сімейства команд `lattice`, `daq pool-*`, `project` та `time-sync`; нові параметри `process` (`--input-level`, перемикачі для окремих продуктів, `--reflectance-source`, прапори вирівнювання масивів); дескриптори Smart-Connect для SDK (`connect_camera` / `connect_array` / `connect_daq_sensor`), які автоматично запускають бекенд; Автоматизація `open_project()`; колесо SDK входить до складу інсталяторів та опубліковано на PyPI як `chloros-sdk`.
* **Чітка семантика помилок.** Запуск `chloros-cli process`, який запитував продукти, але не записав жодного, тепер видає явне повідомлення про помилку та завершується з ненульовим кодом; успішні запуски повідомляють, скільки образів продуктів було записано.
* **Новий формат виводу.** Продукти зберігаються у папках `<project>/<camera>/<format>/<Product>_Images/` і зберігають ім’я вихідного файлу — саме папка, а не суфікс імені файлу, ідентифікує продукт. Див. [Формати вихідних зображень](output-image-formats.md).
* **Більше вхідних даних, планів та мов.** Підтримка вхідних даних `.dng`; повне наповнення всіх 38 мов інтерфейсу; апаратні обмеження для кожного плану з безкоштовним (без входу в систему) використанням до 4 камер та 2 датчиків освітлення.
* **Надійність.** Функція «Зупинити обробку» коректно завершує роботу з докладним звітом про виконання, у проєктах із кількома камерами експортуються дані з кожної камери, а оновлення інсталятора більше не призводять до виходу з системи.

Програма Chloros доступна у 3 варіантах інтерфейсу:

## Chloros: Настільна програма з графічним інтерфейсом

Автономне окреме вікно з усіма функціями, включаючи вкладки «Камери в режимі реального часу» та «Датчики освітлення». _Тільки для Windows._

## [Chloros CLI: Інтерфейс командного рядка](CLI.md)

Пакетна обробка з командного рядка та команди в режимі реального часу `lattice`, `daq pool-*`, `project` та `time-sync`. Ідеально підходить для автоматизації, створення скриптів та роботи в режимі без графічного інтерфейсу. Доступно на **Windows, Linux amd64 та Linux arm64 (NVIDIA Jetson)**. _Для доступу до CLI необхідний платний тарифний план Chloros+._

## [Chloros API: Python SDK](api-python-sdk.md)

Програмний інтерфейс на Python для автоматизації та створення власних робочих процесів: обробка повного конвеєра, сеанси роботи з камерами/масивами в режимі реального часу, сеанси роботи з датчиками DAQ та автоматизація збережених проєктів. Встановлюється разом із пакетом для настільних ПК/CLI, а також опубліковано як `pip install chloros-sdk`. _Для доступу до API необхідний платний тарифний план Chloros+._

## Почніть роботу за три кроки

1. **Встановіть** — завантажте та запустіть інсталятор для вашої платформи. Див. [Завантажити](download.md).
2. **Увійдіть у систему (не обов’язково для графічного інтерфейсу)** — графічний інтерфейс обробляє зображення безкоштовно без облікового запису. [Вхід у Chloros+](chloros+-login.md) надає доступ до паралельної обробки, прискорення на GPU, більших обмежень на кількість пристроїв та доступу до CLI/SDK.
3. **Створіть свій перший проєкт** — відкрийте Chloros, створіть [Новий проєкт](projects.md), [додайте свої зображення](processing-images-gui/adding-files-to-a-project.md) та [розпочніть обробку](processing-images-gui/starting-the-processing.md). Щоб керувати апаратним забезпеченням у режимі реального часу, відкрийте вкладку «Камери» або «Світлові датчики» — див. [GUI: Навігація](navigation.md).

## Chloros+

Хоча Chloros є безкоштовним для більшості завдань, вам може знадобитися більше можливостей. Саме в цьому випадку вам стане в нагоді платна ліцензія на Chloros+. З ліцензією Chloros+ ви зможете отримати доступ до таких нових функцій, як:

* **Багатопотокова обробка**: значно пришвидшіть обробку зображень у великих проєктах завдяки одночасній обробці зображень у конвеєрі.
* **Прискорення за допомогою GPU (CUDA)**: скористайтеся сучасними можливостями великого обсягу пам’яті графічного процесора, щоб ще більше пришвидшити конвеєр обробки зображень. Для найкращих результатів ми рекомендуємо 4 ГБ або більше відеопам’яті (VRAM).
* **Chloros+**[**CLI**](CLI.md) **Доступ**: запускайте Chloros+ з командного рядка для автоматизації та інтеграції у ваше власне програмне забезпечення. Доступно на будь-якому платному рівні; реалізується на стороні сервера.
* **Chloros+**[**API**](api-python-sdk.md) **Доступ:** запускайте Chloros+ з Python для програмного керування, що забезпечує безперебійну інтеграцію з вашими дослідницькими конвеєрами, робочими процесами аналізу даних та власними додатками. Доступно на будь-якому платному тарифі; реалізується на стороні сервера.
* **Більші апаратні обмеження**: підключайте більше камер та світлових датчиків одночасно. Без входу в систему графічний інтерфейс підтримує підключення до 4 камер та 2 світлових датчиків DAQ; платні тарифні плани збільшують обидва ліміти:

| Тариф | Камери | Світлові датчики DAQ |
| --- | --- | --- |
| Iron (безкоштовний, без входу) | 4 | 2 |
| Copper / Bronze | 6 | 3 |
| Silver | 10 | 6 |
| Gold | 20 | 12 |

* **Використання декількох пристроїв**: кожна ліцензія Chloros+ дозволяє зареєструвати 2 і більше пристроїв. Використовуйте свій обліковий запис у хмарному сервісі MAPIR для управління зареєстрованими пристроями. Додайте підтримку для більшої кількості пристроїв, оновивши свою ліцензію Chloros+.
* **Удосконалений метод дебейєрингу з урахуванням текстури:** високоякісний дебейєринг з урахуванням країв у поєднанні з моделлю шумозаглушення на основі штучного інтелекту та машинного навчання, що усуває майже весь шум, пов’язаний з дебейєрингом.
* **Налаштовані формули мультиспектральних індексів:** вводьте власні мультиспектральні індекси в растрові калькулятори Chloros, як для обробки, так і для пісочниці перегляду зображень.
* **Linux та периферійні обчислення:** запускайте Chloros на платформах Linux x86_64 та ARM64, включаючи NVIDIA Jetson, для польової та периферійної обробки. Див. [Огляд Linux](linux/linux-overview.md).
