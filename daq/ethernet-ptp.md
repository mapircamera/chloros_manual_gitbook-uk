# Мережа DAQ-E та синхронізація часу

> Інформація щодо фізичного налаштування мережі для датчика — прокладання кабелів, PoE, призначення IP-адреси та власні мережеві налаштування пристрою — наведена в **[посібнику користувача DAQ](https://mapir.gitbook.io/daq/daq-e/network-setup)**. На цій сторінці розглядаються питання, що стосуються Chloros: підключення, синхронізація часу та що робити, якщо пошук пристроїв не дав результатів.

DAQ-E — це Ethernet-пристрій із сімейства DAQ: він живиться через PoE, виявляється за допомогою mDNS (служба `_daq-e._tcp`) і має ім’я хоста, що походить від ідентифікатора датчика — `daq-e-<6 hex>.local`, наприклад, `daq-e-def330.local`. На цій сторінці розглядається, як пристрій передає дані в мережі та як бере участь у синхронізації часу за протоколом PTP.

## Режими передачі

| Режим | Кінцева точка | Споживачі | Примітки |
| --- | --- | --- | --- |
| **Мультикаст** (за замовчуванням) | UDP `239.10.10.10:5002` | Будь-яка кількість пристроїв у тій самій локальній мережі отримує один і той самий потік | Кожен датаграм перевіряється за допомогою CRC-16/CCITT |
| **Raw** | TCP-порт `5000` | Точно один клієнт (ексклюзивно) | Повністю сумісний на рівні байтів із DAQ-U |

Chloros за замовчуванням використовує мультикаст, що дозволяє графічному інтерфейсу, CLI та SDK одночасно відстежувати один датчик.

## Мережеві вимоги

* **Один і той самий домен широкомовлення.** Комп’ютер, на якому працює Chloros, повинен перебувати в тому самому сегменті мережі рівня 2, що й датчик — виявлення mDNS не проходить через маршрутизатори.
* **Запит брандмауера Windows: прийміть його.** Коли Chloros вперше прив’язує сокети багатоадресного мовлення, Windows Defender запитує про це один раз. Дозвіл охоплює дані DAQ-E (UDP 5002), mDNS (UDP 5353) та PTP (UDP 319/320). На Linux це відбувається автоматично.
* **Живлення через PoE, відсутність світлодіода стану.** DAQ-E не має власного світлодіода — перевірте наявність живлення за допомогою індикатора Link/PoE на комутаторі або порту інжектора, а також зачекайте кілька секунд після увімкнення, щоб пристрій завантажився та підключився до мережі.

## Підключення

**Графічний інтерфейс:** Вкладка «Датчики освітлення» → «Підключити датчик» → Тип пристрою «DAQ-E (Ethernet)». Пошук відбувається лише тоді, коли діалогове вікно підключення відкрите на екрані (пошук за mDNS та ARP-сканування на Windows), повторюючись кожні 15 секунд; кнопка «Оновити» запускає повторний пошук негайно. Виявлені датчики з’являються у випадаючому списку; перший виявлений датчик вибирається автоматично.

<!-- SCREENSHOT-NEEDED: DAQ connect dialog with Device Type set to "DAQ-E (Ethernet)" and at least one discovered sensor listed in the Hostname/IP dropdown (e.g. daq-e-xxxxxx.local), Connect button enabled. -->

**CLI** (запущений бекенд):

```bash
chloros-cli daq pool-connect --eth                              # auto-discover on the LAN
chloros-cli daq pool-connect --eth-host daq-e-def330.local      # explicit host — the reliable form
chloros-cli daq pool-connect --eth-host 192.168.1.57            # a plain IP works too
```

### Хости з кількома мережевими адаптерами та перше підключення після завантаження

На хостах з більш ніж одним активним мережевим інтерфейсом **перше** `pool-connect --eth` після завантаження може бути порожнім, навіть якщо датчик працює нормально — під час сканування для виявлення може бути пропущений інтерфейс, на якому знаходиться датчик, поки кеш ARP ще не завантажений. Надійним виходом із ситуації є пропуск сканування та явне вказання адреси:

```bash
chloros-cli daq pool-connect --eth-host daq-e-def330.local
```

`--eth-host` приймає ім&#x27;я хоста mDNS або IP-адресу, завжди звертається до потрібного датчика і є рекомендованим варіантом для скриптів та бездисплейних установок. У графічному інтерфейсі скористайтеся кнопкою «Оновити» у діалоговому вікні підключення та дочекайтеся завершення циклу повторного сканування.

## Налаштування пристрою та прошивка

Сам датчик зберігає мережеві налаштування — статичну IP-адресу або DHCP + локальну адресацію, ім’я пристрою, автоматичний потік під час завантаження, пароль OTA. Ці налаштування на стороні пристрою не доступні у вигляді команд у поставляному CLI; ними керують через графічний інтерфейс Chloros, де вони відображаються, або за допомогою служби підтримки MAPIR.

**Оновлення прошивки вбудовано в графічний інтерфейс.**Коли підключений DAQ-E працює на прошивці, старшій за образ, що входить у комплект вашої збірки Chloros, у рядку його датчика з’являється помаранчева піктограма**Доступне оновлення**, а в модальному вікні налаштувань у вигляді шестерні з’являється<version>

кнопка</version> «Оновити до<version>

». Оновлення передається через мережу приблизно за 30 секунд; датчик автоматично перезапускається та підключається знову, а у разі переривання передачі поточна версія прошивки залишається незмінною.

## Синхронізація часу PTP

Прошивка DAQ-E версії 1.2.0+ підтримує стандарт IEEE 1588 PTPv2 як звичайний (лише підлеглий) годинник. **Бекенд хоста Chloros є головним годинником PTP** — кожен DAQ-E та кожна камера LATTICE у локальній мережі підпорядковуються йому в домені 0, підтримуючи всі часові мітки пристроїв у межах похибки ~1 мс. Саме цей спільний годинник забезпечує збіг часових міток даних DAQ з експозиціями камер (див. [Запис та формат .daq](recording.md)).

Перевірте синхронізацію за допомогою CLI:

| Команда | Показує |
| --- | --- |
| `chloros-cli time-sync status` | Стан головного годинника хоста, пріоритети BMCA, ідентифікатор годинника |
| `chloros-cli time-sync peers` | Усі виявлені підлеглі пристрої (датчики DAQ-E + камери LATTICE) |
| `chloros-cli time-sync cameras` | Стан PTP для кожної камери (`PtpStatus`, `PtpOffsetFromMaster`, `PtpMeanPathDelay`) |
| `chloros-cli time-sync restart` | Перезапуск процесу «гранмастера» |

У графічному інтерфейсі користувача (GUI) у модальному вікні налаштувань DAQ-E відображається рядок **PTP Sync** у режимі реального часу з поточним станом PTP датчика.

Детальна інформація для споживачів, що потребують суворого синхронізування:

* Кожен переданий датаграм містить поле прапорців; **біт 2 встановлюється у кадрах, час яких синхронізовано за PTP**. Конвеєри, що вимагають суворого синхронізування камери та DAQ, повинні керуватися цим бітом.
* Перед синхронізованим записом переконайтеся, що датчик відображається у списку `chloros-cli time-sync peers`. (Внутрішні апаратні засоби MAPIR також можуть керувати записом за фіксацією PTP за допомогою прапора `--wait-ptp`, який очікує до 15 с, поки датчик не перейде у стан SLAVE; цей інструмент не входить до комплекту поставки CLI.)
* Поки PTP активно працює у режимі підпорядкованого пристрою, датчик відхиляє ручні команди синхронізації («PTP забезпечує тактову частоту»). Це передбачено конструкцією — довіряйте PTP.

## Примітки щодо Linux

* **PTP потребує `libcap2-bin` під час інсталяції.** Скрипт postinst для `.deb` надає `cap_net_bind_service=+ep` права на `/usr/lib/chloros/chloros-backend`, щоб він міг прив’язувати PTP-порти 319/320 без прав root. Якщо `libcap2-bin` відсутній, цей крок пропускається, і PTP не зможе запуститися. Виправлення:

  ```bash
  sudo apt install libcap2-bin
  sudo apt reinstall chloros
  ```

* **Jetson / Raspberry Pi без монітора:** під час першої інсталяції модуль systemd `chloros-backend.service` генерується, але не вмикається. Для постійної роботи PTP (та доступності DAQ) без графічного інтерфейсу:

  ```bash
  sudo systemctl enable --now chloros-backend.service
  ```

  Без нього PTP працює лише тоді, коли відкрито графічний інтерфейс Chloros.

## Усунення несправностей: «Не знайдено пристроїв DAQ-E»

| Перевірка | Деталі |
| --- | --- |
| Живлення | Світлодіод на датчику не світиться — перевірте індикатори PoE та зв’язку на комутаторі/порту інжектора; зачекайте кілька секунд після увімкнення |
| Домен широкомовлення | Хост і датчик знаходяться в одному сегменті L2; mDNS не маршрутизує |
| Брандмауер Windows | При першому запуску погодьтеся на запит Defender (UDP 5002, 5353, 319/320) |
| Хост із кількома мережевими картами | Під час першого виявлення після завантаження датчик може не бути знайдений — підключіться за допомогою `--eth-host <ip-or-hostname>` |
| Повторне сканування через графічний інтерфейс | Виявлення відбувається лише тоді, коли відкрито діалогове вікно підключення; скористайтеся кнопкою «Оновити» |</version>
