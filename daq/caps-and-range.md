# Характеристики ковпачків та калібрований діапазон

> Інформація про самі ковпачки — які ковпачки постачаються з якими датчиками, як вони кріпляться та їхні оптичні характеристики — наведена в **[посібнику користувача DAQ](https://mapir.gitbook.io/daq)**. На цій сторінці розглядається *задавання* встановленого ковпачка в Chloros, що забезпечує правильність корекції.

Заводська радіометрична калібровка кожного світлового датчика DAQ описує *голий* датчик. Фізична кришка, встановлена над дифузором, змінює світло, яке збирає датчик, тому Chloros застосовує **профіль корекції кришки**, виміряний на заводі, поверх набору калібрувальних даних. Зазначення правильного ковпачка є частиною отримання каліброваних даних — на цій сторінці описано, які ковпачки існують для кожної моделі, як їх зазначити та яким насправді є калібрований спектральний діапазон датчика.

## Наявність ковпачків за моделями

| Профіль ковпачка (`cap_id`) | Фізичний ковпачок | DAQ-U | DAQ-M | DAQ-E |
| --- | --- | --- | --- | --- |
| `sunshine_cosine` | Насадка для корекції косинуса сонячного світла (**за замовчуванням на всіх моделях**) | Так | Так | Так |
| `fov_15` / `fov_45` / `fov_90` | Конуси, що обмежують поле зору (15° / 45° / 90°) | Так | — | Так |
| `fov_30` / `fov_60` | Конуси для обмеження поля зору (30° / 60°) | Так | — | — |
| `none` | Без ковпачка | — | — | Так |

Примітки щодо конкретних моделей:

* **DAQ-M має один профіль ковпачка: `sunshine_cosine`.** «Bare-plus-Sunshine-cap» — це його визначення як продукту, а «голий» DAQ-M не потребує геометричного профілю.
* **«Голий» DAQ-U є справді «голим»** — він взагалі не потребує геометричного профілю, тому для нього не існує профілю `none`.
* **`none` на DAQ-E НЕ є «no-op» (невиконуваною операцією).** Утоплений, покритий склом дифузор DAQ-E має власну реальну геометричну корекцію, тому «без ковпачка» — це сам по собі вимірюваний профіль на цій моделі.
* **Оголений DAQ-E не може вимірювати пряме сонячне світло на будь-якому куті висоти** — ковпачок Sunshine є стандартною конфігурацією для польового використання. Не плануйте роботи на відкритому повітрі з використанням оголеного DAQ-E.

У налаштуваннях для кожного датчика в графічному інтерфейсі (значок шестерні на вкладці «Light Sensors») у випадаючому меню **Cap** також доступний варіант «None (bare sensor)» для DAQ-U та DAQ-M — для цих двох моделей «bare» просто означає, що корекція ковпачка не застосовується, як зазначено вище. Вибирайте цей варіант лише тоді, коли ковпачок фізично знято.

## Вказівка про наявність ковпачка — і чому це важливо

**Зазначений код `cap_id` повинен відповідати ковпачку, який фізично встановлено на датчику.** Ні датчик, ні програмне забезпечення не можуть виявити встановлений ковпачок. Вказівка ковпачка впливає на дві речі:

1. **Корекцію в режимі реального часу**, що застосовується до кожного спектра.
2. **Позначку про ковпачок, що записується в кожен запис `.daq`**, на яку покладається подальша обробка відбиття.

Ковпачок Sunshine за своєю конструкцією забезпечує ослаблення приблизно **у 12 разів**, тому запис із неправильно вказаним ковпачком призводить до неправильного масштабування спектрів приблизно на цей коефіцієнт. Негайно вказуйте зміни ковпачка.

### Налаштування ковпачка

Графічний інтерфейс: вкладка «Світлові датчики» → значок шестерні в рядку датчика → випадаюче меню **«Ковпачок»**. За замовчуванням для кожної моделі встановлено `sunshine_cosine` (усі датчики DAQ постачаються з встановленим косинусним коректором), і цей вибір зберігається у проєкті.

<!-- SCREENSHOT-NEEDED: DAQ tab per-sensor settings modal (gear icon) scrolled to the Cap dropdown, open to show the per-model choices with "Sunshine (cosine corrector)" selected. Use a connected DAQ-E so the Hostname/Firmware/PTP rows are also visible above it. -->

CLI (бекенд має працювати):

```bash
# Declare at connect time
chloros-cli daq pool-connect --eth-host daq-e-def330.local --cap-id sunshine_cosine

# Swap at runtime (after physically changing the cap)
chloros-cli daq pool-set-cap --sensor-id daq-e-def330 --cap-id fov_45
```

CLI синтаксично підтримує повний список `cap_id` (`{none, fov_15, fov_30, fov_45, fov_60, fov_90, sunshine_cosine}`); кожен профіль перевіряється на відповідність моделі датчика під час підключення, тому недоступний ідентифікатор конденсатора (наприклад, ідентифікатор, що підтримує лише режим E, на DAQ-U) призведе до явної помилки, а не до неправильного коригування. За замовчуванням бекенд, якщо нічого не передано, використовує `sunshine_cosine`.

Python SDK примітка: `cap_id` **не** є регулятором SDK — `connect_daq_sensor()` / `DAQSensorSession` не надають параметра конденсатора. Виберіть обмеження за допомогою наведених вище команд CLI або випадаючого меню графічного інтерфейсу; див. [Довідку по SDK](../reference/sdk-reference.md).

Для досвідчених користувачів: профілі постачаються в складі інсталяції Chloros у `daq/cap_profiles/<u|m|e>/<cap_id>.json` і можуть бути замінені для кожного користувача окремо в `~/.chloros/daq_cap_profiles/<u|m|e>/<cap_id>.json`.

Окремо від обмежень, датчики, які ніколи не піддавалися повторній калібровці, автоматично отримують невелике уточнення темнового зміщення, отримане на основі даних парку обладнання — без будь-яких дій з боку користувача.

## Ефективність обмеження сонячного світла (конфігурація для зовнішнього використання)

Цифри, на основі яких можна розробляти процедури:

| Характеристика | Значення |
| --- | --- |
| Поле зору | 180° півсферичне |
| Похибка косинусної характеристики | ≤ ±4 % при куті падіння до 60°; ≤ ±4,5 % при куті падіння до 70° |
| Межа низького положення Сонця | Не рекомендується при куті підйому Сонця нижче ~15° |
| Ослаблення | ~12× (за конструкцією) |
| Повторюваність повторного встановлення ковпака | ≈ 1,5 % |
| Кількісне значення інтенсивності сонячного випромінювання | Середнє значення за **≥ 15 с** вимірювань (характеристика приладу, а не дефект) |

Для будь-якого кількісного значення інтенсивності сонячного випромінювання — включаючи дані про коефіцієнт відбиття — слід використовувати середнє значення за щонайменше 15 секунд вимірювань, а не окремий кадр.

## Калібрований спектральний діапазон

| Характеристика | Значення |
| --- | --- |
| Спектральна дискретизація | 340–1010 нм з кроком 5 нм (135 точок) |
| Радіометрично відкалібрований діапазон | **~374–974 нм** (визначено програмним забезпеченням) |

Датчик передає дані по всій сітці 340–1010 нм, але радіометричний коефіцієнт підсилення, відстежуваний за стандартами NIST, охоплює діапазон ~374–974 нм. Chloros **відмовляється від поділу за абсолютним відбиванням** для будь-якої смуги камери, менше половини спектральної ваги якої знаходиться в межах цього діапазону, повідомляючи про причину пропуску `dls-uncalibrated-band-<nm>` замість того, щоб створювати некалібрований результат. Серед камер, що постачаються, лише фільтр F988 виходить за межі цього діапазону; для нього замість цього використовується робочий процес із панеллю відбиття — див. [Робочі процеси з відбиттям](reflectance.md).

Інформацію про моделі датчиків, транспортні засоби та ідентифікатори датчиків див. у [огляді DAQ](README.md). Про те, як під час обробки використовується маркування капсули, див. [Запис та формат .daq](recording.md).
