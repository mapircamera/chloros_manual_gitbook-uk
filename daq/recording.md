# Запис та формат .daq

Файл `.daq` — це формат запису даних світлового датчика Chloros: **база даних SQLite**, що містить відкалібровані спектральні кадри, отримані з одного датчика DAQ. Запишіть один такий файл під час сеансу збору даних, і конвеєр обробки відбиття зможе згодом поділити кожне зображення на інтенсивність опромінення, виміряну саме в цей момент.

## Що містить файл .daq

| Властивість | Значення |
| --- | --- |
| Контейнер | База даних SQLite, один файл на датчик на запис |
| Ім’я файлу | Містить **ідентифікатор датчика**та**мітку часу**, наприклад, `daq_data_daq-e-def330_2026_04_13_18h30m00.daq` |
| Спектр на кадр | 135 точок, 340–1010 нм з кроком 5 нм, а також тристимульні координати CIE XYZ |
| Одиниці виміру | Калібрована спектральна інтенсивність випромінювання, **Вт/м²/нм** (застосовано заводський калібрувальний набір + профіль ковпачка) |
| Вбудовані метадані | Ідентифікатор датчика (ключ для отримання заводської калібрування цього пристрою) та діючий профіль кришки — див. [Профілі кришок та калібрований діапазон](caps-and-range.md) |

Формат є однаковим для DAQ-U, DAQ-M та DAQ-E, тому для подальшої обробки не має значення, який пристрій записав дані.

Для каліброваного запису потрібен заводський калібрувальний пакет датчика. Для DAQ-U та DAQ-M сервер завантажує пакет із хмари MAPIR за ідентифікатором датчика (якщо це неможливо, запис відхиляється); пристрої DAQ-E є винятком, оскільки вони зберігають калібрування на самому пристрої.

## Запис через графічний інтерфейс

Для запису через графічний інтерфейс користувача (GUI) потрібно **відкрити проєкт** (інакше кнопки «Запис» будуть неактивними):

* **Записати все / Зупинити все** — у верхній частині бічної панелі «Світлові датчики»; одночасно запускає або зупиняє запис `.daq` на всіх підключених датчиках.
* **Запис / Зупинити запис** — для кожного датчика окремо, у модальному вікні налаштувань (значок шестерні). Під час запису у рядках інформації про стан датчика відображається червоний індикатор «REC».

Файли записуються у `<project>/light_sensor/`, і коли запис зупиняється — чи то за допомогою кнопки «Зупинити», «Зупинити все», чи то через від’єднання датчика, що здійснює запис — готовий файл `.daq` **автоматично додається до відкритого проєкту**. Він з’являється у списку файлів проєкту без необхідності ручного додавання, вже готовий для обробки відбиття.

## Запис з CLI

CLI здійснює запис через пул датчиків бекенду (бекенд має працювати — ці команди є «тонким» клієнтом HTTP):

```bash
# Connect the sensor into the backend pool
chloros-cli daq pool-connect --eth-host daq-e-def330.local

# Record for 150 seconds, with a human-friendly device label
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
    -o ./out --device-name "rooftop-A"

# Or run open-ended and stop explicitly
chloros-cli daq pool-record --sensor-id daq-e-def330            # --duration defaults to 0 = run until --stop
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

Отримати значення `--sensor-id` з `chloros-cli daq pool-list`. Два значення за замовчуванням, про які варто знати:

| Параметр | Значення за замовчуванням |
| --- | --- |
| `--duration` | `0` — записувати до `pool-record --stop` |
| `--output` / `-o` | `~/Documents/DAQ Live View/` у файловій системі **бекенду**, а не CLI |

Розрізнення каталогів виводу має значення, коли CLI націлений на бекенд на іншій машині: файл зберігається там, де працює бекенд.

## Запис із Python

`DAQSensorSession` (повернутий `chloros_sdk.connect_daq_sensor()`) надає доступ до того самого запису з пулу: `record_start(output_dir=None, device_name=None)` повертає шлях до файлу, а `record_stop()` повертає `{path, rows}`. Див. [Довідку щодо SDK](../reference/sdk-reference.md) для повного сеансу API. Класи прямого апаратного забезпечення SDK (лише для настільних установок) за замовчуванням записують записи у `~/Documents/DAQ/`; для випущених збірок підтримуваним шляхом є зазначений вище об’єднаний шлях.

## Використання файлу .daq під час обробки

Для обчислення відбивної здатності за зображеннями Chloros потребує даних про інтенсивність опромінення, спрямованого вниз, що відповідають кожній експозиції:

* **Зберігайте файл `.daq` разом із зображеннями.**Під час обробки конвеєр автоматично визначає**інтенсивність опромінення, що відповідає часовій мітці**, на основі записаного файлу `.daq` (будь-якої моделі DAQ) — або на основі власного файлу DAQ-M `.csv` — знайденого поруч із зображеннями. Записи з графічного інтерфейсу користувача автоматично відповідають цій вимозі, оскільки вони додаються до проєкту одразу після завершення запису.
* **Калібрування завантажується за запитом.** Якщо пакет заводської калібрування для конкретної камери або DAQ ще не збережено в локальному кеші, Chloros автоматично завантажує його з хмари MAPIR під час першого використання (одноразове підключення до Інтернету; кешується під `~/.chloros/`).
* **Зображення, зняті в режимі реального часу, створюють власний супровідний файл.** Для кожного кадру відбиття, знятого в режимі реального часу, фактично використане значення DAQ зберігається як супровідний файл `.daq` поруч із зображенням, завдяки чому знімок можна буде переобробити пізніше без оригінального запису.

## Відновлення даних про інтенсивність випромінювання

Під час обробки проєкту також експортуються всі записи світлових датчиків, що містяться в ньому, у
папку `Light Sensor/` поруч із зображеннями. Для цього **не** потрібні зображення:
світловий датчик, що літав самостійно, є повноцінним записом, а папка, що містить лише файли `.daq`,
є дійсним вхідним матеріалом. Програма повідомляє, скільки продуктів світлового датчика було записано.

| Продукт | Що це |
| --- | --- |
| `<name>_calibrated.daq` | Архів, придатний для повторної обробки, за тією ж схемою, що й запис у реальному часі, який тепер містить інформацію про калібрувальний пакет, за допомогою якого він було створено. Повторне імпортування цього файлу **не** призводить до його повторної калібрування. |
| `<name>_calibrated.csv` | Спектральна інтенсивність випромінювання в Вт/м²/нм за власною сіткою довжин хвиль датчика, один рядок на одне зчитування, а також фотометричні стовпці: загальна потужність, фотопічні та скотопічні люкси, PPFD із розбиттям на синій/зелений/червоний діапазони та пікова довжина хвилі. |

DAQ-U або DAQ-M, калібрувальний пакет якого неможливо завантажити — ви перебуваєте в автономному режимі або
для цього датчика немає калібрування в файлі — **пропускається з зазначенням причини**, ніколи не записується
як «відкалібрований» файл, що містить необроблені дані. Підключіться до Інтернету та запустіть процедуру знову. DAQ-E
має власну калібрування, тому воно потрібне лише тоді, коли пристрій не підключено і
локально нічого не збережено у кеші.

### DAQ-A: необроблені дані, і чому це правильне рішення

**DAQ-A** з’явився ще до впровадження системи калібрувальних пакетів для кожного серійного номера і не має пакета, який
можна завантажити. Це не є недоглядом: DAQ-A калібрується в польових умовах за допомогою
мішені відбиття, а калібрування на основі мішені потребує лише *відносної*
чутливості датчика — а це саме те, чим є його необроблені імпульси. Chloros сьогодні калібрується саме за ними.

Отже, запис DAQ-A експортується, але під іншою назвою:

```
<project>/
└── Light Sensor/
    ├── <name>_raw.daq
    └── <name>_raw.csv
```

`_raw`, а не `_calibrated` — це інше ім’я файлу, а не прапорець усередині файлу,
оскільки ця інформація має зберегтися під час надсилання файлу електронною поштою як простого імені. Заголовок `.csv`
вказує `raw spectral sensor counts (NOT irradiance)` і попереджає, що значення є
порівнянними **в межах** файлу, а не між датчиками. Стовпці, які мають значення
лише для реальної інтенсивності випромінювання — загальна потужність, люкс, PPFD — залишаються порожніми, а не
обчислюються на основі кількості імпульсів.

Старіші записи DAQ-A-SD (схема v1.01 / v1.02) фіксують лише час запису файлу, а не
часовий штамп для кожного зчитування. Chloros не буде зіставляти зображення з цими даними — зіставлення кадру з
часом запису було б помилковим, хоча на перший погляд це й не виглядало б так — але експорт читає їх без проблем, і
CSV вказує, за яким годинником вони йдуть.

Повну інформацію про відбиття — з одним датчиком із камерою та двома датчиками (навколишнє середовище/об’єкт) — див. у розділі [Робочі процеси відбиття](reflectance.md).
