# Запис та формат .daq

Файл `.daq` — це формат запису даних світлового датчика Chloros: **база даних SQLite**, що містить відкалібровані спектральні кадри з одного датчика DAQ. Запишіть такий файл під час сеансу збору даних, і конвеєр обробки відбиття зможе згодом поділити кожне зображення на інтенсивність опромінення, виміряну саме в цей момент.

## Що містить файл .daq

| Властивість | Значення |
| --- | --- |
| Контейнер | База даних SQLite, один файл на датчик на запис |
| Ім’я файлу | Містить **ідентифікатор датчика**та**мітку часу**, наприклад, `daq_data_daq-e-def330_2026_04_13_18h30m00.daq` |
| Спектр на кадр | 135 точок, 340–1010 нм з кроком 5 нм, а також тристимульні координати CIE XYZ |
| Одиниці виміру | Калібрована спектральна інтенсивність випромінювання, **Вт/м²/нм** (застосовано заводський калібрувальний пакет + профіль ковпачка) |
| Вбудовані метадані | Ідентифікатор датчика (ключ для отримання заводської калібрування цього пристрою) та діючий профіль ковпачка — див. [Профілі ковпачків та калібрований діапазон](caps-and-range.md) |

Формат є однаковим для DAQ-U, DAQ-M, DAQ-E та DAQ-E-S, тому під час подальшої обробки не має значення, який пристрій запису здійснив запис. Запис DAQ-E-S також зберігає дані про нахил, крен та тангаж пристрою поруч із кожним спектром.

**Записи зберігаються навіть у разі відключення живлення (версія 1.3.0).**Запис у реальному часі записується з використанням журналу та повної синхронізації з диском при кожному фіксуванні змін, тому відключення живлення або завершення процесу призводить до втрати лише останніх 3 секунд, а не всього файлу. Запис, зупинений посеред запису, може залишити файл `<name>.daq-journal` поруч із `.daq`:**збережіть і скопіюйте обидва разом.** Chloros відкочує журнал назад під час першого читання файлу. Зайнятий диск затримує запис файлу, але ніколи — показання датчика.

**DAQ-E, який припинив передачу даних, підключається знову (версія 1.3.0).** Коли потік даних від DAQ-E переривається (через перезапуск комутатора або розрив з’єднання), серверний модуль повторно підключає його з попередніми налаштуваннями, і запис на ньому продовжується у тому самому файлі `.daq` із позначенням пропуску у файлі.

Для каліброваного запису потрібен заводський калібрувальний пакет датчика. Для DAQ-U та DAQ-M сервер завантажує пакет із хмари MAPIR за ідентифікатором датчика (якщо це неможливо, запис відхиляється); пристрої DAQ-E є винятком, оскільки вони зберігають калібрування на самому пристрої.

## Запис через графічний інтерфейс

Для запису через графічний інтерфейс користувача (GUI) потрібно **відкрити проєкт** (інакше кнопки запису будуть неактивними):

* **Записати все / Зупинити все** — у верхній частині бічної панелі «Світлові датчики»; одночасно запускає або зупиняє запис `.daq` на всіх підключених датчиках.
* **Запис / Зупинити запис** — для кожного датчика окремо, у модальному вікні налаштувань (значок шестерні). Під час запису у рядках інформації про стан датчика відображається червоний індикатор «REC».

Файли записуються у `<project>/light_sensor/`, і коли запис зупиняється — чи то за допомогою кнопки «Зупинити», «Зупинити все», чи то внаслідок від’єднання датчика, що здійснює запис — готовий файл `.daq` **автоматично додається до відкритого проєкту**. Він з’являється у списку файлів проєкту без необхідності ручного додавання, вже готовий до обробки відбиття.

## Запис через CLI



CLI здійснює запис через пул датчиків бекенду (бекенд має працювати — ці команди є «тонким» HTTP-клієнтом):

```bash
# Connect the sensor into the backend pool
chloros-cli daq pool-connect --eth-host daq-e-def330.local

# Record for 150 seconds, with a human-friendly device label
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
    -o ./out --device-name "rooftop-A"

# Or run open-ended and stop explicitly
chloros-cli daq pool-record --sensor-id daq-e-def330            # --duration defaults to 0 = run until --stop
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

Отримати значення `--sensor-id` з `chloros-cli daq pool-list`. Два параметри за замовчуванням, про які варто знати:

| Параметр | Значення за замовчуванням |
| --- | --- |
| `--duration` | `0` — записувати до `pool-record --stop` |
| `--output` / `-o` | `~/Documents/DAQ Live View/` у файловій системі **бекенду**, а не CLI |

Розрізнення каталогів виводу має значення, коли CLI націлений на бекенд на іншій машині: файл потрапляє туди, де працює бекенд. Якщо бекенд знаходиться на тому ж комп’ютері, відносний `-o` (наприклад, `./out` вище) розпізнається відносно папки, в якій було виконано команду.

## Запис із Python

`DAQSensorSession` (повернутий `chloros_sdk.connect_daq_sensor()`) надає доступ до того самого об’єднаного запису: `record_start(output_dir=None, device_name=None)` повертає шлях до файлу, `record_stop()` повертає `{path, rows}`. Повний опис API сеансів див. у [Довідці по SDK](../reference/sdk-reference.md). Класи SDK для прямого доступу до апаратного забезпечення (лише для настільних установок) за замовчуванням записують дані в `~/Documents/DAQ/`; для випущених збірок підтримується зазначений вище об’єднаний шлях.

## Використання файлу .daq під час обробки

Для обчислення коефіцієнта відбиття за зображеннями програмі Chloros потрібна інтенсивність опромінення, спрямованого вниз, що відповідає кожній експозиції:

* **Зберігайте файл `.daq` разом із зображеннями.**Під час обробки конвеєр автоматично визначає**інтенсивність сонячного випромінювання, що відповідає часовій мітці**, на основі записаного файлу `.daq` (будь-якої моделі DAQ) — або на основі власного файлу `.csv` — знайденого поруч із зображеннями. Записи з графічного інтерфейсу користувача автоматично відповідають цій вимозі, оскільки вони додаються до проєкту одразу після завершення запису.
* **Калібрування завантажується за запитом.** Якщо пакет заводської калібрування для конкретної камери або DAQ ще не збережено в локальному кеші, Chloros автоматично завантажує його з хмарного сховища MAPIR під час першого використання (потрібен доступ до Інтернету один раз; зберігається в кеші під назвою `~/.chloros/`).
* **Записи в режимі реального часу створюють власний супровідний файл.** Для будь-якого кадру відбиття, знятого в режимі реального часу, фактично використане значення DAQ зберігається як файл `.daq` у папці `daq/` знімків, тому знімок можна буде переобробити пізніше без оригінального запису.
* **Записи з реєстраторів `chloros_scripts` (версія 1.3.0).**Файл `.daq`, записаний загальнодоступними реєстраторами [`chloros_scripts`](https://github.com/mapircamera/chloros_scripts), вказаний як модель DAQ, що його створила, і його обмеження можна встановити в**Налаштуваннях проєкту → DAQ-датчик освітленості**, як і для будь-якого іншого запису. Ці реєстратори записують необроблені дані лічильника датчика; Chloros отримує заводську калібровку датчика через послідовний порт і застосовує її.
* **Чиї це дані (1.3.0).**Поряд із кожним записом `.daq`, `.daq.cameras.json` вказує камеру (камери), кадри яких описує це значення, і обробка зіставляє його**лише із зображеннями з цих камер**. Тому автономна камера, яка не має власного датчика освітленості, більше не використовує показники іншої камери — підключіть до неї датчик або запишіть власні показники. Запис, зроблений за допомогою самого DAQ (GUI Record, `daq pool-record`), та будь-який `.daq` без цього файлу (включно зі старими знімками), як і раніше, обслуговує кожну камеру.

## Відновлення даних про інтенсивність випромінювання

Під час обробки проєкту також експортуються всі записи датчиків освітленості, що містяться в ньому, у
`Light Sensor/` поруч із зображеннями. Для цього **не** потрібні зображення:
запис датчика освітленості сам по собі є повноцінним записом, а папка, що містить лише файли `.daq`,
є допустимим вхідним матеріалом. Проєкт, що містить лише записи датчиків освітленості, відображає їх у списку та
обробляє як у додатку, так і в CLI, і вони залишаються у списку після завершення запуску. Звіт про запуск
вказує, скільки продуктів датчиків освітленості було записано.

| Продукт | Що це |
| --- | --- |
| `<name>_calibrated.daq` | Архів, який можна переобробити, за тією ж схемою, що й запис у реальному часі, але тепер із зазначенням калібрувального пакета, за допомогою якого його було створено. Повторне імпортування **не** призводить до повторної калібрування. |
| `<name>_calibrated.csv` | Спектральна інтенсивність випромінювання у Вт/м²/нм за власною сіткою довжин хвиль датчика, один рядок на одне зчитування, а також фотометричні стовпці: загальна потужність, фотопічні та скотопічні люкси, PPFD із розбиттям на синій/зелений/червоний діапазони та пікова довжина хвилі. |

DAQ-U або DAQ-M, калібрувальний пакет якого неможливо завантажити — ви перебуваєте в автономному режимі або
для цього датчика немає калібрувальних даних у файлі — **пропускається із зазначенням причини**, ніколи не записується
як «відкалібрований» файл, що містить необроблені дані підрахунку. Підключіться до Інтернету та запустіть процедуру знову. DAQ-E
має власну калібровку, тому вона потрібна лише тоді, коли пристрій не підключено і
локально нічого не збережено в кеші.

### DAQ-A: необроблені дані, і чому це правильне рішення

**DAQ-A** з’явився ще до впровадження системи калібрувальних пакетів для кожного послідовного порту і не має пакета, який
можна завантажити. Це не є недоглядом: DAQ-A калібрується в польових умовах за допомогою
мішені відбиття, а калібрування на основі мішені вимагає лише *відносної*
чутливості датчика — саме цим і є його необроблені лічильні дані. Компанія Chloros і сьогодні використовує їх для калібрування.

Отже, запис з DAQ-A експортується, але під іншою назвою:

```
<project>/
└── Light Sensor/
    ├── <name>_raw.daq
    └── <name>_raw.csv
```

`_raw`, а не `_calibrated` — це інше ім’я файлу, а не прапорець усередині файлу,
оскільки ця інформація має зберегтися під час надсилання файлу електронною поштою у вигляді простого імені. Заголовок `.csv`
вказує `raw spectral sensor counts (NOT irradiance)` і попереджає, що значення є
порівнянними **всередині** файлу, а не між датчиками. Стовпці, які мають значення
лише для реальної інтенсивності випромінювання — загальна потужність, люкс, PPFD — залишаються порожніми, а не
обчислюються на основі підрахунків.

Старіші записи DAQ-A-SD (схема v1.01 / v1.02) фіксують лише час запису файлу, а не
часовий штамп для кожного зчитування. Chloros не зіставлятиме зображення з цими даними — прив’язування кадру до
часу запису було б неправильним, хоча на перший погляд це й не виглядало б так — але експорт читає їх нормально, і
у файлі CSV вказано, до якого годинника вони відносяться.

Повну інформацію про відбивання — з одним датчиком і камерою, а також з двома датчиками (навколишнє середовище/об’єкт) — див. у розділі [Робочі процеси з відбиванням](reflectance.md).
