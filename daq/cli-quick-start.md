# Швидкий старт CLI (pool-*)

Поставлений пристрій `chloros-cli` керує датчиками DAQ за допомогою сімейства команд **`daq pool-*`** — «тонких» HTTP-клієнтів, які керують датчиками через постійний пул датчиків бекенду Chloros. Бекенд відповідає за транспорт, тому графічний інтерфейс, CLI та скрипти SDK використовують один спільний активний дескриптор, замість того, щоб конкурувати за порт. Усе, що потрібно клієнту, доступне через `pool-*`: підключення, потокова передача, запис відкаліброваних файлів `.daq` та заміна профілів капсул.

`pool-*` — це підтримуваний інтерфейс збору даних (DAQ) у випущених збірках. `chloros-cli daq --help` виводить список підкоманд `pool-*`, а `daq discover` / `daq list` виконують те саме сканування, що й `pool-discover`. Якщо підкоманда DAQ для прямого керування апаратним забезпеченням недоступна, програма завершується з явною помилкою, в якій вказується назва відсутнього пакета та рекомендується повернутися до `pool-*` — жодна помилка не залишається непоміченою. (`pip install chloros-sdk` також не надає команд для прямого керування апаратним забезпеченням.)

***

## Необхідні умови

* **Бекенд Chloros має працювати** — команди `pool-*` є HTTP-клієнтами, а не драйверами апаратного забезпечення. У Windows запустіть настільну програму Chloros (вона запускає бекенд). На бездисплейних системах Linux/Jetson увімкніть службу під своїм обліковим записом: `sudo systemctl enable --now chloros-backend@$USER.service` (див. [Встановлення на Linux](../linux/linux-installation.md#always-on-ptp-for-headless-hosts)).
* **Вхід у систему Chloros+ (платний тариф)**: спочатку запустіть `chloros-cli login`. Перевірка відбувається на стороні сервера — без входу команди завершуються з помилкою `401 AUTH_REQUIRED`; на безкоштовному (Iron) рівні вони завершуються з помилкою `403 PLAN_UPGRADE_REQUIRED`.
* За замовчуванням команди спрямовані на `http://127.0.0.1:5000`; сімейство `daq pool-*` враховує змінну середовища `CHLOROS_BACKEND_URL`, якщо ваш бекенд працює деінде.

## П'ятихвилинна сесія

```bash
# 1. Connect a sensor into the backend pool (pick the line matching your model)
chloros-cli daq pool-connect                                  # smart-detect any DAQ
chloros-cli daq pool-connect --port COM3                      # DAQ-U on a specific COM port
chloros-cli daq pool-connect --mac AA:BB:CC:DD:EE:FF          # DAQ-M by BLE MAC
chloros-cli daq pool-connect --eth-host daq-e-def330.local    # DAQ-E by hostname (reliable)
#    (a DAQ-M's BLE MAC is not printed anywhere: find it with `chloros-cli daq pool-discover --only ble`)

# 2. List the pool — this shows the sensor_id used by every command below
chloros-cli daq pool-list

# 3. Read the most recent calibrated spectrum frame (add --json for scripting)
chloros-cli daq pool-latest --sensor-id daq-e-def330 --json

# 4. Record a calibrated .daq file for 60 seconds
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 60 \
  --device-name "field-A"

# 5. Release the sensor when done
chloros-cli daq pool-disconnect --sensor-id daq-e-def330
```

## `pool-connect` — відкрити датчик у пулі

| Варіант | Значення |
| --- | --- |
| `daq pool-connect` | Розумне виявлення: знайти будь-який DAQ на цій машині. |
| `daq pool-connect --port PORT` | DAQ-U на певному послідовному порту (наприклад, `COM3`, `/dev/ttyUSB0`). |
| `daq pool-connect --ble` | DAQ-M через BLE, автоматичне сканування MAC-адреси. |
| `daq pool-connect --mac MAC` | DAQ-M за відомим MAC-адресою BLE (означає `--ble`). |
| `daq pool-connect --eth-host HOST` | DAQ-E за відомим іменем хоста або IP-адресою — **надійний шлях**. |
| `daq pool-connect --eth` | DAQ-E з автоматичним виявленням (mDNS, з резервним варіантом ARP). Див. застереження нижче. |

Прапори налаштування, усі необов’язкові:

| Прапор | Значення |
| --- | --- |
| `--integration-time MS` / `-t MS` | Час інтеграції, заданий вручну, у мілісекундах. |
| `--frame-avg N` / `-f N` | Кількість кадрів, що усереднюються для кожного спектрального діапазону. |
| `--no-ae` | Вимкнути автоматичну експозицію (AE увімкнено за замовчуванням). |
| `--no-stream` | Підключитися без запуску потоку (продовжити пізніше за допомогою `pool-stream --start`). |
| `--cap-id CAP` | Профіль корекції капсули; за замовчуванням для бекенду використовується `sunshine_cosine`. Див. [`pool-set-cap`](#pool-set-cap-declare-the-fitted-cap). |

Підключення пристрою DAQ-E, який уже знаходиться в пулі під іншою своєю адресою — іменем хоста `daq-e-<id>.local` або IP-адресою — повертає існуючий запис у пулі замість того, щоб відкривати пристрій вдруге.

{% hint style="warning" %}
**Застереження щодо автоматичного виявлення `--eth`.** На хості з кількома мережевими інтерфейсами (більше одного активного мережевого інтерфейсу) *перший* `pool-connect --eth` після завантаження може не знайти нічого, навіть якщо датчик працює нормально — під час сканування для виявлення може бути пропущений інтерфейс датчика, поки кеш ARP ще не завантажений. Якщо `--eth` нічого не знаходить, спробуйте ще раз або повністю пропустіть виявлення за допомогою `--eth-host <ip-or-hostname>`, що є надійним способом для машин з кількома мережевими інтерфейсами. Ім'я хоста DAQ-E — `daq-e-<id>.local` (наприклад, `daq-e-def330.local`); також підійде його звичайна IP-адреса.
{% endhint %}

## `pool-discover` — сканування без підключення

```bash
chloros-cli daq pool-discover                  # USB, BLE and Ethernet
chloros-cli daq pool-discover --only ble       # BLE only: this is how you find a DAQ-M's MAC
chloros-cli daq pool-discover --json           # machine-readable
```

Сканує датчики, до яких можна підключитися, і показує адресу для підключення, не встановлюючи з’єднання. `--only` приймає підмножину `usb,ble,eth`, розділену комами; `--timeout SEC` встановлює час сканування для кожного транспорту (за замовчуванням 5 с, обмежено діапазоном 1–20 с). Датчики, які вже відкриті в пулі, не відображаються у списку (підключений DAQ-M припиняє передачу інформації про себе) — для них використовуйте `pool-list`. У готовій збірці команди `chloros-cli daq discover` та `daq list` виконують це саме сканування.

## `pool-list` — перегляд підключених пристроїв

Показує всі датчики у пулі бекенду, включаючи `sensor_id`, який потрібен для виконання всіх інших команд:

| Модель | Формат `sensor_id` | Приклад |
| --- | --- | --- |
| DAQ-U / DAQ-M | 5-октетовий з дефісом | `CB-7C-A8-2E-5F` |
| DAQ-E | `daq-e-<6 hex digits>` | `daq-e-def330` |

DAQ-E, у якого вимкнено PTP (налаштування збережено в пристрої), позначається у `pool-list` за допомогою `!! PTP is switched OFF on this unit (saved in its flash): its timestamps are not PTP-synced.` та команди, що знову вмикає його — див. [`pool-enable-ptp`](#pool-enable-ptp-switch-a-daq-es-ptp-back-on).

## `pool-latest` — читання кадрів спектру

```bash
chloros-cli daq pool-latest --sensor-id daq-e-def330 --recent 10 --json
```

Повертає найновіший кадр або найновіші кадри `--recent N`; `--json` видає машиночитаний вихідний потік для використання у скриптах. Кадри представляють собою радіометрично відкалібровану спектральну інтенсивність випромінювання (Вт/м²/нм) на сітці з 135 точками в діапазоні 340–1010 нм, з уже застосованим профілем кришки датчика. Для отримання кількісних значень інтенсивності випромінювання слід усереднювати дані щонайменше за 15 секунд — це характеристика приладу, а не його несправність.

## `pool-stream` — призупинити або відновити потокову передачу

```bash
chloros-cli daq pool-stream --sensor-id daq-e-def330 --stop    # pause
chloros-cli daq pool-stream --sensor-id daq-e-def330 --start   # resume
```

## `pool-record` — запис файлу `.daq`

```bash
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
  --output ~/Documents/spectra --device-name "rooftop-A"
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

| Прапорець | За замовчуванням | Значення |
| --- | --- | --- |
| `--duration SEC` / `-d SEC` | `0` | Тривалість запису в секундах; `0` означає, що процес триватиме доти, доки не буде видано команду `--stop`. |
| `--output DIR` / `-o DIR` | `~/Documents/DAQ Live View/` | Каталог виводу. Якщо бекенд розташований на цьому комп’ютері, відносний шлях визначається відносно папки, в якій було виконано команду; у разі віддаленого бекенда шлях визначається **на машині, де працює бекенд**. |
| `--device-name NAME` | — | Мітка, що зберігається разом із записом. |
| `--stop` | — | Припинити запис, що виконується. |
| `--confirm-after SEC` | `20` | Після запуску чекати до зазначеного часу на запис першого рядка та видавати гучне попередження (`!! WARNING: no rows written after …s. This recording is producing an EMPTY file.`), якщо його не надійде. `0` вимикає цю перевірку. |
| `--heartbeat SEC` | `30` | З `--duration` виводити кількість рядків кожні SEC секунд і видавати попередження, якщо вона перестає зростати. `0` вимикає цю функцію. |

{% hint style="info" %}
Запис відбувається на сервері, тому файл `.daq` зберігається у файловій системі **сервера** — за замовчуванням у `~/Documents/DAQ Live View/` саме там, а не обов’язково там, де ви запустили CLI. Імена файлів містять ідентифікатор датчика та мітку часу.
{% endhint %}

## `pool-set-cap` — вказати встановлений ковпачок

```bash
chloros-cli daq pool-set-cap --sensor-id daq-e-def330 --cap-id sunshine_cosine
```

Ідентифікатор ковпачка визначає виміряний на заводі профіль корекції, що застосовується до кожного спектра, і він **повинен відповідати ковпачку, фізично встановленому на датчику** — ані датчик, ані програмне забезпечення не можуть самостійно виявити ковпачок, і цей вибір фіксується у кожному файлі `.daq`. За замовчуванням скрізь використовується `sunshine_cosine` (кожен DAQ постачається з встановленим коректором косинуса Sunshine, який за конструкцією забезпечує ослаблення приблизно в 12 разів — незадекларована зміна коректора призводить до неправильної корекції спектрів приблизно на цей коефіцієнт).

| `--cap-id` | Доступно на |
| --- | --- |
| `sunshine_cosine` (за замовчуванням) | DAQ-U, DAQ-M, DAQ-E |
| `fov_15`, `fov_45`, `fov_90` | DAQ-U, DAQ-E |
| `fov_30`, `fov_60` | Тільки DAQ-U |
| `none` | Тільки DAQ-E — див. примітку |

Ідентифікатор кришки, що не входить до набору датчика, відхиляється під час підключення з явною помилкою. `none` (DAQ-E) означає, що кришка фізично знята — пристрій все ще застосовує заводський геометричний профіль для вбудованого скляного дифузора DAQ-E, тому це не є бездіяльністю, а DAQ-E без кришки є лабораторною конфігурацією, а не підтримуваною польовою конфігурацією. (Голий DAQ-U є справді голим і взагалі не потребує профілю корекції; DAQ-M використовується разом із кришкою Sunshine.)

## `pool-disconnect` — звільнення датчиків

```bash
chloros-cli daq pool-disconnect --sensor-id daq-e-def330   # one sensor
chloros-cli daq pool-disconnect --all                      # everything in the pool
```

`pool-disconnect` звільняє датчик незалежно від того, хто його відкрив, тому він також звільняє датчик, залишений у пулі скриптом, що зазнав збою (запис на ньому спочатку завершується). Датчик, якого немає в пулі, звільнити ніяк не можна: команда виводить `<sensor-id>: already released (not in the pool)` і завершується `0`. Звільнення, яке бекенд відхилив або не підтвердив, завершується `1`.

## `pool-enable-ptp` — знову увімкнути PTP на DAQ-E

```bash
chloros-cli daq pool-enable-ptp --sensor-id daq-e-def330
```

DAQ-E зберігає налаштування увімкнення/вимкнення PTP у власній пам'яті, тому пристрій, PTP якого було вимкнено, залишається вимкненим — і його часові мітки не синхронізуються за PTP — доти, доки його не увімкнуть знову. `pool-list` позначає такий пристрій і виводить для нього цю команду. Chloros ніколи не вмикає пристрій самостійно, оскільки вимкнений стан може бути навмисним. Нове у версії 1.3.0.

## Налаштування пристрою DAQ-E

```bash
chloros-cli daq pool-info --sensor-id daq-e-def330
chloros-cli daq pool-set-network --sensor-id daq-e-def330 \
  --static 192.168.1.50 --gateway 192.168.1.1
chloros-cli daq pool-set-network --sensor-id daq-e-def330 --auto
chloros-cli daq pool-set-auto-stream --sensor-id daq-e-def330 --on
chloros-cli daq pool-reboot --sensor-id daq-e-def330
chloros-cli daq pool-update-firmware --sensor-id daq-e-def330
```

`pool-info` показує прошивку датчика (а також чи містить ця версія Chloros новішу версію), його адресу та спосіб її отримання, збережені налаштування мережі, якщо вони відрізняються від поточних, потокову передачу даних при увімкненні та PTP. `pool-set-network` перезапускає датчик для застосування змін і повторно підключає його з тими налаштуваннями, які були раніше; `--no-reboot` лише зберігає їх. Статична адреса має бути в мережі цього комп’ютера, інакше Chloros відхилить її; `--force` ігнорує це обмеження, але лише для комп’ютера, якому буде присвоєно нову адресу або який буде перенаправлено на цей комп’ютер. Перезапуск не допускається під час запису даних датчиком. `pool-update-firmware` — це еквівалент пункту меню **Оновити до \<version\>** </version\>у графічному інтерфейсі <version\>для командного рядка, а також спосіб оновлення DAQ-E в Linux, де графічний інтерфейс відсутній. Нове в версії 1.3.0.

| `daq pool-update-firmware --sensor-id ID` | Запис прошивки DAQ-E цього випуску на датчик старішої версії. |

## Усунення несправностей під час першого підключення DAQ-E

1. DAQ-E не має світлодіода стану — переконайтеся, що пристрій отримує живлення, перевіривши індикатор PoE/з’єднання на комутаторі або порту інжектора, і зачекайте кілька секунд після увімкнення, щоб пристрій завантажився та підключився до мережі.
2. Сервер повинен перебувати в **тому самому домені мовлення**, що й датчик — mDNS не проходить через маршрутизатори.
3. Брандмауер повинен пропускати mDNS (UDP 5353), дані DAQ-E (UDP 5002) та PTP (UDP 319/320). Інсталятор для Windows додає відповідне правило, а в Linux `.deb` відкриває ці порти у `ufw` / `firewalld`, який був активним під час інсталяції; сторонній брандмауер або брандмауер, увімкнений пізніше, повинен дозволити їх проходження.
4. Все ще немає відповіді від `--eth`? Використовуйте `--eth-host` із іменем хоста пристрою (`daq-e-<id>.local`) або IP-адресою, що дозволить пропустити процес виявлення.
