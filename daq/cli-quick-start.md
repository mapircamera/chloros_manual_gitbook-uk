# CLI: Короткий посібник з експлуатації (pool-*)

Постачаються пристрої `chloros-cli`, які керують датчиками DAQ за допомогою сімейства команд **`daq pool-*`** — «тонкі» клієнти HTTP, які керують датчиком через постійний пул датчиків бекенду Chloros. Бекенд керує транспортом, тому графічний інтерфейс, CLI та скрипти SDK використовують один спільний активний дескриптор, замість того щоб змагатися за порт. Усе, що потрібно клієнту, доступне через `pool-*`: підключення, потокова передача, запис відкаліброваних файлів `.daq` та заміна профілів капсул.

`pool-*` також є **єдиним** інтерфейсом DAQ у випущених збірках. `chloros-cli daq --help` відображає список підкоманд `pool-*`, а виклик підкоманди DAQ для прямого керування апаратним забезпеченням у випущеній збірці завершується явною помилкою, в якій вказується відсутній пакет і рекомендується звернутися до `pool-*` — ніщо не завершується без повідомлення. (Команди прямого доступу до апаратного забезпечення працюють лише з версії коду MAPIR; `pip install chloros-sdk` їх також не надає.)

***

## Необхідні умови

* **Бекенд Chloros повинен працювати** — команди `pool-*` є клієнтами HTTP, а не драйверами обладнання. На Windows запустіть настільну програму Chloros (вона запускає бекенд). На бездисплейному Linux/Jetson увімкніть службу: `sudo systemctl enable --now chloros-backend.service`.
* **Вхід на Chloros+ (платний тариф)**: спочатку запустіть `chloros-cli login`. Перевірка відбувається на стороні сервера — без входу команди завершуються з помилкою `401 AUTH_REQUIRED`; на безкоштовному (Iron) тарифі — з помилкою `403 PLAN_UPGRADE_REQUIRED`.
* За замовчуванням команди спрямовані на `http://127.0.0.1:5000`; сімейство `daq pool-*` враховує змінну середовища `CHLOROS_BACKEND_URL`, якщо ваш бекенд працює деінде.

***

## П’ятихвилинна сесія

```bash
# 1. Connect a sensor into the backend pool (pick the line matching your model)
chloros-cli daq pool-connect                                  # smart-detect any DAQ
chloros-cli daq pool-connect --port COM3                      # DAQ-U on a specific COM port
chloros-cli daq pool-connect --mac AA:BB:CC:DD:EE:FF          # DAQ-M by BLE MAC
chloros-cli daq pool-connect --eth-host daq-e-def330.local    # DAQ-E by hostname (reliable)

# 2. List the pool — this shows the sensor_id used by every command below
chloros-cli daq pool-list

# 3. Read the most recent calibrated spectrum frame (add --json for scripting)
chloros-cli daq pool-latest --sensor-id daq-e-def330 --json

# 4. Record a calibrated .daq file for 60 seconds
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 60 \
  --device-name "field-A"

# 5. Release the sensor when done
chloros-cli daq pool-disconnect --sensor-id daq-e-def330
```

***

## `pool-connect` — відкрити датчик у пулі

| Варіант | Значення |
| --- | --- |
| `daq pool-connect` | Розумне виявлення: знайти будь-який DAQ на цій машині. |
| `daq pool-connect --port PORT` | DAQ-U на певному послідовному порту (наприклад, `COM3`, `/dev/ttyUSB0`). |
| `daq pool-connect --ble` | DAQ-M через BLE, автоматичне сканування MAC-адреси. |
| `daq pool-connect --mac MAC` | DAQ-M за відомим MAC-адресою BLE (означає `--ble`). |
| `daq pool-connect --eth-host HOST` | DAQ-E за відомим іменем хоста або IP-адресою — **надійний шлях**. |
| `daq pool-connect --eth` | DAQ-E з автоматичним виявленням (mDNS, з резервним використанням ARP). Див. застереження нижче. |

Прапори налаштування, усі необов’язкові:

| Прапор | Значення |
| --- | --- |
| `--integration-time MS` / `-t MS` | Час інтеграції, заданий вручну, у мілісекундах. |
| `--frame-avg N` / `-f N` | Кількість кадрів, що усереднюються для кожного спектра, що передається. |
| `--no-ae` | Вимкнути автоматичну експозицію (AE увімкнено за замовчуванням). |
| `--no-stream` | Підключитися без запуску потоку (продовжити пізніше за допомогою `pool-stream --start`). |
| `--cap-id CAP` | Профіль корекції капа; за замовчуванням у бекенді використовується `sunshine_cosine`. Див. [`pool-set-cap`](#pool-set-cap-declare-the-fitted-cap). |

{% hint style="warning" %}
**Застереження щодо автоматичного виявлення `--eth`.** На хості з кількома мережевими інтерфейсами (більше одного активного мережевого інтерфейсу) *перший* виклик `pool-connect --eth` після завантаження може завершитися безрезультатно, навіть якщо датчик працює справно — під час сканування для виявлення може бути пропущений інтерфейс датчика, поки кеш ARP ще не завантажений. Якщо `--eth` нічого не знаходить, спробуйте ще раз або повністю пропустіть виявлення за допомогою `--eth-host <ip-or-hostname>`, що є надійним шляхом для машин з кількома мережевими інтерфейсами. Ім’я хоста DAQ-E — `daq-e-<id>.local` (наприклад, `daq-e-def330.local`); також працює його звичайна IP-адреса.
{% endhint %}

## `pool-list` — перегляд підключених пристроїв

Відображає всі датчики у пулі бекенду, включаючи `sensor_id`, який необхідний для виконання всіх інших команд:

| Модель | Формат `sensor_id` | Приклад |
| --- | --- | --- |
| DAQ-U / DAQ-M | 5-октетовий з дефісами | `CB-7C-A8-2E-5F` |
| DAQ-E | `daq-e-<6 hex digits>` | `daq-e-def330` |

## `pool-latest` — читання кадрів спектру

```bash
chloros-cli daq pool-latest --sensor-id daq-e-def330 --recent 10 --json
```

Повертає найновіший кадр або найновіші кадри `--recent N`; `--json` видає машиночитаний вихідний код для використання у скриптах. Кадри представляють собою радіометрично відкалібровану спектральну інтенсивність випромінювання (Вт/м²/нм) у сітці з 135 точками в діапазоні 340–1010 нм, до якої вже застосовано профіль кришки датчика. Для отримання кількісних значень інтенсивності випромінювання слід усереднювати дані щонайменше за 15 секунд кадрів — це характеристика приладу, а не його несправність.

## `pool-stream` — призупинити або відновити потокову передачу

```bash
chloros-cli daq pool-stream --sensor-id daq-e-def330 --stop    # pause
chloros-cli daq pool-stream --sensor-id daq-e-def330 --start   # resume
```

## `pool-record` — запис файлу `.daq`

```bash
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
  --output ~/Documents/spectra --device-name "rooftop-A"
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

| Прапорець | За замовчуванням | Значення |
| --- | --- | --- |
| `--duration SEC` / `-d SEC` | `0` | Тривалість запису в секундах; `0` означає, що процес триватиме доти, доки ви не введете `--stop`. |
| `--output DIR` / `-o DIR` | `~/Documents/DAQ Live View/` | Каталог виводу, визначається **на машині, де працює бекенд**. |
| `--device-name NAME` | — | Мітка, що зберігається разом із записом. |
| `--stop` | — | Припинення запису, що виконується. |

{% hint style="info" %}
Запис відбувається на сервері, тому файл `.daq` зберігається у файловій системі **машини бекенду** — за замовчуванням у `~/Documents/DAQ Live View/` саме там, а не обов’язково там, де ви запустили CLI. Імена файлів містять ідентифікатор датчика та мітку часу.
{% endhint %}

## `pool-set-cap` — вкажіть встановлений ковпачок

```bash
chloros-cli daq pool-set-cap --sensor-id daq-e-def330 --cap-id sunshine_cosine
```

Ідентифікатор ковпачка визначає виміряний на заводі профіль корекції, що застосовується до кожного спектра, і він **повинен відповідати ковпачку, фізично встановленому на датчику** — ані датчик, ані програмне забезпечення не можуть самостійно виявити ковпачок, і вибір зафіксовано у кожному файлі `.daq`. За замовчуванням скрізь використовується `sunshine_cosine` (кожен DAQ постачається з встановленим коректором косинуса Sunshine, що за проектом забезпечує ослаблення приблизно в 12 разів — незадекларована зміна коректора призводить до неправильної корекції спектрів приблизно на цей коефіцієнт).

| `--cap-id` | Доступно на |
| --- | --- |
| `sunshine_cosine` (за замовчуванням) | DAQ-U, DAQ-M, DAQ-E |
| `fov_15`, `fov_45`, `fov_90` | DAQ-U, DAQ-E |
| `fov_30`, `fov_60` | Тільки DAQ-U |
| `none` | Тільки DAQ-E — див. примітку |

Ідентифікатор кришки, що не входить до набору датчика, відхиляється під час підключення з явною помилкою. `none` (DAQ-E) означає, що ковпачок фізично знято — пристрій все ще застосовує заводський геометричний профіль для вбудованого скляного дифузора DAQ-E, тому це не є «no-op», а DAQ-E без ковпачка є лабораторною конфігурацією, а не підтримуваною польовою конфігурацією. (Датчик DAQ-U без кришки є повністю «голим» і взагалі не потребує профілю корекції; датчик DAQ-M використовується разом із кришкою Sunshine.)

## `pool-disconnect` — звільнення датчиків

```bash
chloros-cli daq pool-disconnect --sensor-id daq-e-def330   # one sensor
chloros-cli daq pool-disconnect --all                      # everything in the pool
```

***

## Зведення команд

| Команда | Призначення |
| --- | --- |
| `daq pool-connect [--port P \| --ble \| --mac M \| --eth \| --eth-host H] [-t MS] [-f N] [--no-ae] [--no-stream] [--cap-id CAP]` | Відкрити датчик у пулі бекенду. |
| `daq pool-list` | Показати всі датчики у пулі разом із їхніми `sensor_id`. |
| `daq pool-latest --sensor-id ID [--recent N] [--json]` | Останні N каліброваних спектральних кадрів. |
| `daq pool-stream --sensor-id ID [--start \| --stop]` | Відновити / призупинити потокову передачу. |
| `daq pool-record --sensor-id ID [-d SEC] [-o DIR] [--device-name NAME] [--stop]` | Запустити / зупинити запис `.daq` (на стороні бекенду). |
| `daq pool-set-cap --sensor-id ID --cap-id CAP` | Зміна профілю корекції обмеження під час роботи. |
| `daq pool-disconnect --sensor-id ID [--all]` | Відключення одного датчика або всіх датчиків. |

***

## Усунення несправностей під час першого підключення DAQ-E

1. DAQ-E не має світлодіода стану — перевірте наявність живлення за допомогою індикатора PoE/з&#x27;єднання на комутаторі або порту інжектора та зачекайте кілька секунд після увімкнення, щоб пристрій завантажився та підключився до мережі.
2. Комп’ютер-сервер повинен перебувати в **тому самому домені мовлення**, що й датчик — mDNS не проходить через маршрутизатори.
3. На Windows під час першого запуску підтвердьте запит брандмауера Defender (mDNS UDP 5353, дані DAQ-E UDP 5002, PTP UDP 319/320).
4. Все ще немає сигналу від `--eth`? Скористайтеся `--eth-host` із іменем хоста пристрою (`daq-e-<id>.local`) або його IP-адресою — це надійніший шлях, особливо на хостах із кількома підключеннями.
