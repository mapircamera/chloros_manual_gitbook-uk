# Посібник з NVIDIA Jetson

Chloros на платформі NVIDIA Jetson забезпечує мультиспектральну обробку зображень на периферії — у польових умовах, на безпілотних літальних апаратах та у віддалених установках. Chloros 1.2.0 визначає модель Jetson під час запуску та оптимізує стратегію обробки відповідно до виявленого апаратного забезпечення. **Ручне налаштування не потрібне.**

***

## Підтримувані моделі Jetson

| Модель                | Оперативна пам’ять            | Стратегія обробки                                     | Рекомендоване використання                                          |
| -------------------- | -------------- | ------------------------------------------------------- | -------------------------------------------------------- |
| **Jetson AGX Orin**  | 32–64 ГБ спільного | `GPU_PARALLEL` (2 робочі процеси)                              | Максимальна продуктивність, великі набори даних                      |
| **Jetson Orin NX**   | 8–16 ГБ спільного | `GPU_PARALLEL` (2 робочі процеси, 16 ГБ) / `GPU_SINGLE` (8 ГБ)   | Основна рекомендація для розгортання в повітряних та польових умовах |
| **Jetson Orin Nano** | 8 ГБ спільної пам&#x27;яті     | `GPU_SINGLE` (1 робочий процес, послідовний)                     | Початковий рівень периферійних обчислень                                 |

{% hint style="info" %}
Пакет Linux для архітектури arm64 вимагає **JetPack 6**, який доступний для сімейства Jetson Orin. Старіші моделі (Nano, TX2, Xavier NX) не можуть працювати з JetPack 6 і не підтримуються цим пакетом.
{% endhint %}

***

## Вимоги

* **JetPack 6.x** (рекомендується найновіша версія)
* **NVIDIA CUDA** (входить до складу JetPack)
* **Платний тарифний план Chloros+** — рівень Copper або вище (необхідний для доступу до всіх CLI/SDK; перевірка здійснюється на стороні сервера)

## Встановлення

```bash
# Install the JetPack 6 .deb package
sudo dpkg -i chloros_1.2.0_arm64_jp6.deb
sudo apt-get install -f

# Verify installation
chloros-cli --version    # prints "Chloros CLI 1.2.0"

# Install Python SDK (optional) — the bundled wheel always matches this build
pip install --user /usr/lib/chloros/sdk/chloros_sdk-*.whl

# Run system diagnostics
chloros-cli selftest
```

Загальні відомості щодо встановлення Linux, розташування файлів та усунення несправностей див. у розділі [Встановлення Linux](linux-installation.md).

{% hint style="info" %}
**Розмістіть каталог для розпакування на швидкому носії.** Скомпільовані бінарні файли розпаковуються у тимчасовий каталог під час кожного запуску — з SD-карти це відбувається надзвичайно повільно. Chloros автоматично використовує `/mnt/ssd/tmp`, якщо той існує; в іншому випадку вкажіть для `TMPDIR` шлях на вашому NVMe (`export TMPDIR=/mnt/nvme/tmp`).
{% endhint %}

## Динамічна адаптація обчислювальних потужностей на Jetson

### Як це працює

Під час запуску Chloros аналізує вашу систему:

1. **Виявляє модель Jetson** за допомогою `/proc/device-tree/model`
2. **Зчитує обсяг доступної спільної пам’яті GPU/CPU** (Jetson використовує уніфіковану пам’ять)
3. **Вибирає стратегію обробки** (`GPU_PARALLEL`, `GPU_SINGLE` або `CPU_PARALLEL`)
4. **Автоматично встановлює кількість робочих процесів, тип конвеєра та розподіл пам’яті**Рішення залежить від**загального обсягу спільної оперативної пам’яті**, а не від назви моделі:

* **Загальний обсяг оперативної пам’яті менше 12 ГБ**(усі Jetson з 8 ГБ): `GPU_SINGLE` з**1 робочим процесом — цілеспрямована послідовна обробка**. Обсягу пам’яті недостатньо для одночасного виконання декількох робочих процесів, тому зображення обробляються по одному. На пристроях Jetson з**8 ГБ або менше** потік 3 повністю оминає пул робочих процесів і виконує обробку кожного зображення в рамках одного процесу.
* **12 ГБ або більше**(Orin NX 16 ГБ, AGX Orin): об’єднана пам’ять відповідає вимогам для `GPU_PARALLEL`, але кількість робочих процесів**обмежена до 2 на Jetson** — графічний процесор, оперативна пам&#x27;ять робочих процесів та їхні контексти CUDA для кожного робочого процесу використовують один і той самий спільний пул, тому збільшення кількості робочих процесів підвищує ризик помилок через нестачу пам&#x27;яті.

Ви можете замінити автоматичний вибір за допомогою змінної середовища `CHLOROS_STRATEGY` — див. [Динамічна адаптація обчислень](../processing-architecture/dynamic-compute-adaptation.md#manual-strategy-override).

### Поведінка для кожної моделі

| Модель Jetson                | Стратегія       | Робочі процеси | Виконання                                      |
| --------------------------- | -------------- | ------- | ---------------------------------------------- |
| **Jetson Orin Nano 8 ГБ**    | `GPU_SINGLE`   | 1       | Послідовний цикл у процесі (`tiled_gpu` за умови нестачі пам’яті) |
| **Jetson Orin NX 8 ГБ**      | `GPU_SINGLE`   | 1       | Послідовний цикл у процесі                     |
| **Jetson Orin NX 16 ГБ**     | `GPU_PARALLEL` | 2       | Паралельні робочі процеси, шлях `fused_gpu`  |
| **Jetson AGX Orin 32–64 ГБ** | `GPU_PARALLEL` | 2       | Паралельні робочі процеси, шлях `fused_gpu`  |

Ключовою відмінністю між платформами є **обсяг пам&#x27;яті**. Jetson з 8 ГБ пам&#x27;яті під час високого навантаження має обробляти зображення по одному, використовуючи ефективний з точки зору використання пам&#x27;яті підхід з поділом на фрагменти, тоді як Orin з 16 ГБ і більше може одночасно обробляти 2 зображення за допомогою графічного процесора, використовуючи об&#x27;єднаний конвеєр з вищою пропускною здатністю.

### Бюджет графічного процесора для кожної моделі

Кожна модель Jetson також має апаратний профіль, який обмежує обсяг ресурсів спільного пулу, що може бути задіяний для обробки, та масштабує розміри пакетів:

| Модель | Верхня межа бюджету графічного процесора | Множник розміру пакета | Зарезервовано для системи/дисплея |
| --- | --- | --- | --- |
| **Jetson Orin Nano** | 70 % | ×0,8 | 2,0 ГБ |
| **Jetson Orin NX** | 75 % | ×1,0 | 3,0 ГБ |
| **Jetson AGX Orin** | 80 % | ×1,5 | 4,0 ГБ |

Профіль коригується відповідно до виявленого обсягу оперативної пам’яті: для пристроїв Jetson, що повідомляють про наявність **16 ГБ або більше**, множник розміру пакету збільшується на ×1,2. Базовий розмір пакету до застосування множників становить 8 зображень.

Повний довідник щодо адаптації обчислювальних потужностей див. у розділі [Динамічна адаптація обчислювальних потужностей](../processing-architecture/dynamic-compute-adaptation.md).

## Обмеження частоти GPU для функції Texture Aware на Nano та Orin Nano

Альгоритм Texture Aware для дебейєрингу виконує інференцію нейронної мережі на GPU, що може спричинити **попередження про перевищення струму**на моделях Jetson з низьким енергоспоживанням (клас 10–15 Вт) при повній тактовій частоті GPU. Перед початком обробки за допомогою Texture Aware на**Jetson Nano або Orin Nano**модуль Chloros перевіряє максимальну частоту графічного процесора та обмежує її до**510 МГц** (510000000), якщо поточна частота вища:

* Якщо CLI може записати значення частоти графічного процесора у вузол sysfs, обмеження **застосовується автоматично**, і на екран виводиться підтвердження.
* Якщо ні (потрібні права root), CLI виводить точну команду `sudo` для ручного застосування обмеження, чекає деякий час, щоб ви могли її прочитати, а потім продовжує роботу — обробка все ще триває, але можуть з’являтися попередження про перевищення струму.

Щоб самостійно застосувати обмеження перед обробкою:

```bash
echo 510000000 | sudo tee /sys/devices/platform/bus@0/17000000.gpu/devfreq/17000000.gpu/max_freq
```

Моделі з більшою потужністю (Orin NX 25 Вт, AGX Orin 60 Вт) працюють на повній швидкості графічного процесора; обмеження не застосовується. Стандартний дебейер ніколи не запускає обмеження на жодній моделі.

{% hint style="info" %}
**Технітура Aware на Jetson завжди обробляє по одному зображенню за раз.** Кожному робочому процесу потрібен власний контекст CUDA (~1 ГБ) та власна копія моделі шумозаглушення, чого не може забезпечити об’єднана пам’ять — тому на Jetson шлях Texture Aware прив’язаний до одного робочого процесу з послідовним доступом до графічного процесора. Очікуйте, що Texture Aware буде помітно повільнішим за Standard на будь-якому Jetson.
{% endhint %}

## Управління тепловим режимом

Пристрої Jetson мають обмежений запас теплової потужності, особливо в закритих приміщеннях або під час використання в повітряних суднах. Chloros контролює температуру SoC і автоматично регулює розмір пакетів:

| Температура         | Дія                                            |
| ------------------- | ------------------------------------------------- |
| **&lt; 70 °C**          | Нормальна робота — повна швидкість обробки          |
| **70 °C** (Попередження) | Розмір пакета поступово зменшується (100 % → 50 % у діапазоні від 70 °C до 80 °C) |
| **80 °C** (Критичний) | Агресивне обмеження (від 50 % до 0 % у діапазоні від 80 °C до 90 °C) |
| **90 °C** (Вимкнення) | Повне припинення обробки на GPU — необхідне охолодження |

{% hint style="warning" %}
**Забезпечте належну вентиляцію та відведення тепла** для безперебійної роботи, особливо в закритих польових корпусах або бортових системах. Терморегулювання знизить продуктивність обробки даних для захисту апаратного забезпечення.
{% endhint %}

## Управління пам’яттю

Пристрої Jetson використовують **уніфіковану пам’ять** — графічний процесор (GPU) та центральний процесор (CPU) спільно використовують одну й ту саму фізичну оперативну пам’ять (RAM). Вказаний обсяг відеопам’яті (VRAM) (наприклад, ~15,3 ГБ на Orin NX 16 ГБ) не є виділеною пам’яттю для графічного процесора; це та сама оперативна пам’ять, яку використовують операційна система та всі інші процеси.

### Попередження щодо підкачки та рекомендації

Перед початком обробки на Jetson CLI підраховує кількість RAW-зображень у вашій вхідній папці (`.tif`, `.tiff`, `.raw`, `.dng` — попередні перегляди у форматі JPG не враховуються), оцінює піковий обсяг пам’яті, необхідний для виконання, і **попереджає перед запуском**, якщо оперативної пам’яті та обміну, ймовірно, недостатньо. Попередження має заголовок `LOW MEMORY WARNING - Jetson Detected`, відображає кількість зображень, обсяг оперативної пам’яті, поточний обсяг обмінного простору та оцінку пікового споживання, а потім надає точні команди `fallocate` / `chmod` / `mkswap` / `swapon`, розмір яких підібрано відповідно до вашого проєкту (ніколи менше 8 ГБ). Програма робить паузу на кілька секунд, щоб повідомлення не загубилося у стрічці прокрутки, а потім продовжує обробку.**Оцінки обсягу пам’яті, що використовуються у попередженні:**

| Режим дебейєрингу | Базовий | На зображення |
| --- | --- | --- |
| Стандартний | ~1,5 ГБ | ~10 МБ |
| З урахуванням текстур | ~2,5 ГБ (модель + час виконання Python) | ~15 МБ |

Попередження спрацьовує, коли розрахований піковий обсяг перевищує обсяг оперативної пам’яті + обмінну пам’ять за вирахуванням запасу безпеки в 1 ГБ, причому враховується лише **обмінна пам’ять, підкріплена файлами** — конфігурація, що використовує виключно zram, все одно буде позначена як проблема.

Щоб додати обмінну пам’ять вручну (приклад: 8 ГБ):



<!-- SCREENSHOT-NEEDED: Terminal on a Jetson Orin (SSH session) showing the full "LOW MEMORY WARNING - Jetson Detected" block printed by `chloros-cli process` on a large folder: the image count and debayer mode line, RAM / current swap / estimated peak figures, and the fallocate/chmod/mkswap/swapon command block it recommends -->

```bash
# Check current memory and swap
free -h

# Create a swap file
sudo fallocate -l 8G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Make persistent across reboots
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```### Обробка OOM (Out of Memory)

Під час обробки Chloros відстежує пам’ять графічного процесора та плавно знижує продуктивність замість того, щоб аварійно завершувати роботу:

1. Коли завантаження пам&#x27;яті графічного процесора перевищує **85%**, розмір пакетів попередньо зменшується
2. Якщо ситуація нестачі пам&#x27;яті все ж виникає, розмір пакета **зменшується вдвічі**, і знову зменшується вдвічі при кожному наступному випадку нестачі пам&#x27;яті; кожний наступний успішно оброблений пакет зменшує це обмеження на один крок
3. За умов тривалого навантаження конвеєр переходить з режиму `fused_gpu` на енергоефективний режим `tiled_gpu`, а в крайньому випадку — на обробку на CPU

## Впровадження в умовах реального використання

### Рекомендації щодо енергоспоживання

| Модель Jetson     | Типове енергоспоживання | Примітки                   |
| ---------------- | ------------------ | ----------------------- |
| Jetson Orin Nano | 7–15 Вт              | Роз’єм DC типу «barrel»          |
| Jetson Orin NX   | 10–25 Вт             | Роз’єм DC типу «barrel»          |
| Jetson AGX Orin  | 15–60 Вт             | USB-C PD або роз’єм типу «barrel» |

Сплануйте енергоспоживання для тривалої обробки — пікове споживання енергії відбувається під час виконання потоку 3 (обробка), що інтенсивно задіює графічний процесор.

### Рекомендації щодо сховищ даних

* **SSD NVMe** настійно рекомендується для розгортання на архітектурі arm64
* SD-картки занадто повільні для обробки даних — використовуйте їх лише як завантажувальний носій
* Заплануйте обсяг, що в 2–3 рази перевищує розмір вихідних даних зображення, для оброблених результатів

### Робота без монітора через SSH

Chloros та CLI ідеально підходять для розгортання Jetson без монітора:

```bash
# SSH into the Jetson
ssh user@jetson-hostname

# Process a dataset
chloros-cli process /data/datasets/flight001 --format "TIFF (32-bit, Percent)"

# Monitor export progress
chloros-cli export-status
```

### Постійно активний бекенд для синхронізації часу LATTICE / DAQ-E

Якщо ваш Jetson безмоніторно керує камерами LATTICE або світловими датчиками DAQ-E, увімкніть службу systemd бекенду, щоб головний сервер PTP працював безперервно (модуль встановлено, але за замовчуванням не увімкнено):

```bash
sudo systemctl enable --now chloros-backend.service
chloros-cli time-sync status
```

Детальнішу інформацію, зокрема про те, як пакет забезпечує можливість прив’язки портів PTP 319/320 без прав суперкористувача, див. у розділі [Встановлення Linux](linux-installation.md#always-on-ptp-for-headless-hosts).

### Автоматизована обробка за допомогою systemd

Створіть службу systemd для автоматизованої обробки:

```ini
# /etc/systemd/system/chloros-process.service
[Unit]
Description=Chloros Automated Processing
After=network.target

[Service]
Type=oneshot
User=chloros
ExecStart=/usr/bin/chloros-cli process /data/incoming --output /data/processed
StandardOutput=append:/var/log/chloros-process.log
StandardError=append:/var/log/chloros-process.log

[Install]
WantedBy=multi-user.target
```

`chloros-cli process` завершує роботу з ненульовим кодом, якщо запуск, що запитував продукти, не записує жодних зображень, тому статус помилки systemd є значущим для моніторингу.

Поєднайте з таймером systemd для запланованої обробки:

```ini
# /etc/systemd/system/chloros-process.timer
[Unit]
Description=Run Chloros Processing Every Hour

[Timer]
OnCalendar=hourly
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl enable chloros-process.timer
sudo systemctl start chloros-process.timer
```

## Приклади робочих процесів

### Базова обробка на Jetson

```bash
#!/bin/bash
# Process a drone flight dataset on Jetson
chloros-cli process /data/flights/flight_042 \
    --output /data/processed/flight_042 \
    --format "TIFF (32-bit, Percent)" \
    --indices NDVI NDRE GNDVI
```

### Python та SDK на Jetson

```python
from chloros_sdk import ChlorosLocal

with ChlorosLocal() as chloros:
    chloros.create_project("field_survey_042")
    chloros.import_images("/data/flights/flight_042")
    chloros.configure(
        indices=["NDVI", "NDRE", "GNDVI"],
        export_format="TIFF (32-bit, Percent)",
        reflectance_calibration=True
    )
    chloros.process(mode="parallel")

print("Processing complete!")
```

### Пакетна обробка даних з декількох польотів

```bash
#!/bin/bash
# Process all flight datasets in a directory
for flight in /data/flights/*/; do
    name=$(basename "$flight")
    echo "Processing $name..."
    chloros-cli process "$flight" \
        --output "/data/processed/$name" \
        --format "TIFF (32-bit, Percent)" \
        --indices NDVI NDRE
    echo "Completed $name"
done
```

## Рекомендовані системи Jetson для польового використання

Для польового та повітряного застосування рекомендуємо розглянути такі варіанти несучої плати Jetson Orin NX 16 ГБ:

* **Повітряні/дрони**: Системи з вібростійкістю (MIL-STD), легкі (до 300 г), з пасивним охолодженням
* **Надійні для польових умов**: Водонепроникні корпуси класу IP67/IP69K з підключенням камер через PoE GigE
* **Мінімальний/економний варіант**: набори для розробників із додатковими корпусами

Зверніться до [служби підтримки MAPIR](https://www.mapir.camera/community/contact), щоб отримати конкретні рекомендації щодо апаратного забезпечення для вашого сценарію розгортання.
