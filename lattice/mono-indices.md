# Монохромні камери та індекси рослинності

## Одна камера = один діапазон

Камера **M3M**— це монохромний аналог моделі Bayer**M3C**: монохромний сенсор IMX265, оснащений одним вузькосмуговим інтерференційним фільтром. Назва моделі вказує на діапазон — `M3M-<lens>-F<wavelength>`, наприклад, `M3M-L87-F685` (у програмі Chloros

відображається як `LATT-M3M-L87-F685`). Сенсор забезпечує **один діапазон відтінків сірого** без мозаїки Байєра: немає чого демозаїкувати, немає міжканальних перехресних перешкод, які потрібно розділяти, і немає балансу білого, який потрібно налаштовувати.

Наслідки, про які варто знати перед плануванням монохромної системи:

* **Радіанс та відбивна здатність повністю визначені для кожного діапазону.**Це радіометричні карти для кожного діапазону, тому одна камера M3M видає відкалібровані значення випромінювання у форматі float32 (Вт/м²/sr/нм) та відбиття у форматі uint16 (`32768` = ρ 1,0) точно так само, як це робить діапазон M3C. Монохроматичні кадри містять**ідентичну** матрицю відгуку сенсора — розкладання 3×3 не потрібне і не застосовується.
* **Одна монохроматична камера не може генерувати індекс рослинності.** Для розрахунку NDVI

, NDRE

та подібних показників потрібно щонайменше два діапазони. Щоб обчислювати індекси за допомогою монохроматичного обладнання, слід поєднати кілька камер M3M — див. нижче.
* Камери M3M передають потік **Mono12** (12-бітний: 2 байти/піксель у мережі або 1,5 байта/піксель, коли масив використовує [ущільнений 12-бітний транспорт](arrays.md#packed-12-bit-transport)), що має значення для [розрахунку пропускної здатності масиву](arrays.md#bandwidth-how-many-cameras-fit).

## Що Chloros

пропускає для моно — і як про це повідомляє

Етапи кольорового конвеєра просто не застосовуються до односмугового сенсора. Chloros

**пропускає їх, виводячи однорядкове повідомлення**, а не видаючи помилку, і при цьому нормально виконує їх для будь-якої камери M3C (Bayer) у тій самій сесії:

| Етап | Поведінка в монорежимі (M3M) | Поведінка в M3C |
| --- | --- | --- |
| Демозаїка / дебейер | Пропущено — рівень експорту `debayered` є 1-канальним зображенням у відтінках сірого. | 3-канальна демозаїка. |
| Баланс білого (`lattice white-balance`) | Пропускається з однорядковим повідомленням. | Виконується нормально. |
| Колірний профіль (`lattice color-profile`) | Пропускається з однорядковим повідомленням. | Виконується нормально. |
| Насиченість/контраст (`lattice color`) | Пропускається з однорядковим повідомленням. | Працює нормально. |
| Розділення спектральних перехресних перешкод | Ідентичне (без матриці 3×3). | Застосовано матрицю 3×3 для кожної камери. |
| Яскравість / відбивна здатність | **Працює** — для кожного діапазону, повністю відкалібровано. | Працює для кожного діапазону. |

Графічний інтерфейс застосовує те саме обмеження: для монохромної камери панель налаштувань для кожної камери приховує рядки, що стосуються лише RGB

(баланс білого, гамма, колірний профіль, насиченість, контраст, розділення каналів), а гістограма в режимі реального часу зафіксована на одній кривій **MONO**. Дискримінатором у всьому стеку є токен `M3M` у рядку моделі, який відображається в графічному інтерфейсі користувача/SDK

як `is_mono`.

## Індекси потребують ≥ 2 діапазонів: вирівнювання → стекування → індексація

Робочий процес моно-індексу завжди складається з трьох однакових етапів:

1. **Вирівнювання** — наведіть кілька камер M3M на різні довжини хвиль (наприклад, F650 «Red

» та F850 «NIR

»), з’єднайте їх у [масив з декількох камер](arrays.md) і дозвольте Chloros

обчислити деформацію для спільного вирівнювання між камерами.
2. **Стекування** — вирівняні кадри об’єднуються в одне багатосмугове зображення (кожна камера надає одну іменовану смугу).
3. **Індекс** — обчислення формули індексу для смуг стека з можливістю візуалізації через таблицю перекладу (LUT).

У графічному інтерфейсі весь цей ланцюжок реалізовано у режимі відображення масиву **Combined Cameras**: композитне зображення в режимі реального часу вже вирівняно, а калькулятор індексу масиву (нижче) визначає формулу, за якою воно візуалізується. Експортовані знімки можна виправити до того самого вирівнювання за допомогою опції зйомки**Вирівняно**.

## Калькулятор індексу

Калькулятор індексу створює вираз індексу, який використовується у режимі реального часу та при експорті індексу для кожної камери окремо. Це одна спільна поверхня, яку можна відкрити з двох місць на бічній панелі вкладки «Камери»:

* **Для кожної камери**— «Попередній перегляд у реальному часі» → значок налаштувань**Індекс** (лише камери RGN

/OCN

/NGB

з матрицею Байєра; окрема монохромна камера не має керування індексом, оскільки одна смуга не може утворити індекс).
* **Для масиву**— налаштування масиву → Попередній перегляд у реальному часі → значок налаштувань**Індекс**. Це монохромний шлях: список діапазонів охоплює**усі камери, що входять до масиву**, тому монохромна пара додає сюди свої два діапазони.

Елементи керування, зверху вниз:

* **Чіпи діапазонів** («Діапазони — натисніть, щоб додати до виразу») — одна кнопка на кожен доступний діапазон, позначена назвою кольору + довжиною хвилі в нм (повторювані назви кольорів розрізняються, наприклад, як «Колір 850»). Натискання вставляє маркер діапазону в місце курсора. Діапазони з камер, які не можуть генерувати радіанс для кожного діапазону окремо (RGB

/FRGB), відфільтровуються.
* **Кнопки операторів та функцій** — `+ - * / ( ) ^ ,` та `abs() sqrt() log() log10() exp() min() max() pow()`.
* **Текстове поле виразу** — формула, що вводиться вільно; у місці-заповнювачі відображається класична форма NDVI

: `(NIR - Red) / (NIR + Red)`. Попередній перегляд у режимі «тільки для читання» над ним, що складається з токенів, відображає фрагменти смуг, числа та позначки невідомих токенів.
* **Смуга дійсності**— сіра «Порожньо — індекс не застосовуватиметься»; зелена «Дійсний вираз»; червона з конкретною помилкою синтаксичного аналізу (невідома смуга, неоднозначна смуга, що фіксується кількома камерами, відсутня дужка тощо); або жовта, коли вираз є дійсним, але**константа** (наприклад, `X/X` або знаменник NDVI

, введений як `−` замість `+`) — константа відображає весь кадр одним кольором.
* Окреме помаранчеве попередження з’являється, якщо застосоване вираження є правильним, але **кадр у реальному часі є однорідним** (рівна або насичена сцена) — для вас виявлено збіг гістограми.
* **Застосувати LUT**(за замовчуванням увімкнено; вимкнено = розтягнення в відтінках сірого),**Рівень**2/3/5/7 ступенів (за замовчуванням 7 ступенів) та поля введення**Мін. / Макс.**, розташовані по боках смуги градієнта. За замовчуванням**Min**дорівнює**0,2**— це збільшує колірний діапазон у межах, що відповідають рослинності, тоді як значення нижче цього проходять як відтінки сірого; встановіть**Min**на −1 для повного діапазону індексу (кнопка**Скинути**відновлює діапазон від −1 до +1). За замовчуванням**Max** дорівнює 1.
* **Гістограма в реальному часі** розподілу індексу — стовпчики, масштабовані за коренем квадратним, бурштинові лінії 2-го та 98-го процентилів, біла лінія медіани та показники хвостів поза діапазоном («◀ N% &lt; lo» / «hi &lt; N% ▶»), які стають бурштиновими при значенні понад 1 % як сигнал до розширення діапазону Min/Max.
* **Застосувати** застосовує вираз до потоку даних у реальному часі; налаштування LUT застосовуються в реальному часі без натискання кнопки «Застосувати». Якщо проект відкрито, налаштування виразу та LUT зберігаються разом із проектом і відновлюються при його повторному відкритті; якщо проект відсутній, вони зберігаються лише протягом сеансу.

## Шлях CLI



Той самий ланцюжок «вирівнювання → стек → індекс», який можна повністю налаштувати за допомогою скриптів:

```bash
chloros-cli lattice align-calibrate --serials SN_RED,SN_NIR --save align.json
chloros-cli lattice index --live --profile align.json \
  --preset NDVI --channel red=Red_660 --channel nir=NIR_850 \
  --save-multiband -o output/
```

`align-calibrate` використовує підключений масив, що містить його камери, або відкриває їх самостійно для одного запуску. `index --live` завжди самостійно відкриває камери ([тимчасовий масив](../reference/cli-reference.md#multi-camera-transient-sessions)) і не має `--serials`: він відкриває кожну камеру в мережі. Тому звільніть усі камери, які утримує Chloros

, до того, як — графічний інтерфейс, `cam-connect`, `array-connect` (`chloros-cli lattice array-disconnect --all`): повторне відкриття заблокованої камери може зупинити потік її власника або призвести до збою серверної частини. Камера, яка не передає кадри, призводить до збою запуску, і стек або індекс не записуються.

`--channel` зіставляє символи пресета з назвами діапазонів стека. Два правила допоможуть уникнути невдалого запуску:

* **У символах враховується регістр**, і вони повинні точно відповідати назвам каналів пресета — у пресетах використовуються малі літери (пресети NDVI

мають назви `red`, `nir`; перевірте `--list-presets`). `--channel red=Red_660` працює; `--channel RED=660` завершується з помилкою `channel_map missing entries`.
* У параметрі «band side» слід вказати назву смуги у вирівняному стеку (`lattice align-info --profile align.json` містить їх перелік). У автономному режимі також допускаються індекси смуг, що починаються з 0, наприклад, `--channel red=0 --channel nir=1`.

`lattice index` також працює в автономному режимі з збереженим вирівняним багатосмуговим файлом TIFF

. Кожна форма працює на серверній частині, тому вона повинна бути запущена та авторизована на платному рівні Chloros

+; відносні `--input` або `--output` визначаються відносно папки, з якої ви запускаєте команду:

```bash
chloros-cli lattice index --input aligned.tif --preset NDVI \
  --output ndvi.tif --colorize --gradient RdYlGn
```

### Пресети індексу

`lattice index --preset` (а також [Індекс/LUT-пісочниця](../image-viewer-gui/index-lut-sandbox.md) на вкладці «Зображення», яка використовує той самий движок) містить ці **22 пресети**:

`NDVI, GNDVI, BNDVI, NDRE, ENDVI, SAVI, OSAVI, MSAVI, EVI, EVI2, CVI, MSR, TDVI, LAI, GLI, NGRDI, VARI, TGI, EXG, CIRE, CIGREEN, NDWI`

Виконайте `chloros-cli lattice index --list-presets`, щоб переглянути формули та символи каналів для кожного пресета, а `--list-gradients` — щоб переглянути доступні колірні градієнти. Для власних формул використовуйте `--formula EXPR` із тим самим синтаксисом, що й у «Калькуляторі індексів». Зверніть увагу, що цей список пресетів стосується саме індексного двигуна LATTICE — у випадаючому меню «Обробка» в налаштуваннях проєкту для імпортованих зображень міститься інший список (див. [Формули мультиспектральних індексів](../project-settings/multispectral-index-formulas.md)).

Повний набір прапорців (`--output-format`, `--vmin/--vmax/--percentile`, `--bg-mode`, регулятори вирівнювання та деформації для `--live` тощо) описано в розділі [Довідка по CLI

§ Індекси / Математика рослинності](../reference/cli-reference.md#index--vegetation-maths); еквіваленти для SDK

наведені в [Довіднику SDK

](../reference/sdk-reference.md).

## Збирання індексних продуктів із мономасиву

При підключеному масиві та застосованому індексній виразі, `array-capture` (або функція GUI **«Захопити все»**) зберігає рівні експорту для кожної камери *та* індексне зображення — `--index`/`--no-index` вмикає цю функцію в CLI

, а за замовчуванням захоплює всі відповідні рівні. Внесок монокамери в кожну групу запису становить її одну смугу на рівнях необроблених даних/даних після дебейєрингу (у відтінках сірого)/радіансної яскравості/відбиття, а також спільний композитний індекс, коли масив працює в комбінованому режимі. Див. [Масиви з декількох камер § Збір даних](arrays.md#capturing-monitoring-vs-analysis).
