# Налаштування та режими зйомки

Зйомка на вкладці «Камери» здійснюється за допомогою однієї червоної кнопки **«Зняти все»**та однієї панелі**«Налаштування зйомки»**, яка визначає, що саме буде зроблено при натисканні цієї кнопки: які камери братимуть участь, які типи експорту зберігатиме кожна камера, а також чи спрацьовуватиме затвор один раз, у безперервному режимі чи з певним інтервалом. На цій сторінці описано весь процес — налаштування, саму зйомку, місце збереження файлів на диску та подальшу переробку їх у калібровані продукти. Самі елементи керування камерами та масивами знаходяться на сторінці [Налаштування камер](camera-settings.md).

{% hint style="info" %}
**Для зйомки потрібно відкрити проєкт.** Кнопка «Зняти все» та значок налаштувань зйомки у вигляді шестерні недоступні, доки не відкрито проєкт («Створіть або відкрийте проєкт, щоб зберегти знімки»). Кожен знімок зберігається у папці проєкту в `captures/`.
{% endhint %}

## Панель «Налаштування зйомки»

Відкрийте її за допомогою **значка шестерні поруч із кнопкою «Зняти все»**у списку камер на бічній панелі або за допомогою кнопки**«Відкрити налаштування зйомки…»** у нижній частині будь-якої панелі налаштувань окремої камери. У заголовку написано «Налаштування зйомки» із кнопкою ← «Назад».

Ваші налаштування тут — включені камери, прапорці для окремих типів та режим зйомки — зберігаються **для кожного проєкту** і відновлюються при його повторному відкритті.

### Режими зйомки

Три кнопки режимів у верхній частині панелі:

| Режим | Що робить | Додаткові налаштування (за замовчуванням) |
| --- | --- | --- |
| **Одноразовий** *(за замовчуванням)* | Одне знімання з усіх вибраних камер. | — |
| **Безперервний**| Послідовні знімання до настання умови зупинки. | Зупинка за**кількістю знімків** (за замовчуванням 1) *або* **тривалістю зйомки** (за замовчуванням 10 с; одиниці виміру: секунди / хвилини / години / дні). |
| **Інтервал**(таймлапс) | Серія знімків за таймером. |**Кількість знімків на інтервал**(за замовчуванням 1) ·**Кожні**N одиниць (за замовчуванням 5 с) ·**Протягом** N одиниць (за замовчуванням 1 хв). |

У режимах «Безперервний» або «Інтервал» під час роботи кнопка «Зняти все» перетворюється на кнопку **«Зупинити (N)»**, підраховуючи знімки по мірі їх надходження. Повне заповнення накопичувача зупиняє роботу (див. [Процес «Зняти все»](#the-capture-all-flow)).**Режим «Безперервний» для масивів працює у бекенді (нова функція у версії 1.3.0).** Коли кожна камера у списку належить до масиву (автономні камери приховані або виключені), режим «Безперервний» більше не надсилає один запит на кожне захоплення: бекенд Chloros самостійно запускає цикл захоплення, записуючи одну синхронізовану групу, поки вибирає наступну, а кнопка опитує її кількість. Якщо у списку є автономні камери, Chloros здійснює захоплення послідовно, як і раніше.

{% hint style="warning" %}
**Швидке захоплення в Windows: виключіть бекенд Chloros з сканування Microsoft Defender.** Сканування в реальному часі кожного файлу, який записується під час високошвидкісного захоплення, забирає близько 30 % від швидкості захоплення за результатами тестів MAPIR (сотні файлів на секунду при невеликій області інтересу). Інсталятор для Windows пропонує опцію **«Виключити бекенд Chloros з сканування Microsoft Defender (значно швидше захоплення з камери; рекомендується)»**, яка за замовчуванням відмічена, і скасовує це виключення під час видалення програми. Якщо ви зняли цю галочку, запустіть інсталятор ще раз із встановленою галочкою або додайте виключення процесу Defender для `chloros-backend.exe` (у папці `backend` інсталяційної папки Chloros). Коли Defender використовує одне або більше ядер процесора під час безперервного збору даних масиву, бекенд Chloros фіксує це один раз у своєму журналі, пропонуючи ті самі два способи вирішення проблеми.
{% endhint %}

### Вибір камер та типів експорту

Текст довідки у цій панелі підсумовує суть: виберіть, які камери та типи експорту буде використовувати функція «Записати все» — за замовчуванням увімкнено все, і ці налаштування зберігаються разом із цим проєктом.

* Кнопки **«Вибрати все» / «Не вибирати нічого»** одночасно змінюють стан прапорців включення для кожної камери.
* **Перемикачі типів масового експорту**(два ряди кнопок):**Усі Raw / Усі з дебейєрингом / Усі попередні перегляди / Усі Radiance / Усі Reflectance / Усі Index**. Кожен із них має три кольори: зелений ✓ = увімкнено для кожної камери, що підтримує цей тип; жовтий – = увімкнено для деяких; сірий = жодної. Перемикач вимкнений, якщо жодна підключена камера не підтримує цей тип. Усі вони стають сірими, коли увімкнено режим «Найшвидше захоплення».
* **Рядки для кожної камери**: прапорець включення, а також розгортаний (▸/▾) список відповідних типів експорту для цієї камери з окремими прапорцями. У рядку відображається кількість увімкнених опцій у форматі «4/6».

### Типи експорту та камери, які їх підтримують

Існує шість типів експорту: **Raw, Debayered, Radiance, Reflectance, Preview, Index**. У рядку кожної камери відображаються лише ті типи, які для неї доступні:

| Тип експорту | Вміст | RGB (FRGB) | Мультиспектральний Bayer (FRGN/FOCN/FNGB) | Монохромний (M3M) |
| --- | --- | --- | --- | --- |
| **Raw** | Мозаїка Байєра (моно: одна смуга) безпосередньо з сенсора | ✓ | ✓ | ✓ |
| **Без демозаїки** | Лінійна демозаїка: з RAW-файлу видалено темне зміщення (DSNU) з калібрувального набору, потім виконано демозаїку з урахуванням країв — без корекції лінійності, вирівнювання поля або розкладання. Збережено як 3-канальний RGB-файл у форматі TIFF (монохромний: 1-канальний у відтінках сірого) | ✓ | ✓ | ✓ |
| **Попередній перегляд** | Повний ланцюг відображення (баланс білого + гамма згідно з профілем камери, а також налаштування «Highlights» (Яскраві ділянки) для RGB-камери; мультиспектральний: розтягнення у штучних кольорах) | ✓ | ✓ | ✓ |
| **Радіанс** | float32 Вт/м²/sr/нм через повний радіометричний ланцюг | — (не підтримується) | ✓ | ✓ |
| **Коефіцієнт відбиття** | uint16 ρ (32768 = 1,0) | — (не підтримується) | ✓ — відображається лише тоді, коли камера має світловий датчик DAQ (власний або успадкований від масиву) | те саме, що й для мультиспектрального режиму |
| **Індекс** | Відтворення індексу рослинності (LUT) | — | ✓ — вимагає увімкненого, непорожнього виразу індексу на камері та не доступний для членів комбінованого масиву (масив має один спільний індекс) | — (індекс потребує ≥2 діапазонів; див. [Монокамери та індекси рослинності](mono-indices.md)) |

Радіанс та відбивна здатність ніколи не доступні для камер RGB — радіанс за методом Байєра не має сенсу для широкосмугового фотометричного датчика.

### Найшвидше захоплення

Перемикач **⚡ Найшвидше захоплення — лише RAW**(помаранчевий у включеному стані) замінює всі налаштування експорту на**лише RAW** — плюс безкоштовний композитний знімок із комбінованим індексом для масивів — завдяки чому кадр зберігається якомога швидше: обчислення яскравості/відбиття/відображення повністю пропускаються під час захоплення.

{% hint style="info" %}
**Файл `.daq` все одно зберігається.** Коли призначено датчик освітленості, функція «Найшвидше захоплення» все одно записує показання DAQ щодо інтенсивності світла, що падає (у папку `daq/` з записами) — завдяки чому продукти, що відображають інтенсивність випромінювання, відбиття та індекс, можна створити пізніше шляхом повторної обробки (див. [Переобробка знімків](#re-processing-captures-into-calibrated-products)). Функція «Fastest Capture» також не впливає на ваші налаштування, позначені прапорцями: вимкніть її, і вони відновляться.
{% endhint %}

### Елементи керування для кожного масиву

Кожен підключений масив має власну групову картку у панелі:

* **Прапорець «Включити»** (три стани для всіх елементів) та назва масиву з режимом відображення: «(об’єднаний | окремий)».
* **Позначка «Вирівняти»**(за замовчуванням**увімкнено**): вирівнює експортовані файли елементів за профілем вирівнювання масиву, щоб експортовані дані були піксельно зареєстровані між камерами. Необроблені дані залишаються без викривлення, але містять трансформацію у своїх метаданих. (Сам профіль обчислюється у [панелі налаштувань масиву](camera-settings.md#alignment-co-registration).) Файли елементів масиву зберігаються у власній орієнтації кожної камери, при цьому будь-які налаштування дзеркального відображення/обертання записуються у файл, а не застосовуються.
* Рядки камер-елементів вкладені всередину картки.

Картка масиву також містить два реєстратори. Уявіть їх як **моніторинг проти аналізу**:

| Реєстратор | Рівень | Що він записує |
| --- | --- | --- |
| **● Запис індексного відео / ■ Зупинка запису** *(лише для комбінованих масивів)* | **Моніторинг** | Композитне відео з комбінованого індексу в режимі реального часу зі швидкістю 10 кадрів на секунду — 8-бітне, роздільна здатність попереднього перегляду, вбудована LUT. Потрібен відкритий проєкт та потокове перегляд у реальному часі. Під час запису відображаються кадри та час, що минув. |
| **⦿ Запис необробленої серії кадрів / ■ Зупинити серію необроблених кадрів** *(будь-яка матриця)* | **Аналіз**| Необроблені кадри у форматі Байєра зі швидкістю зчитування в реальному часі (без обробки), а також маніфест для кожного кадру та показники `.daq`, що зберігаються у форматі `captures/bursts/`. Після серії знімків з’являється кнопка**Створити відео**: вона переробляє серію знімків в автономному режимі у відкаліброване відео — з комбінованим індексом та/або показниками яскравості / відбиття / індексу для кожної камери — а також опціональні файли TIFF. Створення відео з комбінованим індексом запускається автоматично після зупинки серії знімків. |

## Процес

<!-- SCREENSHOT-NEEDED: the sidebar during a capture — Capture All showing live "Capturing… 3/6" progress text, and (second capture) the result flash "Saved N files". -->

«Записати все»

Натисніть **«Записати все»** у списку камер на бічній панелі:

1. Кожна включена, видима та не призупинена камера здійснює зйомку з вибраними типами експорту. **Масиви спрацьовують як один синхронізований тригер** (єдина синхронізована група для всіх членів — див. [Багатокамерні масиви](arrays.md)); автономні камери здійснюють зйомку індивідуально.
2. Приховані (око) або призупинені камери пропускаються. Масив повністю блокується лише тоді, коли *всі* його члени приховані або призупинені.
3. Щоразу, коли призначається датчик освітленості, відповідне значення DAQ щодо інтенсивності світла, що падає, зберігається як файл `.daq` у папці `daq/` знімків — навіть для знімків лише у форматі RAW — щоб пізніше завжди можна було отримати радіометричні продукти.
4. Кнопка відображає хід процесу в реальному часі — «Запис… завершено/загалом» — а в режимі «Безперервний/Інтервальний» перетворюється на **«Стоп (N)»**. Кожен елемент запису має тайм-аут 300 с.
5. Після завершення проходу у вікні результатів з’являється повідомлення **«Збережено N файлів»**або**«Збережено N, F не вдалося»**, а також «(S приховано/призупинено/пропущено)», якщо камери було пропущено. Якщо диск заповнюється, процес зупиняється і з’являється повідомлення**«Зупинено: диск заповнений. Збережено N, F не вдалося»** — кожен файл, який не вдалося записати, вважається невдалим.

## Де зберігаються записи

Записи зберігаються у відкритому проєкті за адресою `<project>/captures/`. Кожен тип експорту розміщується у **власній підпапці**, тому в багаторівневому записі типи ніколи не змішуються:

```
<project>/captures/
├── raw/           capture_<ts>_SN<serial>_raw.tif
├── debayered/     capture_<ts>_SN<serial>_debayered.tif
├── radiance/      capture_<ts>_SN<serial>_radiance.tif
├── reflectance/   capture_<ts>_SN<serial>_reflectance.tif
├── preview/       capture_<ts>_SN<serial>_display.tif
├── index/         per-camera vegetation-index (LUT) render, when Index is selected
├── composite/     array foreground/background live-view composite, when produced
├── clamp_masks/   radiance/…_clampmask.tif, reflectance/…, index/… — unmix clamp masks,
│                  one subfolder per product folder, only when a band was clamped
├── bursts/        raw-burst recordings (frames + manifest + .daq per burst)
└── daq/           the downwelling reading(s) matched to each capture (.daq), each with a
                   .daq.cameras.json naming the cameras it describes
```

* `<ts>` — це мітка часу знімка, а `<serial>` — серійний номер камери. Окремі знімки мають назву `capture_<ts>_SN<serial>_<level>`; знімки масиву, отримані за одним синхронізованим тригером, мають назву `sync_<ts>_SN<serial>_<level>` і **мають один і той самий час зйомки для всіх камер у групі** (суфікс рівня опускається, коли камера зберігає лише один рівень).
* **Одна особливість, про яку варто знати:** рівень відображення зберігається у папці з назвою `preview/`, тоді як файли зберігають у назві `_display` — папка та суфікс відрізняються лише для цього рівня.
* Невідомі рівні зберігаються у папці з їхнім власним іменем; якщо підпапку неможливо створити, файл записується в кореневу папку знімків, а не втрачається.
* Знімки у форматі TIFF за замовчуванням стискаються без втрат (DEFLATE) і містять повні метадані калібрування та обробки **всередині XMP-файлу** — знімки є самоописувальними, без додаткових файлів, окрім запису `.daq` (та його `.daq.cameras.json`).
* **Маски обмеження (нова функція у версії 1.3.0).**У випадках, коли спектральне розкладання 3×3 змушувало обмежувати значення смуги до 0 принаймні на одному пікселі, для величин яскравості, відбиття та індексу створюється маска для кожного пікселя, `clamp_masks/<product folder>/<product name>_clampmask.tif` (біт 0 = смуга в каналі R продукту, біт 1 = G, біт 2 = B); тег XMP продукту `Chloros:UnmixClampMask` вказує на неї. Маски розміщуються**поруч** із папками продуктів, ніколи всередині них, тому папку продукту, наприклад `reflectance/`, можна передавати до програмного забезпечення для фотограмметрії у тому вигляді, в якому вона є. Власний імпорт Chloros пропускає маски.
* **Орієнтація (1.3.0).** Продукти «Preview», «Radiance», «Reflectance» та «Index» автономної камери обертаються відповідно до налаштування «Mirror/Rotation»; файли «Raw» та «Debayered» залишаються такими, якими їх зчитав сенсор. Усі файли-елементи масиву залишаються у вихідному форматі. Кожен файл записує ці налаштування у своєму XMP, тому під час повторної обробки вони застосовуються так само.
* **До якої камери належить файл `.daq` (1.3.0).** Під час обробки `.daq` знімка зіставляється лише з зображеннями з камер, зазначених у її `.daq.cameras.json`. Тому автономна камера, яка не має власного датчика освітленості, більше не використовує показання іншої камери — підключіть до неї датчик або вкажіть його на вкладці «Датчики освітленості». Запис датчика освітленості (а також будь-який `.daq` без цього файлу, включаючи старі записи) як і раніше обслуговує кожну камеру.

Це той самий макет, який `chloros-cli lattice capture` / `array-capture` записують у свій каталог `-o` — описано в [Довідка по CLI, § Як виглядає папка знімків](../reference/cli-reference.md#what-a-captures-folder-looks-like).

## Повторна обробка знімків у калібровані продукти

Зняті необроблені кадри та збережений файл `.daq` — це все, що потрібно для конвеєра обробки; саме тому режим «Fastest Capture» безпечний для реальної роботи.

* **GUI**: додайте папку з знімками до проєкту ([Додавання файлів до проєкту](../processing-images-gui/adding-files-to-a-project.md)) і обробіть як зазвичай.
* **Інтерфейс CLI**: вкажіть `process` на **кореневу папку знімків**:

```bash
chloros-cli process "C:/ChlorosProjects/MyField/captures"
```

`process` зазвичай імпортує лише вказану вами папку, але якщо ця папка не містить зображень і має підпапки, програма автоматично переходить до них — таким чином підпапки рівня та папка `daq/` імпортуються за один раз. Кожне захоплення імпортується як **одне зображення**, до якого інші рівні додаються як режими перегляду, а не як окреме зображення для кожного рівня.

Пряме вказання імені підпапки рівня (наприклад, `…/captures/raw/`) також працює, але при цьому папка `daq/` залишається поза увагою — скопіюйте її разом із папкою, коли ви-отримуєте радіометричний продукт із `raw/`, інакше збіг за часовим штампом не матиме з чим зіставитися.

{% hint style="warning" %}
**Обробка завжди починається з `raw`.** У межах кожного знімка вихідним джерелом для конвеєра є необроблений кадр; `debayered`, `radiance`, `reflectance`, а `preview` з’являються як режими перегляду, але ніколи не повертаються назад у конвеєр — повторна обробка похідного продукту призвела б до повторного застосування віньєтування, кольору та математичних обчислень яскравості, вже вбудованих у його пікселі, тому Chloros відмовляється від цього, замість того щоб проводити подвійну обробку. Рендери `index/` та `composite/` взагалі не обробляються (вони є вихідними даними, а не знімками). Папка «captures», збережена **без** імпорту необроблених даних, відображається нормально, але `process` пропускає її та повідомляє про це; `--input-level {raw,debayered,processed}` — це навмисний «запасний вихід», що примусово створює точку входу. Точні повідомлення про пропуск дивіться у [Довіднику CLI](../reference/cli-reference.md#what-a-captures-folder-looks-like).
{% endhint %}

Ще дві особливості, про які варто знати під час написання скриптів для повторної обробки:

* Виконання `chloros-cli process`, яке запитувало продукти, але **не записало жодних зображень**, завершується з гучною помилкою та виходить із ненульовим кодом** — ви ніколи не отримаєте тихого порожнього запуску. Успішні запуски повідомляють про кількість отриманих продуктів. (Навмисний запуск, що створює лише метадані, все одно вважається успішним.)
* Повторно імпортовані оброблені експортовані дані ніколи не займають слот необроблених даних знімка — оригінальні необроблені дані завжди залишаються джерелом конвеєра.

## Еквіваленти CLI



Усе, що описано на цій сторінці, можна керувати в режимі без графічного інтерфейсу. Режими зйомки в графічному інтерфейсі безпосередньо відповідають `chloros-cli lattice array-capture`:

| GUI | CLI |
| --- | --- |
| Одноразовий | `chloros-cli lattice array-capture` |
| Безперервний | `array-capture --continuous [--count N] [--duration S]` |
| Інтервальний | `array-capture --interval S [--duration S]` |
| Найшвидший запис | `array-capture --fastest` |
| Позначка «Вирівняти» | `--aligned / --no-aligned` |
| Поля вибору типу експорту | `--processing LEVEL` або `--levels L1,L2,…` (за замовчуванням `all`) |
| Запис індексного відео | `chloros-cli lattice array-record` |
| Запис необробленої серії кадрів / Створення відео | `chloros-cli lattice array-burst` / `array-build-video` |

Повні таблиці прапорців, опція зйомки зі стабілізованою експозицією Smart-AE (`--smart`) та модель з постійною швидкістю описані в розділі [Довідка по CLI, § Режими зйомки, записуючі пристрої та офлайн-переробка](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess).
