# Налаштування та режими зйомки

Зйомка на вкладці «Камери» здійснюється за допомогою однієї червоної кнопки **«Зняти все»**та однієї панелі**«Налаштування зйомки»**, яка визначає, що саме буде зроблено при натисканні цієї кнопки: які камери братимуть участь, які типи файлів кожна камера зберігатиме, а також чи спрацьовуватиме затвор один раз, у безперервному режимі чи з певним інтервалом. На цій сторінці описано весь процес — налаштування, саму зйомку, місце збереження файлів на диску та подальшу переробку їх у відкалібровані продукти. Елементи керування камерами та масивами знаходяться на сторінці [Налаштування камер](camera-settings.md).

{% hint style="info" %}
**Для зйомки потрібно відкрити проєкт.** Кнопка «Зняти все» та значок налаштувань зйомки у вигляді шестерні будуть неактивними, доки не буде відкрито проєкт («Створіть або відкрийте проєкт, щоб зберегти знімки»). Кожен знімок зберігається у папці проєкту в `captures/`.
{% endhint %}

## Панель «Налаштування зйомки»

Відкрийте її за допомогою **значка шестерні поруч із «Зняти все»**у списку камер на бічній панелі або за допомогою кнопки**«Відкрити налаштування зйомки…»** у нижній частині будь-якої панелі налаштувань окремої камери. У заголовку вказано «Налаштування зйомки» із кнопкою повернення ←.

Ваші налаштування тут — включені камери, прапорці за типами та режим зйомки — зберігаються **для кожного проекту** і відновлюються при його повторному відкритті.

### Режими зйомки

Три кнопки режимів у верхній частині панелі:

| Режим | Що робить | Додаткові налаштування (за замовчуванням) |
| --- | --- | --- |
| **Одноразовий** *(за замовчуванням)* | Один знімок з кожної вибраної камери. | — |
| **Безперервний**| Послідовні зйомки до настання умови зупинки. | Зупинка за**Кількістю знімків** (за замовчуванням 1) *або* **Тривалістю зйомки** (за замовчуванням 10 с; одиниці виміру: секунди / хвилини / години / дні). |
| **Інтервал**(таймлапс) | Серія знімків за таймером. |**Кількість знімків / інтервал**(за замовчуванням 1) ·**Кожні**N одиниць (за замовчуванням 5 с) ·**Протягом** N одиниць (за замовчуванням 1 хв). |

У режимі «Безперервний» або «Інтервал» кнопка «Зняти все» під час роботи перетворюється на кнопку **«Зупинити (N)»**, підраховуючи кількість знімків у міру їх надходження.

### Вибір камер та типів експорту

Довідковий текст панелі підсумовує це так: виберіть, які камери та типи експорту використовує «Зняти все» — за замовчуванням увімкнено все, і вибір зберігається разом із цим проєктом.

* Кнопки **Вибрати все / Не вибирати нічого** одночасно змінюють стан прапорців включення для кожної камери.
* **Перемикачі типів масового експорту**(два ряди кнопок):**Усі RAW / Усі з дебейєрингом / Усі попередні перегляди / Усі Radiance / Усі відбиття / Усі індексні**. Кожен із них має три кольори: зелений ✓ = увімкнено для кожної камери, яка підтримує цей тип; жовтий – = увімкнено для деяких; сірий = жодна. Перемикач вимкнено, якщо жодна підключена камера не підтримує цей тип. Усі вони стають сірими, коли увімкнено «Найшвидше захоплення».
* **Рядки для кожної камери**: прапорець включення, а також розгортаний (▸/▾) список доступних для цієї камери типів експорту з окремими прапорцями. У рядку відображається кількість увімкнених опцій, наприклад «4/6».

### Типи експорту та камери, які їх підтримують

Існує шість типів експорту: **Raw, Debayered, Radiance, Reflectance, Preview, Index**. У рядку кожної камери відображаються лише ті типи, які для неї доступні:

| Тип експорту | Вміст | RGB (FRGB) | Мультиспектральний Bayer (FRGN/FOCN/FNGB) | Моно (M3M) |
| --- | --- | --- | --- | --- |
| **Raw** | Мозаїка Байєра (монохромний: одна смуга) безпосередньо з сенсора | ✓ | ✓ | ✓ |
| **Debayered** | Лінійне демозаїкування (монохромний: 1-канальна шкала сірих) | ✓ | ✓ | ✓ |
| **Попередній перегляд** | Повний ланцюг обробки зображення (баланс білого + гамма згідно з профілем камери; мультиспектральний: розтягнення у штучних кольорах) | ✓ | ✓ | ✓ |
| **Радіанс** | float32 Вт/м²/sr/нм через повний радіометричний ланцюг | — (не передбачено) | ✓ | ✓ |
| **Відбивна здатність** | uint16 ρ (32768 = 1,0) | — (не підтримується) | ✓ — відображається лише тоді, коли камера має світловий датчик DAQ (власний або успадкований від масиву) | так само, як і для мультиспектральних даних |
| **Індекс** | Відтворення індексу рослинності (LUT) | — | ✓ — вимагає увімкненого, непорожнього виразу індексу на камері та не доступний для членів комбінованого масиву (масив має один спільний індекс) | — (індекс потребує ≥2 діапазонів; див. [Монокамери та індекси рослинності](mono-indices.md)) |

Радіанс та відбивна здатність ніколи не доступні для камер RGB — радіанс за пікселем Байєра не має сенсу для широкосмугового фотометричного датчика.

### Найшвидше знімання

Перемикач **⚡ Найшвидше захоплення — тільки RAW**(помаранчевий у включеному стані) замінює всі налаштування експорту на**тільки RAW** — плюс безкоштовну композицію з комбінованим індексом для масивів — завдяки чому кадр зберігається якомога швидше: обчислення яскравості/відбиття/відображення повністю пропускаються під час захоплення.

{% hint style="info" %}
**Кадр у форматі `.daq` все одно зберігається.** Коли призначено датчик освітленості, функція «Найшвидше захоплення» все одно записує показання DAQ щодо інтенсивного випромінювання поруч із кадрами у форматі RAW — тож продукти, пов’язані з інтенсивністю випромінювання, відбивною здатністю та індексом, можна створити пізніше шляхом повторної обробки (див. [Повторна обробка знімків](#re-processing-captures-into-calibrated-products)). Fastest Capture також не впливає на ваші налаштування у вигляді прапорців: вимкніть цю функцію, і вони відновляться.
{% endhint %}

### Елементи керування для кожного масиву

Кожен підключений масив має власну групову картку у панелі:

* **Поле «Включити»** (три стани для всіх елементів) та назва масиву з режимом відображення: «(об’єднаний | окремий)».
* Позначка **Вирівняти**(за замовчуванням**увімкнено**): викривлення експортованих даних елементів відповідно до профілю вирівнювання масиву, завдяки чому експортовані дані зареєстровані за пікселями між камерами. Сирі дані залишаються невикривленими, але містять трансформацію у своїх метаданих. (Сам профіль обчислюється у [панелі налаштувань масиву](camera-settings.md#alignment-co-registration-combined-only).)
* Рядки камер-елементів вкладені всередину картки.

Картка масиву також містить два реєстратори. Уявіть їх як **моніторинг проти аналізу**:

| Реєстратор | Рівень | Що він записує |
| --- | --- | --- |
| **● Запис індексного відео / ■ Зупинка запису** *(лише для комбінованих масивів)* | **Моніторинг** | Композитне відео з комбінованим індексом у реальному часі зі швидкістю 10 кадрів на секунду — 8-бітне, роздільна здатність попереднього перегляду, вбудована LUT. Потрібен відкритий проєкт та потокове перегляд у реальному часі. Під час запису відображаються кадри та час, що минув. |
| **⦿ Запис необробленої серії кадрів / ■ Зупинити запис необробленої серії кадрів** *(будь-яка матриця)* | **Аналіз**| Необроблені кадри у форматі Bayer із частотою зчитування в режимі реального часу (без обробки) разом із маніфестом для кожного кадру та показниками `.daq`, що зберігаються у форматі `captures/bursts/`. Після завершення серії з’являється кнопка**Створити відео**: вона переобробляє серію знімків в автономному режимі у каліброване відео — з комбінованим індексом та/або показниками яскравості / відбиття / індексу для кожної камери окремо — а також опціональні файли TIFF. Створення відео з комбінованим індексом запускається автоматично після зупинки серійної зйомки. |##

Процес

<!-- SCREENSHOT-NEEDED: the sidebar during a capture — Capture All showing live "Capturing… 3/6" progress text, and (second capture) the result flash "Saved N files". -->

«Записати все» Натисніть **«Записати все»** у списку камер на бічній панелі:

1. Кожна включена, видима, не призупинена камера здійснює зйомку з вибраними типами експорту. **Масиви спрацьовують як один синхронізований тригер** (єдина синхронізована група для всіх членів — див. [Багатокамерні масиви](arrays.md)); автономні камери знімають індивідуально.
2. Приховані (око) або призупинені камери пропускаються. Масив повністю блокується лише тоді, коли *всі* його члени приховані або призупинені.
3. Щоразу, коли призначається датчик освітленості, відповідне значення DAQ щодо інтенсивності світла, що падає, зберігається у вигляді файлу `.daq` разом із зображеннями — навіть для знімків лише у форматі RAW — щоб пізніше завжди можна було отримати радіометричні продукти.
4. Кнопка відображає хід процесу в реальному часі — «Зйомка… завершено/загалом» — а в режимі «Безперервний/Інтервальний» стає **«Стоп (N)»**. Кожен елемент зйомки має тайм-аут 300 с.
5. Після завершення проходу у вікні результатів з’являється повідомлення **«Збережено N файлів»**або**«Збережено N, F не вдалося»**, а також «(S приховано/призупинено/пропущено)», якщо камери було пропущено.

## Де зберігаються зняті дані

Зняті дані зберігаються у відкритому проєкті за адресою `<project>/captures/`. Кожен тип експорту зберігається у **власній підпапці**, тому під час багаторівневого зняття типи ніколи не змішуються:

```
<project>/captures/
├── raw/           capture_<ts>_SN<serial>_raw.tif
├── debayered/     capture_<ts>_SN<serial>_debayered.tif
├── radiance/      capture_<ts>_SN<serial>_radiance.tif
├── reflectance/   capture_<ts>_SN<serial>_reflectance.tif
├── preview/       capture_<ts>_SN<serial>_display.tif
├── index/         per-camera vegetation-index (LUT) render, when Index is selected
├── composite/     array foreground/background live-view composite, when produced
├── bursts/        raw-burst recordings (frames + manifest + .daq per burst)
└── *.daq          the downwelling reading matched to the capture
```

* `<ts>` — це мітка часу зйомки, а `<serial>` — серійний номер камери. Окремі знімки мають імена у форматі `capture_<ts>_SN<serial>_<level>`; знімки масиву з одного синхронізованого тригера мають імена у форматі `sync_<ts>_SN<serial>_<level>` і **мають одну мітку часу для всіх камер у групі** (суфікс рівня опускається, коли камера зберігає лише один рівень).
* **Одна асиметрія, про яку варто знати:** рівень дисплея зберігається у папці з назвою `preview/`, тоді як файли зберігають у назві `_display` — папка та суфікс відрізняються лише для цього рівня.
* Невідомі рівні зберігаються у папці з їхнім власним іменем; якщо підпапку неможливо створити, файл записується до кореневого каталогу знімків, а не втрачається.
* TIFF-файли знімків за замовчуванням стискаються без втрат (DEFLATE) і містять повні метадані калібрування та обробки **всередині XMP-файлу** — знімки є самоописувальними, без додаткових файлів, окрім самого файлу `.daq`.

Це той самий формат, у якому `chloros-cli lattice capture` / `array-capture` записують дані у свій каталог `-o` — описано в [Довідка CLI § Як виглядає папка з знімками](../reference/cli-reference.md#what-a-captures-folder-looks-like).

## Повторна обробка знімків у калібровані продукти

Зняті необроблені кадри та збережений файл `.daq` — це все, що потрібно для конвеєра обробки; саме тому режим «Fastest Capture» безпечно використовувати для реальної роботи.

* **Графічний інтерфейс**: додайте папку із знімками до проєкту ([Додавання файлів до проєкту](../processing-images-gui/adding-files-to-a-project.md)) та обробіть їх як зазвичай.
* **CLI**: вкажіть `process` на**кореневу папку знімків**:

```bash
chloros-cli process "C:/ChlorosProjects/MyField/captures"
```

`process` зазвичай імпортує лише вказану вами папку, але якщо ця папка не містить зображень і має підпапки, він автоматично переходить до них — тому файли з підпапок цього рівня та кореневої папки `.daq` імпортуються за один раз. Кожен знімок імпортується як **єдине зображення**, до якого інші рівні додаються як режими перегляду, а не як окреме зображення для кожного рівня.

Пряме вказання імені підпапки рівня (наприклад, `…/captures/raw/`) також працює, але при цьому кореневі файли `.daq` залишаються поза увагою — скопіюйте їх разом із іншими, коли ви повторно створюєте радіометричний продукт із `raw/`, інакше збіг за часовим штампом не матиме з чим зіставитися.

{% hint style="warning" %}
**Обробка завжди починається з `raw`.**У межах кожного знімка вихідним джерелом для конвеєра є необроблений кадр; `debayered`, `radiance`, `reflectance` та `preview` є режимами перегляду, але ніколи не повертаються назад у конвеєр — повторна обробка похідного продукту призвела б до повторного застосування віньєтування, кольору та математичних обчислень яскравості, вже вбудованих у його пікселі, тому Chloros відхиляється, а не піддається подвійній обробці. Рендери `index/` та `composite/` взагалі не обробляються (це вихідні дані, а не знімки). Папка «captures», збережена**без** імпорту RAW-файлів, відображається нормально, але `process` пропускає її та повідомляє про це; `--input-level {raw,debayered,processed}` — це навмисний «запасний вихід», який примусово створює точку входу. Дивіться [Довідку щодо CLI](../reference/cli-reference.md#what-a-captures-folder-looks-like) для точних повідомлень про пропуск.
{% endhint %}

Ще дві особливості поведінки, про які варто знати під час написання скриптів для повторної обробки:

* Виконання `chloros-cli process`, яке запитувало продукти, але **не записало жодних зображень**, завершується з гучною помилкою та виходить із ненульовим кодом** — ви ніколи не отримаєте тихого порожнього виконання. Успішні виконання повідомляють про кількість отриманих продуктів. (Навмисне виконання, що стосується лише метаданих, все одно вважається успішним.)
* Повторно імпортовані оброблені експортовані дані ніколи не займають слот необроблених даних знімка — оригінальні необроблені дані завжди залишаються джерелом конвеєра.

## Еквіваленти CLI

Усе на цій сторінці можна керувати в режимі без графічного інтерфейсу. Режими збору даних у графічному інтерфейсі безпосередньо відповідають `chloros-cli lattice array-capture`:

| GUI | CLI |
| --- | --- |
| Одноразовий | `chloros-cli lattice array-capture` |
| Безперервний | `array-capture --continuous [--count N] [--duration S]` |
| Інтервальний | `array-capture --interval S [--duration S]` |
| Найшвидше захоплення | `array-capture --fastest` |
| Вирівнювання прапорців | `--aligned / --no-aligned` |
| Поля вибору типу експорту | `--processing LEVEL` або `--levels L1,L2,…` (за замовчуванням `all`) |
| Запис індексного відео | `chloros-cli lattice array-record` |
| Запис необробленої серії знімків / Створення відео | `chloros-cli lattice array-burst` / `array-build-video` |

Повні таблиці прапорців, опція зйомки зі стабілізованою експозицією Smart-AE (`--smart`) та модель з постійною швидкістю знаходяться в розділі [CLI Довідка § Режими зйомки, записуючі пристрої та офлайн-переробка](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess).
