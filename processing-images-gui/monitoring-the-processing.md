# Моніторинг обробки

Після початку обробки Chloros надає кілька способів відстежувати хід обробки, перевіряти наявність проблем та розуміти, що відбувається з вашим набором даних. На цій сторінці пояснюється, як відстежувати хід обробки та інтерпретувати інформацію, яку надає Chloros.

## Огляд індикатора прогресу

Індикатор прогресу у верхньому заголовку показує стан обробки в режимі реального часу та відсоток завершення. Інформація про прогрес надходить у режимі реального часу з серверної частини через Server-Sent Events (SSE), тому індикатор відображає те, що насправді виконує конвеєр.

### Індикатор прогресу у безкоштовному режимі

Для користувачів без ліцензії Chloros+:

**2-етапне відображення прогресу:**

1.**Виявлення мішеней** — пошук калібрувальних мішеней на зображеннях
2. **Обробка** — застосування корекцій та експорт**Смуга прогресу показує:**

* Загальний відсоток виконання (0–100 %)
* Назву поточного етапу
* Просту горизонтальну візуалізацію у вигляді смуги

### Смуга прогресу Chloros+

Для користувачів із ліцензією Chloros+:

**4-етапне відображення прогресу:**

1.**Виявлення** — пошук калібрувальних мішеней
2. **Аналіз** — вивчення зображень та підготовка конвеєра обробки
3. **Калібрування** — застосування корекцій віньєтування та відбиття
4. **Експорт** — збереження оброблених файлів**Інтерактивні функції:*** **Наведіть курсор** на індикатор прогресу, щоб побачити розгорнуту панель із 4 етапами
* **Клацніть** на індикаторі прогресу, щоб зафіксувати розгорнуту панель
* **Клацніть ще раз**, щоб скасувати фіксацію та автоматично приховати панель при відведенні курсору
* Кожен етап показує індивідуальний прогрес (0–100 %)

{% hint style="info" %}
**Парність CLI**: під час виконання `chloros-cli process` ті самі чотири потоки повідомляють про стан «Виявлення», «Аналіз», «Processing», «Exporting», а `chloros-cli export-status` показує хід експорту потоку-4 у реальному часі з іншого терміналу. Див. [Довідку по CLI](../reference/cli-reference.md).
{% endhint %}

## Розуміння кожного етапу обробки

{% hint style="info" %}
**Архітектура конвеєра**: Ці 4 етапи графічного інтерфейсу відповідають [4-потоковому конвеєру обробки](../processing-architecture/processing-pipeline.md). У системах із прискоренням на GPU потік 3 (калібрування) використовує переваги [динамічної адаптації обчислень](../processing-architecture/dynamic-compute-adaptation.md), яка оптимізує обробку під ваше конкретне обладнання.
{% endhint %}

### Етап 1: Виявлення (виявлення об’єктів)

**Що відбувається:**

* Chloros сканує зображення, які ви позначили прапорцем «Ціль» (усі зображення, якщо жодне не позначено)
* Алгоритми комп’ютерного зору ідентифікують калібрувальні панелі
* З кожної панелі витягуються значення відбиття
* Записуються часові мітки цілей для правильного планування калібрування

**Тривалість:**

* З позначеними мішенями: 10–60 секунд
* Без позначених мішеней: 5–30+ хвилин (сканує всі зображення)

**Індикатор прогресу:**

* Виявлення: 0% → 100%
* Кількість просканованих зображень (враховуються лише ті зображення, які фактично проскановано)
* Кількість знайдених міток

**На що слід звернути увагу:**

* Процес має завершитися швидко, якщо мітки позначено правильно
* Якщо процес триває надто довго, можливо, мітки не позначено
* Перевірте журнал налагодження на наявність повідомлень «Мітка знайдена»

### Етап 2: Аналіз

**Що відбувається:**

* Зчитування метаданих EXIF зображень (часові мітки, налаштування експозиції)
* Визначення стратегії калібрування на основі часових міток цілей та доступних даних DAQ про нісперне випромінювання
* Організація черги обробки зображень
* Підготовка робочих процесів для паралельної обробки (лише Chloros+)

**Тривалість:** 5–30 секунд**Індикатор прогресу:**

* Аналіз: 0% → 100%
* Швидкий етап, зазвичай завершується швидко

**На що слід звернути увагу:**

* Прогрес повинен відбуватися рівномірно, без пауз
* Попередження про відсутні метадані з’являтимуться у журналі налагодження

### Етап 3: Калібрування

**Що відбувається:*** **Дебейеринг**: перетворення RAW-матриці за схемою Байєра у 3 канали (пропускається для монохромних модулів LATTICE, з відповідною приміткою)
* **Корекція віньєтування**: усунення затемнення по краях об’єктива
* **Калібрування відбивної здатності**: нормалізація за допомогою цільових значень та/або даних DAQ
* **Розрахунок індексів**: обчислення мультиспектральних індексів
* Обробка кожного зображення через повний конвеєр

**Тривалість:** Більша частина загального часу обробки (60–80 %)**Індикатор прогресу:**

* Калібрування: 0 % → 100 %
* Поточне зображення, що обробляється
* Оброблених зображень / Загальна кількість зображень

**Характеристики обробки:*** **Вільний режим**: Послідовна обробка одного зображення за раз
* **Режим Chloros+**: Запускає пул робочих процесів, що адаптується до апаратного забезпечення — 1–4 паралельних робочих процеси на системах із графічними процесорами (залежно від обсягу VRAM), один робочий процес на кожне фізичне ядро (мінус один) на системах, що використовують лише центральні процесори. Див. [Динамічна адаптація обчислень](../processing-architecture/dynamic-compute-adaptation.md)
* **Прискорення за допомогою GPU**: Значно прискорює цей етап**На що слід звернути увагу:**

* Стабільний прогрес у обробці зображень
* Перевірте журнал налагодження на наявність повідомлень про завершення обробки кожного зображення
* Попередження про проблеми з якістю зображення або калібруванням

### Етап 4: Експорт

**Що відбувається:**

* Запис оброблених зображень на диск у вибраному форматі по мірі їх завершення
* **LATTICE**: кожен кадр розгалужується на всі увімкнені продукти (без бейєрингу / попередній перегляд / радіанс / відбивна здатність)
* Експорт мультиспектральних індексних зображень із кольорами LUT
* Створення вихідної структури `<project>/<camera>/<format>/<Product>_Images/` — експортовані файли зберігають ім’я вихідного файлу; папка ідентифікує продукт

**Тривалість:** 10–20 % від загального часу обробки**Індикатор прогресу:**

* Експорт: 0% → 100%
* Запис файлів
* Формат експорту та місце призначення

**На що слід звернути увагу:**

* Попередження про недостатній простір на диску
* Помилки запису файлів
* Завершення всіх налаштованих операцій виводу

## Вкладка «Журнал налагодження»

Журнал налагодження містить детальну інформацію про хід обробки та будь-які виявлені проблеми. Повідомлення про запуск серверної частини також відображаються в консолі журналу, тому журнал містить повну історію подій, навіть якщо ви відкриєте його пізніше.

### Доступ до журналу налагодження

1. Натисніть піктограму **Журнал налагодження**<img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

на лівій бічній панелі
2. Відкриється панель журналу, на якій відображаються повідомлення про обробку в режимі реального часу
3. Панель автоматично прокручується, щоб показати найновіші повідомлення

<!-- SCREENSHOT-NEEDED: Debug Log tab open at the end of a completed run, showing real backend log lines including the [RUN-SUMMARY] lines (images / camera groups / targets / calibrated / files written) -->

### Розуміння повідомлень журналу

Рядки журналу формату Chloros мають префікс у вигляді тегів у дужках, що позначають підсистему — наприклад, `[PROCESSING]`, `[RUN-SUMMARY]`, `[LATTICE-EXPORT]`, `[EXPORT-CHECK]`, `[IMPORT-LEVEL]`. Найважливішим для ознайомлення є **підсумок запуску**, що виводиться в кінці кожного запуску (включно з зупиненими запусками):

```
[RUN-SUMMARY] 49 image(s) in 2 camera group(s); 4 target(s) detected; 45 image(s) calibrated; 180 file(s) written.
```

Додаткові рядки підказок `[RUN-SUMMARY]` з’являються, коли щось потребує пояснення — наприклад, запуск, який не дав жодних результатів, або камера, запитуваний продукт якої було пропущено як невідповідний. Рядки `[EXPORT-CHECK]` пояснюють пропуски для кожної камери (наприклад, чому камера RGB не отримала продукт випромінювання).

Загальні рівні серйозності повідомлень (наведені нижче приклади є ілюстративними, а не дослівними):

#### Інформаційні повідомлення (білі/сірі)

Звичайні оновлення щодо обробки: початок обробки, виявлення цілей (із кількістю панелей), хід калібрування для кожного зображення, експортовані файли, завершення обробки.

#### Попереджувальні повідомлення (жовті)

Некритичні проблеми, які не зупиняють обробку — наприклад, відсутність даних GPS у кадрі, великий проміжок часу між знімками цілей або низький контраст на калібрувальній панелі.

**Дії:** Переглянути попередження після завершення обробки, але не переривати її

#### Повідомлення про помилки (Red)

Критичні проблеми, які можуть призвести до збою обробки — наприклад, диск переповнений, пошкоджений файл зображення або відсутність виявлених цілей під час калібрування відбиття.

**Дії:** Припиніть обробку, усуньте помилку, перезапустіть

### Типові ситуації, що фіксуються в журналі

| Ситуація                             | Значення                                       | Необхідні дії                                         |
| ------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| Ціль виявлено у \[ім’я файлу]        | Ціль калібрування знайдено успішно         | Нічого — нормально                                         |
| Смуги прогресу для кожного зображення              | Оновлення поточного прогресу                       | Нічого — нормально                                         |
| Цілі не знайдено                      | Не виявлено цілей калібрування               | Позначте зображення цілей або вимкніть калібрування відбиття |
| Недостатньо місця на диску               | Недостатньо місця для збереження результатів                 | Звільніть місце на диску                                    |
| Пропускається пошкоджений файл               | Файл зображення пошкоджено                         | Скопіюйте файл знову з SD-карти                             |
| `[IMPORT-LEVEL] Skipping ... no raw source` | Знімок без необробленого кадру не може бути оброблений | Зробіть знімок знову з необробленим кадром або скористайтеся CLI `--input-level`  |
| `[RUN-SUMMARY] ... 0 file(s) written` | У результаті виконання не було створено жодних зображень — повідомлено про збій із підказками | Прочитайте рядки з підказками; перевірте, що було пропущено та чому |

### Копіювання даних журналу

Щоб скопіювати журнал для усунення несправностей або звернення до служби підтримки:

1. Відкрийте панель «Журнал налагодження»
2. Натисніть кнопку **«Копіювати журнал»** (або клацніть правою кнопкою миші → «Виділити все»)
3. Вставте вміст у текстовий файл або електронний лист
4. За необхідності надішліть до служби підтримки MAPIR

## Моніторинг системних ресурсів

### Використання процесора

**Вільний режим:**

* 1 ядро процесора працює на рівні ~100%
* Інші ядра перебувають у режимі очікування або вільні
* Система продовжує реагувати на запити

**Паралельний режим Chloros+:**

* Кілька ядер працюють з високим навантаженням — їхня кількість залежить від стратегії, обраної за допомогою [Динамічної адаптації обчислювальних потужностей](../processing-architecture/dynamic-compute-adaptation.md)
* Система може здаватися менш чутливою

**Для моніторингу:**

* Windows Диспетчер завдань (Ctrl+Shift+Esc)
* Вкладка «Продуктивність» → розділ «Процесор»
* Знайдіть процеси «Chloros» або «chloros-backend»

### Використання пам’яті (RAM)

**Типове використання:**

* Невеликі проєкти (&lt; 100 зображень): 2–4 ГБ
* Середні проєкти (100–500 зображень): 4–8 ГБ
* Великі проєкти (500+ зображень): 8–16 ГБ
* Паралельний режим Chloros+ використовує більше оперативної пам’яті

**Якщо пам’яті недостатньо:**

* Обробляйте менші партії
* Закрийте інші програми
* Збільште обсяг оперативної пам’яті, якщо регулярно обробляєте великі набори даних

### Використання графічного процесора (Chloros+ з CUDA)

Коли увімкнено прискорення на графічному процесорі:

* Графічний процесор NVIDIA демонструє високий рівень завантаження (60–90 %)
* Використання відеопам’яті (VRAM) зростає (потрібно 4 ГБ+ відеопам’яті; 7 ГБ+ для одночасного дебейерінгу з урахуванням текстур)
* Етап калібрування відбувається значно швидше

**Для моніторингу:**

* Іконка NVIDIA в системному треї
* Диспетчер завдань → Продуктивність → Графічний процесор
* GPU-Z або подібний інструмент моніторингу

### Введення-виведення з диска

**Чого слід очікувати:**

* Висока інтенсивність читання з диска на етапі аналізу
* Висока інтенсивність запису на диск на етапі експорту
* SSD працює значно швидше, ніж HDD

**Порада щодо продуктивності:**

* За можливості використовуйте SSD для папки проєкту
* Уникайте використання мережевих дисків для великих наборів даних
* Переконайтеся, що диск не майже заповнений (це впливає на швидкість запису)

## Виявлення проблем під час обробки

### Ознаки, що викликають занепокоєння

**Прогрес зупинився (відсутність змін протягом 5 і більше хвилин):**

* Перевірте журнал налагодження на наявність помилок
* Перевірте наявність вільного місця на диску
* Перевірте в «Диспетчері завдань», чи запущено процес Chloros

**Часто з’являються повідомлення про помилки:**

* Припиніть обробку та перегляньте помилки
* Типові причини: недостатньо місця на диску, пошкоджені файли, проблеми з пам’яттю
* Див. розділ «Усунення несправностей» нижче

**Система не реагує на дії користувача:**

* Паралельний режим роботи Chloros+ споживає занадто багато ресурсів
* Розгляньте можливість зменшення кількості одночасних завдань або оновлення апаратного забезпечення
* Вільний режим є менш ресурсоємним

### Коли слід зупинити обробку

Зупиніть обробку, якщо ви помітили:

* ❌ Помилки «Диск заповнений» або «Неможливо записати файл»
* ❌ Повторні помилки пошкодження файлів зображень
* ❌ Система повністю зависла (не реагує)
* ❌ Виявлено, що налаштування були встановлені неправильно
* ❌ Імпортовано неправильні зображення

**Як зупинити:**

1. Натисніть**кнопку «Зупинити»** (замість кнопки «Пуск») — достатньо одного разу
2. На смузі прогресу з’явиться напис «Зупинка...», поки завершується обробка поточного образу, після чого процес закінчиться у зупиненому стані
3. Вже експортовані продукти залишаються на диску; у журналі виводиться точний код `[RUN-SUMMARY]`, що вказує на те, що було завершено
4. Виправте проблеми та перезапустіть — процес почнеться з початку

## Усунення несправностей під час обробки

### Обробка відбувається дуже повільно

**Можливі причини:**

* Непозначені цільові зображення (сканування всіх зображень)
* Використання HDD замість SSD
* Недостатньо системних ресурсів
* Налаштовано занадто багато індексів
* Доступ до мережевого диска

**Рішення:**

1. Якщо процес щойно розпочався і перебуває на етапі виявлення: зупиніть його, позначте цілі, перезапустіть
2. На майбутнє: використовуйте SSD, зменшіть кількість індексів, оновлюйте апаратне забезпечення
3. Розгляньте можливість використання CLI для пакетної обробки великих наборів даних

### Попередження про «місце на диску»

**Рішення:**

1. Негайно звільніть місце на диску
2. Перемістіть проєкт на диск із більшим обсягом місця
3. Зменшіть кількість індексів для експорту
4. Вимкніть експорт продуктів LATTICE, які вам не потрібні (Налаштування проєкту → Обробка)
5. Використовуйте формат JPG замість TIFF (файли меншого розміру)

### Часті повідомлення про «Пошкоджені файли»

**Рішення:**

1. Перекопіюйте зображення з SD-картки, щоб переконатися в їх цілісності
2. Перевірте SD-картку на наявність помилок
3. Видаліть пошкоджені файли з проєкту
4. Продовжуйте обробку решти зображень

### Перегрів системи / обмеження продуктивності

**Рішення:**

1. Забезпечте належну вентиляцію
2. Очистіть вентиляційні отвори комп’ютера від пилу
3. Зменшіть навантаження на систему (використовуйте режим «Free» замість Chloros+)
4. Здійснюйте обробку в прохолодніші години доби

***

## Повідомлення про завершення обробки

Коли обробка завершиться:

* Смуга прогресу досягне 100%
* У журналі налагодження з’являються рядки `[RUN-SUMMARY]` із кінцевими підрахунками
* Кнопка «Пуск» знову стає активною
* Усі вихідні файли знаходяться у дереві вихідних файлів проекту для кожної камери: `<project>/<camera>/<format>/<Product>_Images/`

***

## Наступні кроки

Після завершення обробки:

1. **Перегляньте результати** — див. [Завершення обробки](finishing-the-processing.md)
2. **Перевірте папку вихідних файлів** — переконайтеся, що всі файли експортовано правильно
3. **Перегляньте журнал налагодження** — перевірте, чи немає попереджень або помилок
4. **Перегляньте оброблені зображення** — скористайтеся програмою перегляду зображень або зовнішнім програмним забезпеченням

Інформацію про перегляд та використання оброблених результатів див. у розділі [Завершення обробки](finishing-the-processing.md).
