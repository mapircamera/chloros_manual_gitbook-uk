# Моніторинг обробки

Після початку обробки Chloros пропонує кілька способів відстежувати хід роботи, перевіряти наявність проблем та розуміти, що відбувається з вашим набором даних. На цій сторінці пояснюється, як відстежувати хід обробки та інтерпретувати інформацію, яку надає Chloros.

## Огляд індикатора прогресу

Смуга прогресу у верхньому заголовку показує стан обробки в режимі реального часу та відсоток завершення. Інформація про прогрес передається в режимі реального часу з серверної частини через Server-Sent Events (SSE), тому смуга відображає те, що насправді робить конвеєр.

### Смуга прогресу у безкоштовному режимі

Для користувачів без ліцензії Chloros+:

**2-етапне відображення прогресу:**

1.**Виявлення цілей** — пошук калібрувальних цілей на зображеннях
2. **Обробка** — застосування корекцій та експорт**Смуга прогресу показує:**

* Загальний відсоток завершення (0–100 %)
* Назву поточного етапу
* Просту горизонтальну візуалізацію у вигляді смуги

### Смуга прогресу Chloros+

Для користувачів із ліцензією Chloros+:

**4-етапне відображення прогресу:**

1.**Виявлення** — пошук калібрувальних мішеней
2. **Аналіз** — вивчення зображень та підготовка конвеєра
3. **Калібрування** — застосування корекції віньєтування та відбиття
4. **Експорт** — збереження оброблених файлів

**Інтерактивні функції:**

* **Наведіть курсор** на індикатор прогресу, щоб побачити розгорнуту панель із 4 етапами
* **Клацніть** на індикаторі прогресу, щоб зафіксувати розгорнуту панель
* **Клацніть ще раз**, щоб розблокувати панель; вона автоматично сховається при відведенні курсору
* Кожен етап показує індивідуальний прогрес (0–100 %)

{% hint style="info" %}
**Параметри CLI**: під час виконання `chloros-cli process` ті самі чотири потоки відображаються як «Виявлення», «Аналіз», «Обробка», «Експорт», а `chloros-cli export-status` показує в режимі реального часу хід експорту потоку 4 з іншого терміналу. Див. [Довідник CLI](../reference/cli-reference.md).
{% endhint %}

## Розуміння кожного етапу обробки

{% hint style="info" %}
**Архітектура конвеєра**: Ці 4 етапи графічного інтерфейсу відповідають [4-потоковому конвеєру обробки](../processing-architecture/processing-pipeline.md). У системах із прискоренням на GPU потік 3 (калібрування) використовує переваги [динамічної адаптації обчислень](../processing-architecture/dynamic-compute-adaptation.md), яка оптимізує обробку під ваше конкретне апаратне забезпечення.
{% endhint %}

### Етап 1: Виявлення (виявлення цілей)

**Що відбувається:**

* Chloros сканує зображення, які ви позначили галочкою у полі «Ціль» (усі зображення, якщо жодне не позначено)
* Алгоритми комп’ютерного зору ідентифікують калібрувальні панелі
* З кожної панелі витягуються значення відбиття
* Записуються часові мітки цілей для правильного планування калібрування

**Тривалість:**

* З позначеними цілями: 10–60 секунд
* Без позначених цілей: 5–30+ хвилин (сканує всі зображення)

**Індикатор прогресу:**

* Виявлення: 0% → 100%
* Кількість просканованих зображень (враховуються лише ті зображення, які фактично проскановано)
* Кількість знайдених мішеней

**На що слід звернути увагу:**

* Процес має завершитися швидко, якщо мішені правильно позначені
* Якщо процес триває надто довго, можливо, мішені не позначені
* Перевірте журнал налагодження на наявність повідомлень «Мішень знайдено»

### Етап 2: Аналіз

**Що відбувається:**

* Зчитування метаданих EXIF зображень (часові мітки, налаштування експозиції)
* Визначення стратегії калібрування на основі часових міток цілей та доступних даних DAQ, що надходять
* Організація черги обробки зображень
* Підготовка робочих процесів для паралельної обробки (лише Chloros+)

**Тривалість:** 5–30 секунд**Індикатор прогресу:**

* Аналізується: 0% → 100%
* Швидкий етап, зазвичай завершується швидко

**На що слід звернути увагу:**

* Процес повинен протікати рівномірно, без пауз
* Попередження про відсутні метадані з’являтимуться у журналі налагодження (Debug Log)

### Етап 3: Калібрування

**Що відбувається:**

* **Дебейеринг**: перетворення RAW-матриці Байєра у 3 канали (пропускається для монохромних модулів LATTICE, з відповідною приміткою)
* **Корекція віньєтування**: усунення затемнення по краях об’єктива
* **Калібрування відбиття**: нормалізація за допомогою цільових значень та/або зниження рівня DAQ
* **Розрахунок індексів**: обчислення мультиспектральних індексів
* Обробка кожного зображення через повний конвеєр

**Тривалість:** Більша частина загального часу обробки (60–80 %)**Індикатор прогресу:**

* Калібрування: 0 % → 100 %
* Поточне зображення обробляється
* Оброблені зображення / Загальна кількість зображень

**Режими обробки:**

* **Вільний режим**: Послідовна обробка по одному зображенню за раз
* **Режим Chloros+**: Запуск пулу робочих процесів, що адаптується до апаратного забезпечення — 1–4 одночасних робочих процесів на системах із графічними процесорами (залежно від обсягу VRAM), один робочий процес на кожне фізичне ядро (мінус один) на системах, що використовують лише центральний процесор. Див. [Динамічна адаптація обчислень](../processing-architecture/dynamic-compute-adaptation.md)
* **Прискорення за допомогою GPU**: Значно прискорює цей етап**На що слід звернути увагу:**

* Стабільний прогрес у підрахунку зображень
* Перевірте журнал налагодження на наявність повідомлень про завершення обробки кожного зображення
* Попередження про проблеми з якістю зображень або калібруванням

### Етап 4: Експорт

**Що відбувається:**

* Запис оброблених зображень на диск у вибраному форматі по мірі їх завершення
* **LATTICE**: кожен кадр розгалужується на всі увімкнені продукти (без бейєрингу / попередній перегляд / радіанс / відбивна здатність)
* Експорт мультиспектральних індексних зображень із кольорами LUT
* Створення вихідної структури `<project>/<camera>/<format>/<Product>_Images/` — експортовані файли зберігають ім’я вихідного файлу; папка ідентифікує продукт

**Тривалість:** 10–20 % від загального часу обробки**Індикатор прогресу:**

* Експорт: 0 % → 100 %
* Запис файлів
* Формат експорту та місце призначення

**На що слід звернути увагу:**

* Попередження про брак місця на диску
* Помилки запису файлів
* Завершення всіх налаштованих операцій виведення

## Вкладка «Журнал налагодження»

Журнал налагодження містить детальну інформацію про хід обробки та будь-які проблеми, що виникли. Повідомлення про запуск серверної частини також відображаються в консолі журналу, тому журнал містить повну історію подій, навіть якщо ви відкриєте його пізніше.

### Доступ до журналу налагодження

1. Клацніть на піктограму **Журнал налагодження** <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

на лівій бічній панелі
2. Відкриється панель журналу, що відображає повідомлення про обробку в режимі реального часу
3. Панель автоматично прокручується, щоб показати найновіші повідомлення

<!-- SCREENSHOT-NEEDED: Debug Log tab open at the end of a completed run, showing real backend log lines including the [RUN-SUMMARY] lines (images / camera groups / targets / calibrated / files written), with the 1.3.0 bug icon (Report a bug) visible at the top of the tab -->

### Розуміння повідомлень журналу Рядки журналу

Chloros мають префікс у вигляді тегів у дужках, що позначають підсистему — наприклад, `[PROCESSING]`, `[RUN-SUMMARY]`, `[LATTICE-EXPORT]`, `[EXPORT-CHECK]`, `[IMPORT-LEVEL]`. Найважливішим для розуміння є **підсумок запуску**, що виводиться в кінці кожного запуску (включно з зупиненими запусками):

```
[RUN-SUMMARY] 49 image(s) in 2 camera group(s); 4 target(s) detected; 45 image(s) calibrated; 180 file(s) written.
```

Додаткові рядки підказок `[RUN-SUMMARY]` з’являються щоразу, коли щось потребує пояснення — наприклад, запуск, який не дав жодних результатів, або камера, запитуваний для якої результат було пропущено як непридатний. Рядки `[EXPORT-CHECK]` пояснюють пропуски для кожної камери (наприклад, чому камера RGB не отримала результат яскравості).

Загальні рівні серйозності повідомлень (наведені нижче приклади є ілюстративними, а не дослівними):

#### Інформаційні повідомлення (білі/сірі)

Звичайні оновлення обробки: початок обробки, виявлення цілей (із кількістю панелей), хід калібрування для кожного зображення, експортовані файли, завершення обробки.

#### Попереджувальні повідомлення (жовті)

Некритичні проблеми, які не зупиняють обробку — наприклад, відсутність даних GPS у кадрі, великий проміжок у часових мітках між зображеннями цілей або низький контраст у калібрувальній панелі.

**Дія:** Переглянути попередження після обробки, але не переривати її

#### Повідомлення про помилки (колір Red)

Критичні проблеми, які можуть призвести до збою обробки — наприклад, диск заповнений, пошкоджений файл зображення або відсутність виявлених цілей під час запиту на калібрування відбиття.

**Дії:** Припиніть обробку, усуньте помилку, перезапустіть

### Типові ситуації в журналі

| Ситуація                             | Значення                                       | Необхідні дії                                         |
| ------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| Об’єкт виявлено у \[ім’я файлу]        | Об’єкт калібрування знайдено успішно         | Немає — нормально                                         |
| Смуги прогресу для кожного зображення              | Оновлення поточного прогресу                       | Немає — нормально                                         |
| Мішеней не знайдено                      | Не виявлено мішеней калібрування               | Позначте зображення мішеней або вимкніть калібрування відбиття |
| Недостатньо місця на диску               | Недостатньо місця для збереження результатів                 | Звільніть місце на диску                                    |
| Пропускається пошкоджений файл               | Файл зображення пошкоджено                         | Скопіюйте файл знову з SD-картки                             |
| `[IMPORT-LEVEL] Skipping ... no raw source` | Знімок без RAW-кадру не може бути оброблений | Зробіть знімок знову з RAW-кадром, або скористайтеся CLI `--input-level`  |
| `[RUN-SUMMARY] ... 0 file(s) written` | Запуск не дав жодних зображень — повідомлено про збій із підказками | Прочитайте рядки з підказками; перевірте, що було пропущено та чому |
| `[PROCESS] refused: The project folder is too deep for this computer…` | Увімкнено довгі шляхи в Windows, а папка проєкту занадто глибока для обмеження довжини шляху в 260 символів; нічого не було оброблено | Використовуйте коротшу папку проєкту (у повідомленні вказано найдовший шлях, що вміщується), або увімкніть довгі шляхи в Windows та перезапустіть Chloros — див. [Запуск обробки](starting-the-processing.md#the-project-folder-is-too-deep-for-this-computer) |
| `[unmix-clamp-mask] …` | Не вдалося записати маску фіксації продукту LATTICE; сам продукт працює нормально і повідомляє `Chloros:UnmixClampMask=unavailable` | Перевірте вільний простір на диску та права доступу до папки, а потім повторіть обробку, якщо маска вам потрібна |

### Копіювання даних журналу

Щоб скопіювати журнал для усунення несправностей або звернення до служби підтримки:

1. Відкрийте панель «Журнал налагодження»
2. Натисніть кнопку **«Копіювати»**(скопіює журнал у буфер обміну) або**«Завантажити»**, щоб зберегти його як текстовий файл
3. Вставте вміст у текстовий файл або електронний лист
4. За необхідності надішліть його до служби підтримки MAPIR



### Повідомлення про помилку з вкладки «Журнал налагодження»

Нове у версії 1.3.0: піктограма помилки (**Повідомити про помилку**) у верхній частині вкладки «Журнал налагодження» надсилає звіт безпосередньо до MAPIR.

1. Натисніть піктограму помилки у верхній частині вкладки «Журнал налагодження»
2. Опишіть проблему: що ви робили, чого очікували та що сталося насправді (обов’язково)
3. За бажанням поставте галочку біля **Додати кілька зображень (до 10)**і виберіть зображення з відкритого проєкту або скористайтеся кнопкою**Огляд...** для будь-якого іншого файлу зображення
4. Натисніть **Надіслати**

Звіт містить ваш опис, усі додані зображення, журнали Chloros та відомості про систему (версія Chloros, ОС, графічний процесор та налаштування проєкту). Щоб надіслати звіт, ви повинні увійти в Chloros (вкладка «Користувач»). Ви можете закрити вікно під час надсилання; після завершення у журнал записується посилання, наприклад `Bug report sent. Reference: BR-…` — вкажіть його, коли звертатиметеся до MAPIR. Якщо звіт неможливо завантажити (наприклад, через відсутність підключення до Інтернету), Chloros збереже його на вашому комп’ютері та покаже шлях до файлу, щоб ви могли надіслати його електронною поштою на адресу support@mapir.camera.

## Моніторинг системних ресурсів

### Використання процесора

**Вільний режим:**

* 1 ядро процесора на рівні ~100%
* Інші ядра перебувають у режимі очікування або доступні
* Система залишається чутливою

**Паралельний режим Chloros+:**

* Кілька ядер працюють із високим навантаженням — їхня кількість залежить від стратегії, обраної за допомогою [Динамічної адаптації обчислювальних ресурсів](../processing-architecture/dynamic-compute-adaptation.md)
* Система може здаватися менш чутливою

**Для моніторингу:**

* Диспетчер завдань Windows (Ctrl+Shift+Esc)
* Вкладка «Продуктивність» → розділ «Процесор»
* Знайдіть процеси «Chloros» або «chloros-backend»

### Використання пам’яті (RAM)

**Типове використання:**

* Невеликі проєкти (< 100 зображень): 2–4 ГБ
* Середні проєкти (100–500 зображень): 4–8 ГБ
* Великі проєкти (500+ зображень): 8–16 ГБ
* Паралельний режим «Chloros+» використовує більше оперативної пам’яті

**Якщо пам’яті недостатньо:**

* Обробляйте менші партії
* Закрийте інші програми
* Збільште обсяг оперативної пам’яті, якщо регулярно обробляєте великі набори даних

### Використання графічного процесора (GPU) (Chloros+ з CUDA)

Коли увімкнено прискорення за допомогою графічного процесора:

* Графічний процесор NVIDIA демонструє високий рівень завантаження (60–90 %)
* Використання відеопам’яті (VRAM) зростає (потрібно 4 ГБ+ відеопам’яті; 7 ГБ+ для одночасного дебейерінгу з урахуванням текстур)
* Етап калібрування відбувається значно швидше

**Для моніторингу:**

* Іконка NVIDIA у системному лотку
* Диспетчер завдань → Продуктивність → Графічний процесор
* GPU-Z або подібний інструмент моніторингу

### Введення-виведення з диска

**Чого слід очікувати:**

* Висока інтенсивність читання з диска на етапі аналізу
* Висока інтенсивність запису на диск на етапі експорту
* SSD працює значно швидше, ніж HDD

**Порада щодо продуктивності:**

* За можливості використовуйте SSD для папки проєкту
* Уникайте мережевих дисків для великих наборів даних
* Переконайтеся, що диск не заповнений майже повністю (це впливає на швидкість запису)

## Виявлення проблем під час обробки

### Ознаки, що викликають занепокоєння

**Процес зупиняється (відсутність змін протягом 5+ хвилин):**

* Перевірте журнал налагодження на наявність помилок
* Перевірте наявність вільного місця на диску
* Перевірте в «Диспетчері завдань», чи працює Chloros **Часто з’являються повідомлення про помилки:**

* Припиніть обробку та перегляньте помилки
* Типові причини: брак місця на диску, пошкоджені файли, проблеми з пам’яттю
* Див. розділ «Усунення несправностей» нижче

**Система перестає реагувати:**

* Паралельний режим Chloros+ використовує занадто багато ресурсів
* Розгляньте можливість зменшення кількості одночасних завдань або оновлення апаратного забезпечення
* Вільний режим є менш ресурсоємним

### Коли слід зупинити обробку

Зупиніть обробку, якщо ви побачите:

* ❌ Помилки «Диск заповнений» або «Неможливо записати файл»
* ❌ Повторні помилки пошкодження файлів зображень
* ❌ Система повністю зависла (не реагує)
* ❌ Виявилося, що налаштування були встановлені неправильно
* ❌ Імпортовано неправильні зображення

**Як зупинити:**

1. Натисніть**кнопку «Зупинити»** (замість кнопки «Пуск») — достатньо одного разу
2. На смузі прогресу з’явиться напис «Зупинка...», поки завершується обробка поточного образу, після чого процес закінчиться у зупиненому стані
3. Вже експортовані продукти залишаються на диску; у журналі виводиться точний код `[RUN-SUMMARY]`, що вказує на те, що було завершено
4. Виправте проблеми та перезапустіть — процес почнеться з початку

## Усунення несправностей під час обробки

### Обробка відбувається дуже повільно

**Можливі причини:**

* Непозначені цільові зображення (сканування всіх зображень)
* Використання HDD замість SSD
* Недостатні системні ресурси
* Налаштовано занадто багато індексів
* Доступ до мережевого диска

**Рішення:**

1. Якщо процес щойно розпочався і перебуває на етапі виявлення: зупиніть його, позначте цілі, перезапустіть
2. На майбутнє: використовуйте SSD, зменшіть кількість індексів, модернізуйте апаратне забезпечення
3. Розгляньте можливість використання командного рядка (CLI) для пакетної обробки великих наборів даних

### Попередження про «місце на диску»

**Рішення:**

1. Негайно звільніть місце на диску
2. Перемістіть проєкт на диск із більшим обсягом місця
3. Зменшіть кількість індексів для експорту
4. Вимкніть експорт продуктів LATTICE, які вам не потрібні (Налаштування проєкту → Обробка)
5. Використовуйте формат JPG замість TIFF (файли меншого розміру)

### Часті повідомлення про «Пошкоджені файли»

**Рішення:**

1. Перекопіюйте зображення з SD-картки, щоб переконатися в їх цілісності
2. Перевірте SD-картку на наявність помилок
3. Видаліть пошкоджені файли з проєкту
4. Продовжуйте обробку решти зображень

### Перегрів системи / обмеження продуктивності

**Рішення:**

1. Забезпечте належну вентиляцію
2. Очистіть вентиляційні отвори комп’ютера від пилу
3. Зменшіть навантаження на систему (використовуйте режим «Free» замість «Chloros+»)
4. Виконуйте обробку в прохолодніші години доби

***

## Повідомлення про завершення обробки

Коли обробка завершиться:

* Смуга прогресу досягне 100%
* У журналі налагодження з’являються рядки `[RUN-SUMMARY]` із кінцевими підрахунками
* Кнопка «Пуск» знову стає активною
* Усі вихідні файли знаходяться у вихідній структурі проекту для кожної камери: `<project>/<camera>/<format>/<Product>_Images/`

## Наступні кроки

Після завершення обробки:

1. **Перегляньте результати** — див. [Завершення обробки](finishing-the-processing.md)
2. **Перевірте папку вихідних файлів** — переконайтеся, що всі файли експортовано правильно
3. **Перегляньте журнал налагодження** — перевірте, чи немає попереджень або помилок
4. **Перегляньте оброблені зображення** — скористайтеся програмою перегляду зображень або зовнішнім програмним забезпеченням

Інформацію про перегляд та використання оброблених результатів див. у розділі [Завершення обробки](finishing-the-processing.md).
