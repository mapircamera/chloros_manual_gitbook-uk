# Початок обробки

Після імпорту зображень, позначення калібрувальних міток та налаштування параметрів проєкту ви готові розпочати обробку. Ця сторінка містить інструкції щодо запуску конвеєра обробки Chloros.

## Контрольний список перед початком обробки

Перш ніж натиснути кнопку «Start», переконайтеся, що все готово:

* [ ] **Файли імпортовано** — усі зображення відображаються у файловому браузері
* [ ] **Зображення-мітки позначено** — у стовпці «Target» відмічено зображення для калібрування (або імпортований запис `.daq` для LATTICE)
* [ ] **Моделі камер виявлені** — у стовпці «Модель камери» вказано правильні камери
* [ ] **Налаштування налаштовані** — налаштування проєкту перевірено та скориговано
* [ ] **Вибрано індекси** — додано потрібні мультиспектральні індекси (за потреби)
* [ ] **Обрано формат експорту** — формат виводу, що відповідає вашому робочому процесу

{% hint style="info" %}
**Порада**: Перегляньте кілька зображень у браузері файлів, щоб переконатися, що вони завантажилися правильно, перед початком обробки.
{% endhint %}

***

## Початок обробки

### Знайдіть кнопку «Пуск»

Кнопка «Пуск/Відтворити» розташована у верхній панелі заголовка Chloros:

* Розташування: у верхній центральній частині вікна
* Піктограма: **Кнопка «Відтворити/Пуск»** <img src="../.gitbook/assets/image (2) (1) (1).png" alt="" data-size="line">
* Стан: кнопка активна (підсвічена), коли система готова до обробки

### Натисніть, щоб розпочати

1. Натисніть **кнопку «Відтворити/Почати»** у верхній панелі заголовка
2. Обробка розпочнеться негайно
3. Під час обробки кнопка перетворюється на кнопку **«Стоп»**

4. Смуга прогресу оновлюється, відображаючи стан обробки

{% hint style="success" %}
**Обробка розпочата**: Після натискання Chloros автоматично виконує всі етапи обробки — виявлення об’єктів, дебейерінг, калібрування, обчислення індексу та експорт. Програма автоматично визначає, чи є ваш проєкт Survey3, LATTICE чи їхнім поєднанням, і застосовує відповідний конвеєр обробки для кожної камери.
{% endhint %}

## Ознайомлення з режимами обробки

Chloros працює у двох різних режимах обробки залежно від вашої ліцензії:

### Безкоштовний режим (Послідовна обробка)

**Доступний для всіх користувачів**

**Як це працює:**

* Обробляє зображення по одному, послідовно
* Однопотокова робота
* Менше використання пам’яті

**Смуга прогресу показує 2 етапи:**

1.**Виявлення мішеней** — сканування для пошуку калібрувальних мішеней
2. **Обробка** — застосування калібрування та експорт зображень**Час обробки:**

* Значно повільніше, ніж у паралельному режимі Chloros+
* Підходить для малих та середніх наборів даних (&lt; 200 зображень)

### Режим Chloros+ (Паралельна обробка)

**Потрібна ліцензія Chloros+**

**Як це працює:**

* Одночасно обробляє кілька зображень за допомогою [4-потокового конвеєра обробки](../processing-architecture/processing-pipeline.md)
* [Динамічна адаптація обчислень](../processing-architecture/dynamic-compute-adaptation.md) автоматично обирає оптимальну стратегію для вашого обладнання на початку виконання
* Прискорення за допомогою GPU (CUDA) на графічних картах NVIDIA (настільних ПК та Jetson)
* **Кількість робочих процесів адаптується до апаратного забезпечення**: стратегії на GPU запускають**1–4 паралельних робочих процеси** (масштабується залежно від VRAM — Jetson з малим об’ємом пам’яті запускає 1, настільний GPU з 12 ГБ і більше запускає до 4); системи, що використовують лише CPU, запускають один робочий процес на кожне фізичне ядро, мінус один**Смуга прогресу показує 4 етапи** (що відповідають 4 потокам конвеєра):

1. **Виявлення** (потік 1) — пошук об’єктів калібрування
2. **Аналіз** (потік 2) — вивчення метаданих зображення та обчислення калібрування
3. **Калібрування** (потік 3) — дебейерінг, корекція віньєтування, калібрування, обчислення індексу
4. **Експорт** (потік 4) — збереження оброблених зображень та індексів**Взаємодія зі смугою прогресу:*** **Наведіть курсор миші** на індикатор, щоб побачити детальну 4-етапну випадаючу панель
* **Клацніть** по індикатору прогресу, щоб зафіксувати випадаючу панель на місці
* **Клацніть ще раз**, щоб розфіксувати та приховати панель**Час обробки:**

* Значно швидше, ніж у безкоштовному режимі
* Прискорення за допомогою графічного процесора (GPU) ще більше підвищує швидкість

{% hint style="info" %}
**Chloros+ Швидкість**: Паралельна обробка великих наборів даних може бути в 5–10 разів швидшою, ніж послідовний режим. Проект із 500 зображеннями, який у безкоштовному режимі займає 2 години, із Chloros+ може завершитися за 15–20 хвилин.
{% endhint %}

## Що відбувається під час обробки

### Етап 1: Виявлення цілей

**Що робить Chloros:**

* Сканує зображення, які ви позначили у стовпці «Ціль» (усі зображення, якщо жодне не позначено)
* Ідентифікує калібрувальні панелі в кожній мітці
* Витягує значення відбиття з панелей міток
* Записує часові мітки міток для планування калібрування

**Тривалість:** 1–30 секунд (з позначеними мітками), 5–30+ хвилин (без позначок)

### Етап 2: Дебейеринг (Конвертація RAW)

**Що робить Chloros:**

* Конвертує дані RAW у форматі Байєра у повноцінні 3-канальні зображення (монохромні модулі LATTICE залишаються односмуговими — для них дебайєринг пропускається з відповідною приміткою в журналі)
* Застосовує вибраний алгоритм демозаїкування
* Зберігає максимальну якість зображення та деталізацію

**Тривалість:** Залежить від кількості зображень та швидкості CPU/GPU

### Етап 3: Калібрування

**Що робить Chloros:*** **Корекція віньєтування**: усуває затемнення по краях об’єктива
* **Калібрування відбиття**: нормалізує за допомогою цільових значень відбиття та/або даних DAQ про інсоляцію
* Застосовує корекції до всіх діапазонів/каналів
* Використовує відповідний калібрувальний еталон для кожного зображення на основі часової мітки

**Тривалість:** Більша частина часу обробки

### Етап 4: Розрахунок індексів

**Що робить Chloros:**

* Обчислює налаштовані мультиспектральні індекси (NDVI, NDRE тощо)
* Застосовує математичні операції до каліброваних зображень
* Генерує індексні зображення для кожного вибраного індексу

**Тривалість:** Кілька секунд на одне зображення

### Етап 5: Експорт

**Що робить Chloros:**

* Зберігає оброблені зображення у вибраному форматі
* **Розгортка LATTICE**: кожен необроблений кадр LATTICE експортується як усі ввімкнені продукти за один прохід — з дебейєрингом, попереднім переглядом, радіансом (завжди float32), відбивною здатністю
* Записує файли у вихідну структуру проекту: `<project>/<camera>/<format>/<Product>_Images/`
* **Зберігає ім&#x27;я вихідного файлу** — папка ідентифікує продукт, суфікс не додається**Тривалість:** Залежить від формату експорту та розміру файлу***

## Характеристики обробки

### Автоматичний конвеєр обробки

Після запуску весь конвеєр працює автоматично:

* Втручання користувача не потрібне
* Усі налаштовані етапи виконуються послідовно
* Інформація про хід обробки відображається в режимі реального часу
* Експортовані файли записуються на диск по мірі їхнього завершення — ви можете відкривати готові результати, поки обробка триває

### Використання ресурсів комп’ютера під час обробки

**Вільний режим:**

* Відносно низьке завантаження процесора (однопотоковий режим)
* Комп’ютер залишається чутливим до інших завдань
* Можна безпечно згорнути вікно Chloros і працювати в інших програмах

**Chloros+ Паралельний режим:**

* Високе завантаження процесора у всьому пулі робочих процесів стратегії
* З прискоренням на графічному процесорі: високе завантаження графічного процесора
* Під час обробки комп’ютер може реагувати повільніше
* Уникайте запуску інших завдань, що інтенсивно задіюють процесор

{% hint style="warning" %}
**Порада щодо продуктивності**: Для досягнення найкращої продуктивності Chloros+ закрийте інші програми та дозвольте Chloros використовувати всі системні ресурси.
{% endhint %}

### Обробку неможливо призупинити (але зупинка відбувається коректно)

* Після запуску обробку неможливо призупинити та пізніше відновити
* Натискання кнопки **«Стоп»** коректно зупиняє виконання з першого натискання
* Продукти, експортовані до зупинки, залишаються на диску
* Зупинене виконання чесно повідомляє, що було завершено (див. рядки `[RUN-SUMMARY]` у журналі)
* Новий запуск запускає конвеєр з самого початку

**Порада щодо планування:** Для дуже великих проєктів розгляньте можливість обробки партіями або використання CLI для кращого контролю.***

## Моніторинг обробки

Під час виконання процесів обробки ви можете:

* **Спостерігати за індикатором прогресу** — переглядати загальний відсоток завершення
* **Переглядати поточний етап** — виявлення, аналіз, калібрування або експорт
* **Перевіряти вкладку журналу** — переглядати детальні повідомлення та попередження щодо обробки
* **Переглянути готові зображення** — файли для експорту з’являються на диску під час обробки

Детальну інформацію щодо моніторингу див. у розділі [Моніторинг обробки](monitoring-the-processing.md).

## Зупинка обробки

Якщо вам потрібно зупинити обробку:

### Як зупинити

1. Знайдіть **кнопку «Зупинити»** (під час обробки вона замінює кнопку «Пуск»)
2. Натисніть її один раз — на смузі з’явиться напис **«Зупиняється...»**, поки завершується обробка поточного зображення
3. Процес завершиться в остаточному стані зупинки, а в журналі з’явиться точний звіт `[RUN-SUMMARY]` про те, що було виконано

### Коли слід зупиняти

**Вагомі причини для зупинки:**

* Виявлено, що використовувалися неправильні налаштування
* Забули позначити цільові зображення
* Імпортовано неправильні зображення
* Система працює занадто повільно або не реагує

**Після зупинки:**

* Результати, експортовані до зупинки, залишаються на диску
* Перегляньте та виправте будь-які проблеми, скоригуйте налаштування за потреби
* Перезапустіть обробку — процес розпочнеться з початку

## Орієнтовний час обробки

Фактичний час обробки значно варіюється залежно від:

* Кількості зображень
* Роздільної здатності зображень
* Формату вхідних даних (RAW чи JPG)
* Режиму обробки (Free чи Chloros+)
* Швидкості процесора та кількості ядер
* Наявності графічного процесора (лише Chloros+)
* Кількості індексів, що підлягають обчисленню
* Кількості увімкнених продуктів експорту (LATTICE)

### Приблизні оцінки (Chloros+, зображення 12 МП, сучасний процесор)

| Кількість зображень | Режим «Безкоштовний» | Chloros+ (процесор) | Chloros+ (GPU) |
| ----------- | --------- | -------------- | -------------- |
| 50 зображень   | 15–20 хв | 5–8 хв        | 3–5 хв        |
| 100 зображень  | 30–40 хв | 10–15 хв      | 5–8 хв        |
| 200 зображень  | 1–1,5 год | 20–30 хв      | 10–15 хв      |
| 500 зображень  | 2–3 години   | 45–60 хв      | 20–30 хв      |
| 1000 зображень | 4–6 годин   | 1,5–2 години      | 40–60 хв      |

{% hint style="info" %}
**Перший запуск**: Початкова обробка може тривати довше, оскільки Chloros створює кеші та профілі. Наступна обробка подібних наборів даних відбуватиметься швидше.
{% endhint %}

## Типові проблеми під час запуску

### Кнопка «Пуск» неактивна (зафарбована сірим)

**Можливі причини:**

* Зображення не імпортовано
* Бекенд не запущений повністю
* Попередня обробка ще триває
* Проєкт не завантажено повністю

**Рішення:**

1. Дочекайтеся повної ініціалізації серверної частини (перевірте піктограму в головному меню)
2. Перевірте, чи зображення імпортовані у файловому браузері
3. Перезапустіть Chloros, якщо кнопка залишається неактивною
4. Перевірте журнал налагодження на наявність повідомлень про помилки

### Обробка починається, але одразу ж завершується з помилкою

**Можливі причини:**

* У проєкті немає дійсних зображень
* Пошкоджені файли зображень
* Недостатньо місця на диску
* Недостатньо оперативної пам’яті (RAM)

**Способи вирішення:**

1. Перевірте журнал налагодження <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line"> на наявність повідомлень про помилки
2. Перевірте наявність вільного місця на диску
3. Спробуйте обробити менший набір зображень
4. Переконайтеся, що зображення не пошкоджені

### Виконання завершується, але зображення не записуються

Виконання, яке вимагало створення зображень, але не записало жодного, розглядається як **невдача, а не успіх** — Chloros чітко повідомляє про це:

* У журналі графічного інтерфейсу відображаються підказки `[RUN-SUMMARY]` із зазначенням ймовірної причини — зображення не імпортовано, ціль не виявлено або всі запитувані продукти пропущено як непридатні (наприклад, запит на радіанс/відбиваність від камер RGB)
* Еквівалент CLI (`chloros-cli process`) виводить `Processing finished but wrote no image products.` і **завершується з ненульовим результатом**, тому скрипти можуть його виявити
* Навмисний запуск лише з метаданими (усі експортні продукти вимкнені, індекси відсутні) все одно вважається успішним

Див. [Довідку щодо CLI](../reference/cli-reference.md#a-run-that-writes-no-images-fails) для повної семантики.

### Попередження «Цілі не виявлено»

**Можливі причини:**

* Забули позначити зображення-мішені
* Зображення-мішені не містять видимих цілей
* Надто суворі налаштування виявлення цілей

**Рішення:**

1. Ознайомтеся з розділом [Вибір зображень-мішеней](choosing-target-images.md)
2. Позначте відповідні зображення у стовпці «Ціль»
3. Переконайтеся, що цілі видно на позначених зображеннях
4. За необхідності скоригуйте налаштування виявлення цілей

## Поради щодо успішної обробки

### Перед початком роботи

1. **Спочатку проведіть тест на невеликій підмножині** — обробіть 10–20 зображень, щоб перевірити налаштування
2. **Перевірте вільний простір на диску** — забезпечте вільний простір у 2–3 рази більший за розмір набору даних (більше, якщо увімкнено всі продукти LATTICE)
3. **Закрийте непотрібні програми** — звільніть системні ресурси
4. **Перевірте зображення об’єктів** — перегляньте позначені об’єкти, щоб переконатися в якості
5. **Збережіть проєкт** — проєкт зберігається автоматично, але рекомендується зберігати його вручну

### Під час обробки

1. **Уникайте переходу системи в режим сну** — вимкніть режими енергозбереження
2. **Тримайте Chloros у фоновому режимі** — або принаймні видимим на панелі завдань
3. **Періодично перевіряйте хід обробки** — стежте за попередженнями та помилками
4. **Не запускайте інші ресурсоємні програми** — особливо в паралельному режимі Chloros+

### Chloros+ Прискорення за допомогою графічного процесора

Якщо використовується прискорення за допомогою графічного процесора NVIDIA:

1. Оновіть драйвери NVIDIA до останньої версії
2. Переконайтеся, що графічний процесор має 4 ГБ+ відеопам’яті (7 ГБ+ для одночасного дебейерінгу з підтримкою текстур)
3. Закрийте програми, що інтенсивно задіюють графічний процесор (ігри, редагування відео)
4. Слідкуйте за температурою графічного процесора (забезпечте належне охолодження)
