# Початок обробки

Після імпорту зображень, позначення калібрувальних міток та налаштування параметрів проєкту ви готові розпочати обробку. На цій сторінці наведено покрокову інструкцію щодо запуску конвеєра обробки Chloros.

## Перелік дій перед початком обробки

Перш ніж натиснути кнопку «Start», переконайтеся, що все готово:

* [ ] **Файли імпортовано** — усі зображення відображаються у браузері файлів
* [ ] **Зображення-мішені позначено** — у стовпці «Мішені» відмічено зображення для калібрування (або імпортовано запис `.daq` для LATTICE)
* [ ] **Моделі камер виявлені** — у стовпці «Модель камери» вказано правильні камери
* [ ] **Налаштування встановлено** — налаштування проєкту перевірено та скориговано
* [ ] **Індекси вибрано** — додано потрібні мультиспектральні індекси (за потреби)
* [ ] **Обрано формат експорту** — Вибрано формат виводу, що відповідає вашому робочому процесу

{% hint style="info" %}
**Порада**: Перед обробкою перегляньте кілька зображень у браузері файлів, щоб переконатися, що вони завантажилися правильно.
{% endhint %}

***

## Запуск обробки

### Знайдіть кнопку «Старт»

Кнопка «Старт/Відтворити» розташована у верхній панелі заголовка програми Chloros:

* Розташування: у верхній центральній частині вікна
* Піктограма: **Кнопка «Відтворити/Старт»** <img src="../.gitbook/assets/image (2) (1) (1).png" alt="" data-size="line">
* Стан: кнопка активна (підсвічена), коли система готова до обробки

### Натисніть, щоб розпочати

1. Натисніть **кнопку «Відтворити/Почати»** у верхній панелі заголовка
2. Обробка розпочнеться негайно
3. Під час обробки кнопка перетворюється на кнопку **«Стоп»**

4. Смуга прогресу оновлюється, показуючи стан обробки

{% hint style="success" %}
**Обробка розпочалася**: Після натискання Chloros автоматично виконує всі етапи обробки — виявлення об’єктів, дебейерінг, калібрування, обчислення індексу та експорт. Програма автоматично визначає, чи є ваш проєкт Survey3, LATTICE чи їхнім поєднанням, і застосовує відповідний конвеєр обробки до кожної камери.
{% endhint %}

## Ознайомлення з режимами обробки Програма

Chloros працює у двох різних режимах обробки залежно від вашої ліцензії:

### Безкоштовний режим (послідовна обробка)

**Доступний для всіх користувачів**

**Як це працює:**

* Обробляє зображення по одному, послідовно
* Однопотокова робота
* Менше використання пам’яті

**Смуга прогресу показує 2 етапи:**

1.**Виявлення мішеней** — сканування для пошуку калібрувальних мішеней
2. **Обробка** — застосування калібрування та експорт зображень**Час обробки:**

* Значно повільніше, ніж у паралельному режимі Chloros+
* Підходить для малих та середніх наборів даних (< 200 зображень)

### Режим Chloros+ (паралельна обробка)

**Потрібна ліцензія Chloros+**

**Як це працює:**

* Одночасно обробляє кілька зображень за допомогою [4-потокового конвеєра обробки](../processing-architecture/processing-pipeline.md)
* [Динамічна адаптація обчислень](../processing-architecture/dynamic-compute-adaptation.md) автоматично обирає оптимальну стратегію для вашого обладнання на початку виконання
* Прискорення на GPU (CUDA) за допомогою відеокарт NVIDIA
* **Кількість робочих процесів адаптується до апаратного забезпечення**: стратегії на GPU запускають**2–4 паралельних робочих процеси** (масштабується залежно від обсягу VRAM — 3 на GPU з 2–12 ГБ, 2–4 на GPU з 12 ГБ і більше); Системи, що використовують лише CPU, запускають по одному робочому процесу на кожне фізичне ядро, мінус один**Смуга прогресу показує 4 етапи** (що відповідають 4 потокам конвеєра):

1. **Виявлення** (потік 1) — пошук об’єктів калібрування
2. **Аналіз** (потік 2) — вивчення метаданих зображення та обчислення калібрування
3. **Калібрування** (потік 3) — дебейерінг, корекція віньєтування, калібрування, обчислення індексу
4. **Експорт** (потік 4) — збереження оброблених зображень та індексів

**Взаємодія зі смугою прогресу:**

* **Наведіть курсор миші** на смугу, щоб побачити детальну випадаючу панель із 4 етапами
* **Клацніть** на смугу прогресу, щоб зафіксувати випадаючу панель на місці
* **Клацніть ще раз**, щоб розфіксувати та приховати панель**Час обробки:**

* Значно швидше, ніж у безкоштовному режимі
* Прискорення за допомогою графічного процесора (GPU) ще більше підвищує швидкість

{% hint style="info" %}
**Швидкість Chloros+**: Паралельна обробка великих наборів даних може бути в 5–10 разів швидшою, ніж послідовний режим. Проєкт із 500 зображеннями, який у безкоштовному режимі займає 2 години, із Chloros+ може завершитися за 15–20 хвилин.
{% endhint %}

## Що відбувається під час обробки

### Етап 1: Виявлення мішеней

**Що робить Chloros:**

* Сканує зображення, які ви позначили у стовпці «Мішень» (усі зображення, якщо жодне не позначено)
* Визначає калібрувальні панелі на кожній мішені
* Витягує значення відбиття з панелей мішеней
* Записує часові мітки мішеней для планування калібрування

**Тривалість:** 1–30 секунд (з позначеними мішенями), 5–30+ хвилин (без позначок)

### Етап 2: Дебейерінг (конвертація RAW)

**Що робить Chloros:**

* Конвертує дані RAW у форматі Байєра у повноцінні 3-канальні зображення (монохромні модулі LATTICE залишаються односмуговими — для них дебейерінг пропускається з відповідною приміткою в журналі)
* Застосовує обраний алгоритм демозаїкування
* Зберігає максимальну якість зображення та деталізацію

**Тривалість:** Залежить від кількості зображень та швидкості процесора/графічного процесора

### Етап 3: Калібрування

**Що робить Chloros:**

* **Корекція віньєтування**: Усуває затемнення по краях об’єктива
* **Калібрування відбивної здатності**: нормалізує значення за допомогою еталонних значень відбивної здатності та/або даних про інсоляцію, отриманих системою збору даних (DAQ)
* Застосовує корекції до всіх діапазонів/каналів
* Використовує відповідний калібрувальний еталон для кожного зображення на основі часової мітки

**Тривалість:** Більша частина часу обробки

### Етап 4: Розрахунок індексів

**Що робить Chloros:**

* Розраховує налаштовані мультиспектральні індекси (NDVI, NDRE тощо)
* Застосовує математичні операції з діапазонами до відкаліброваних зображень
* Генерує індексні зображення для кожного вибраного індексу

**Тривалість:** Кілька секунд на одне зображення

### Етап 5: Експорт

**Що робить Chloros:**

* Зберігає оброблені зображення у вибраному форматі
* **Розгортка LATTICE**: кожен необроблений кадр LATTICE експортується як усі ввімкнені продукти за один прохід — з дебайєризацією, попереднім переглядом, радіансом (завжди float32), відбивною здатністю
* Записує файли у вихідну структуру проекту: `<project>/<camera>/<format>/<Product>_Images/`
* **Зберігає ім’я вихідного файлу** — папка ідентифікує продукт, суфікс не додається**Тривалість:** Залежить від формату експорту та розміру файлу***

## Хід обробки

### Автоматичний конвеєр обробки

Після запуску весь конвеєр працює автоматично:

* Втручання користувача не потрібне
* Усі налаштовані етапи виконуються послідовно
* Інформація про хід обробки відображається в режимі реального часу
* Експортовані файли записуються на диск по мірі їхнього завершення — ви можете відкривати готові результати, поки обробка триває

### Використання ресурсів комп’ютера під час обробки

**Вільний режим:**

* Відносно низьке завантаження процесора (однопотоковий режим)
* Комп’ютер залишається готовим до виконання інших завдань
* Можна безпечно згорнути Chloros і працювати в інших програмах

**Паралельний режим Chloros+:**

* Високе завантаження процесора у всьому пулі робочих процесів стратегії
* З прискоренням на графічному процесорі: високе завантаження графічного процесора
* Під час обробки комп’ютер може реагувати повільніше
* Уникайте запуску інших завдань, що інтенсивно використовують процесор

{% hint style="warning" %}
**Порада щодо продуктивності**: Для найкращої продуктивності Chloros+ закрийте інші програми та дозвольте Chloros використовувати всі системні ресурси.
{% endhint %}

### Обробку неможливо призупинити (але зупинка відбувається коректно)

* Після запуску обробку неможливо призупинити та пізніше відновити
* Натискання кнопки **«Стоп»** повністю зупиняє процес з першого натискання
* Результати, вже експортовані до зупинки, залишаються на диску
* Зупинений процес чесно повідомляє, що було виконано (див. рядки `[RUN-SUMMARY]` у журналі)
* Новий запуск запускає конвеєр з самого початку

**Порада щодо планування:** Для дуже великих проєктів рекомендується розглядати можливість обробки партіями або використання командного рядка (CLI) для кращого контролю.

## Моніторинг обробки

Під час виконання обробки ви можете:

* **Спостерігати за індикатором прогресу** — переглядати загальний відсоток виконання
* **Переглядати поточний етап** — виявлення, аналіз, калібрування або експорт
* **Перевіряти вкладку журналу** — переглядати детальні повідомлення та попередження щодо обробки
* **Переглядати готові зображення** — файли експорту з’являються на диску під час обробки

Детальну інформацію про моніторинг див. у розділі [Моніторинг обробки](monitoring-the-processing.md).

## Зупинка обробки

Якщо вам потрібно зупинити обробку:

### Як зупинити

1. Знайдіть **кнопку «Зупинити»** (під час обробки вона замінює кнопку «Пуск»)
2. Натисніть її один раз — на смузі з’явиться напис **«Зупинка...»**, поки завершується обробка зображення, що знаходиться в процесі
3. Процес завершиться в остаточному стані зупинки, а в журналі буде виведено точний звіт `[RUN-SUMMARY]` про те, що було виконано

### Коли слід зупинити

**Вагомі причини для зупинки:**

* Виявлено, що використовувалися неправильні налаштування
* Забули позначити цільові зображення
* Імпортовано неправильні зображення
* Система працює занадто повільно або не реагує

**Після зупинки:**

* Продукти, експортовані до зупинки, залишаються на диску
* Перегляньте та виправте будь-які проблеми, скоригуйте налаштування за потреби
* Перезапустіть обробку — процес розпочнеться з самого початку

## Орієнтовні терміни обробки

Фактичний час обробки значно варіюється залежно від:

* Кількості зображень
* Роздільної здатності зображень
* Формату вхідних даних (RAW чи JPG)
* Режиму обробки (Безкоштовний чи Chloros+)
* Швидкості процесора та кількості ядер
* Наявності графічного процесора (лише для Chloros+)
* Кількості індексів, що підлягають обчисленню
* Кількості увімкнених продуктів для експорту (LATTICE)

### Приблизні оцінки (Chloros+, зображення 12 МП, сучасний процесор)

| Кількість зображень | Безкоштовний режим | Chloros+ (процесор) | Chloros+ (графічний процесор) |
| ----------- | --------- | -------------- | -------------- |
| 50 зображень   | 15–20 хв | 5–8 хв        | 3–5 хв        |
| 100 зображень  | 30–40 хв | 10–15 хв      | 5–8 хв        |
| 200 зображень  | 1–1,5 год | 20–30 хв      | 10–15 хв      |
| 500 зображень  | 2–3 год   | 45–60 хв      | 20–30 хв      |
| 1000 зображень | 4–6 годин   | 1,5–2 години      | 40–60 хв      |

{% hint style="info" %}
**Перший запуск**: Початкова обробка може тривати довше, оскільки Chloros створює кеші та профілі. Наступна обробка подібних наборів даних відбуватиметься швидше.
{% endhint %}

## Типові проблеми під час запуску

### Кнопка «Пуск» неактивна (зафарбована сірим)

**Можливі причини:**

* Зображення не імпортовано
* Серверна частина не запущена повністю
* Попередня обробка ще триває
* Проєкт не завантажено повністю

**Рішення:**

1. Дочекайтеся повної ініціалізації серверної частини (перевірте піктограму в головному меню)
2. Перевірте, чи зображення імпортовані у файловому браузері
3. Перезапустіть Chloros, якщо кнопка залишається неактивною
4. Перевірте журнал налагодження на наявність повідомлень про помилки

### Обробка починається, але одразу ж завершується з помилкою

**Можливі причини:**

* У проєкті немає дійсних зображень
* Пошкоджені файли зображень
* Недостатньо місця на диску
* Недостатньо оперативної пам’яті (RAM)

**Способи вирішення:**

1. Перевірте журнал налагодження <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line"> на наявність повідомлень про помилки
2. Перевірте наявність вільного місця на диску
3. Спробуйте обробити меншу підмножину зображень
4. Перевірте, чи зображення не пошкоджені

### Виконання завершується, але зображення не записуються

Виконання, яке вимагало створення зображень, але не записало жодного, розглядається як **невдача, а не успіх** — Chloros чітко повідомляє про це:

* У журналі графічного інтерфейсу виводиться код `[RUN-SUMMARY]` із вказівкою ймовірної причини — зображення не імпортовано, ціль не виявлено або всі запитувані продукти пропущено як непридатні (наприклад, запит на радіанс/відбиття від камер, що підтримують лише RGB)
* Еквівалент у CLI (`chloros-cli process`) виводить `Processing finished but wrote no image products.` і **завершується з ненульовим кодом**, тому скрипти можуть це виявити
* Навмисний запуск лише з метаданими (усі продукти експорту вимкнені, індекси відсутні) все одно вважається успішним

Повну семантику див. у [Довіднику по CLI](../reference/cli-reference.md#a-run-that-writes-no-images-fails).

### Папка проекту занадто глибока для цього комп’ютера

**Тільки для Windows, нововведення у версії 1.3.0.** У Windows за замовчуванням вимкнено підтримку довгих шляхів, і довжина шляху до файлу не може перевищувати 260 символів. Продукти Chloros розміщуються приблизно на 130 символів нижче за папку проєкту, тому папка проєкту, розташована глибше, не зможе отримати свої продукти. Замість того, щоб запускатися й нічого не записувати, Chloros тепер перевіряє це перед початком обробки:

* Натискання кнопки «Пуск» не запускає виконання: смуга прогресу показує причину, а в журналі налагодження відображається код `[PROCESS] refused: The project folder is too deep for this computer…`. У повідомленні вказано довжину папки проекту та найдовшу папку проекту, яка вміщується.
* Створення або відкриття проекту в папці, яка є занадто глибокою навіть для власних файлів проекту, також відхиляється. У вікні повідомлення вказується причина, найдовша папка проекту, яка вміщується, та інструкція щодо увімкнення довгих шляхів; нічого не створюється і не відкривається; у журналі налагодження це фіксується як `[PROJECT] refused: …`. Створення дубліката проекту з довшою назвою також може перевищити обмеження: копія створюється, але не відкривається, і те саме повідомлення пояснює причину.

**Рішення:**

1. Зберігайте проекти в папці з коротшою назвою — змініть**Робочу директорію** у [Налаштуваннях проекту](../project-settings/project-settings.md) і створіть проект заново, або
2. Увімкніть підтримку довгих шляхів у Windows та перезапустіть Chloros: запустіть інсталятор Chloros ще раз, встановивши прапорець **Увімкнути довгі шляхи Windows** (він встановлений за замовчуванням), або скористайтеся груповою політикою: *Конфігурація комп’ютера > Адміністративні шаблони > Система > Файлова система > Увімкнути довгі шляхи Win32*.

### Попередження «Цілі не виявлено»

**Можливі причини:**

* Забули позначити цільові зображення
* Цільові зображення не містять видимих цілей
* Надто суворі налаштування виявлення цілей

**Рішення:**

1. Ознайомтеся з розділом [Вибір цільових зображень](choosing-target-images.md)
2. Позначте відповідні зображення у стовпці «Ціль»
3. Переконайтеся, що цілі видно на позначених зображеннях
4. За потреби скоригуйте налаштування виявлення цілей

## Поради для успішної обробки

### Перед початком

1. **Спочатку проведіть тестування на невеликій підмножині** — обробіть 10–20 зображень, щоб перевірити налаштування
2. **Перевірте вільний простір на диску** — забезпечте вільний простір у 2–3 рази більший за розмір набору даних (більше, якщо увімкнено всі продукти LATTICE)
3. **Закрийте непотрібні програми** — звільніть системні ресурси
4. **Перевірте зображення цілей** — перегляньте позначені цілі, щоб переконатися в якості
5. **Збережіть проєкт** — проєкт зберігається автоматично, але рекомендується зберігати його вручну

### Під час обробки

1. **Уникайте переходу системи в режим сну** — вимкніть режими енергозбереження
2. **Тримайте Chloros у фоновому режимі** — або принаймні видимим у панелі завдань
3. **Періодично перевіряйте хід обробки** — звертайте увагу на попередження чи помилки
4. **Не запускайте інші ресурсоємні програми** — особливо в паралельному режимі Chloros+

### Прискорення на GPU в Chloros+

Якщо ви використовуєте прискорення на GPU від NVIDIA:

1. Оновіть драйвери NVIDIA до останньої версії
2. Переконайтеся, що GPU має 4 ГБ+ відеопам’яті (7 ГБ+ для одночасного дебейерінгу з підтримкою текстур)
3. Закрийте програми, що інтенсивно використовують GPU (ігри, редагування відео)
4. Стежте за температурою GPU (забезпечте належне охолодження)
