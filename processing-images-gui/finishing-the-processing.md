# Завершення обробки

Після того як Chloros завершить обробку, настав час переглянути результати, перевірити якість вихідних даних та підготувати оброблені зображення для використання у вашому робочому процесі. На цій сторінці ви знайдете покрокові інструкції щодо завершальних кроків та подальших дій.

## Позначення про завершення обробки

Після успішного завершення обробки ви побачите кілька індикаторів:

* ✅ **Смуга прогресу**: досягає 100% завершення
* ✅ **Журнал налагодження**: показує останні рядки `[RUN-SUMMARY]` із кількістю (зображень, груп камер, цілей, відкаліброваних зображень, записаних файлів)
* ✅ **Кнопка «Старт»**: знову стає активною (готова до наступного циклу обробки)
* ✅ **Вихідні файли**: усі оброблені зображення збережені у вихідній папці проєкту (нижче)

{% hint style="warning" %}
**Цикл, під час якого не записано жодного зображення, вважається невдалим.** Якщо ви запитували зображення, а цикл не записав жодного, Chloros повідомляє про це як про невдачу — `[RUN-SUMMARY]` у назві журналу вказує на ймовірну причину (нічого не імпортовано, ціль не виявлено або всі запитувані продукти пропущено як непридатні). Еквівалент CLI завершується з ненульовим кодом. Навмисний запуск, що створює лише метадані (усі продукти експорту вимкнені, індекси відсутні), все одно вважається успішним. Див. [Довідник CLI](../reference/cli-reference.md#a-run-that-writes-no-images-fails).
{% endhint %}

## Пошук оброблених зображень

### Відкриття папки вихідних даних

1. Клацніть на піктограму **Головного меню** <img src="../.gitbook/assets/image (1) (1) (1) (1).png" alt="" data-size="line">
(у верхньому лівому куті)
2. Виберіть **«Відкрити папку проєкту»**

3. Відкриється провідник файлів у каталозі проєкту
4. Знайдіть свій проєкт за назвою

### Дерево вихідних файлів

Продукти зберігаються **у папці проєкту, згруповані за камерами, а потім за форматами файлів**:

```
<project>/
└── LATT-M3M-L41-F550/                  # one folder per camera
    ├── tiff16/
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one folder per selected index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

* **Папка камери**: `LATT-<sensor>-<lens>-F<filter>` для LATTICE (відповідає EXIF-даним знімка `Model`), `<model>_<filter>` для Survey3 (наприклад, `Survey3N_RGN`). Дві камери, що мають спільний сенсор і фільтр, але відрізняються об’єктивом, зберігаються в окремих деревах — віньєтування, поле зору та спотворення відрізняються.
* **Формат папки**: відповідає вашим налаштуванням формату експорту — `tiff16`, `tiff8`, `png8`, `jpg8`, або `tiff32` для формату TIFF (32-бітний, у відсотках). Радіанс завжди має тип float32 і завжди зберігається у папці `tiff32`.
* **Папки з результатами**:
  * `Reflectance_Calibrated_Images/` — відкалібрований коефіцієнт відбиття
  * `Debayered_Images/` — лінійне дебейерування (LATTICE): усунуто темне зміщення та проведено демозаїкування, без плоского поля або розкладання, у природній орієнтації датчика
  * `Preview_Images/` — попередній перегляд на екрані (LATTICE)
  * `Radiance_Images/` — спектральна яскравість у форматі float32, Вт/м²/sr/нм (мультиспектральний режим LATTICE)
  * `Vignette_Corrected_Images/` **або** `Sensor_Response_Images/` — некалібрований резервний варіант для кадрів без еталону відбиття; на кожен цикл існує саме один із цих двох варіантів, який обирається за допомогою налаштування корекції віньєтування
  * `<INDEX>_Index_Images/` — одна папка на кожен вибраний індекс (наприклад, `NDVI_Index_Images`)
* **`clamp_masks/`** (нова функція у версії 1.3.0, лише для мультиспектральних камер LATTICE M3C): з’являється у папці формату, поруч із папками продуктів, коли під час розкладання смуг негативні значення обрізаються до нуля у продукті яскравості або відбиття. Вона містить одну маску на піксель для кожного продукту, на який це вплинуло, наприклад, `tiff16/clamp_masks/Reflectance_Calibrated_Images/<name>_clampmask.tif`. Маски ніколи не знаходяться всередині папки з продуктами, тому папку з продуктами можна передавати до програмного забезпечення для фотограмметрії у незміненому вигляді. Див. [Маски обмеження](../output-image-formats.md#clamp-masks).

{% hint style="info" %}
**Кожен експортований продукт зберігає ім’я файлу-джерела.**Експорт інтенсивності випромінювання `capture_..._raw.tif` все ще називається `capture_..._raw.tif` — просто він знаходиться в `tiff32/Radiance_Images/`.**Папка ідентифікує продукт, а не ім’я файлу**, тому пошук за `*radiance*.tif` нічого не знайде; замість цього шукайте за назвою каталогу.
{% endhint %}

### Скільки файлів має бути?

Не рахуйте за формулою — кількість вихідних даних залежить від того, які продукти було ввімкнено та які застосовуються до кожної камери (наприклад, камери RGB не отримують даних про яскравість/відбиття). Достовірна кількість вказана в журналі: остання рядок `[RUN-SUMMARY]` повідомляє, скільки саме файлів було записано, а рядки-підказки пояснюють, що саме було пропущено.

### Швидкий попередній перегляд у Провіднику файлів

**Вбудований попередній перегляд у Windows:**

1. Перейдіть до папки з результатами обробки (наприклад, `tiff16/Reflectance_Calibrated_Images/`)
2. Виберіть файл зображення
3. Попередній перегляд з’явиться у панелі попереднього перегляду Провідника Windows

4. Використовуйте клавіші зі стрілками для перегляду зображень

### Попередній перегляд у зовнішніх програмах перегляду зображень

**Рекомендовані програми перегляду:**

* **QGIS** — безкоштовне програмне забезпечення для роботи з геоінформаційними системами (найкраще підходить для мультиспектрального аналізу з геореференцією)
* **IrfanView** — швидка та компактна програма для перегляду зображень (підтримує формат TIFF)
* **Adobe Photoshop** — професійне редагування (підтримка формату TIFF)
* **GIMP** — безкоштовна альтернатива Photoshop
* **Windows Photos** — базовий перегляд (може не підтримувати 16-бітний формат TIFF)

### Перегляд у програмі перегляду зображень Chloros


Використовуйте вбудовану програму перегляду зображень Chloros для розширеної візуалізації:

1. Клацніть на мініатюру зображення у браузері файлів
2. Зображення відкриється в основній області попереднього перегляду
3. Клацніть на вкладку **Image Viewer** <img src="../.gitbook/assets/icon_image-viewer.JPG" alt="" data-size="line">
у лівій бічній панелі
4. Використовуйте [Index/LUT Sandbox](../image-viewer-gui/index-lut-sandbox.md) для інтерактивного аналізу

Детальні інструкції див. у розділі [Image Viewer](../image-viewer-gui/opening-an-image-full-screen.md).

## Зчитування значень відбивної здатності пікселів (ГІС / Pix4D / Скрипти)

Відбивна здатність зберігається у вигляді цілого числа DN, і **значення DN, яке відповідає ρ = 1,0, залежить від камери-джерела**:

| Джерело          | ρ = 1,0 дорівнює | Як визначити                                        |
| --------------- | ---------- | -------------------------------------------------- |
| LATTICE (M3C/M3M) | **32768** (запас до ρ 2,0) | У файлі проставлено тег XMP `Chloros:PixelScale=32768` |
| Survey3          | **65535** (обрізано при ρ 1,0)     | Тег `Chloros:PixelScale` відсутній — саме ця відсутність є сигналом (продукти Survey3 містять інші теги обробки `Chloros:*`) |

**Прочитайте тег `Chloros:PixelScale` і розділіть на це значення**, замість того щоб припускати загальне значення 65535 — ділення відбивної здатності LATTICE на 65535 непомітно зменшує кожне значення вдвічі. Файл відбиття, створений до версії 1.3.0 у 8-бітному форматі, був обрізаний, а не перемасштабований, і не містить тегу масштабу: переекспортуйте його у 16-бітному або 32-бітному форматі замість того, щоб ділити його. Див. [Формати вихідних зображень](../output-image-formats.md) для повної інформації.

## Метадані, що передаються під час експорту

Кожен продукт зберігає **блок GPS**вихідного знімка та його**під-IFD EXIF**, тому
експорт містить `FocalLength`, `FNumber`, `ExposureTime`, `ISO`, `DateTimeOriginal` та
`CameraSerialNumber`, а також геореференціювання.

{% hint style="warning" %}
**Якщо ортомозаїка виходить у абсурдному масштабі, спочатку перевірте `FocalLength`.**
Pix4D обчислює відстань між точками на місцевості на основі фокусної відстані та висоти над рівнем моря. Без цього тегу програма
використовує вкрай неправильний масштаб — під час одного виміряного польоту з 49 знімками апельсиновий гай розміром 411 м × 160 м
апельсиновий гай був реконструйований як 47,8 км × 13 км, що дало ортофотографію розміром 455 мегапікселів, яка складалася переважно з
порожнього простору. Повільне мозаїкування та несподівано великий розмір файлу є симптомами цієї проблеми, а не окремими
проблемами.

```bash
exiftool -FocalLength -GPSLatitude "YourProject/.../some_export.tif"
```
{% endhint %}

Не *всі* теги копіюються. Структурні теги IFD0 навмисно не копіюються (їхнє копіювання
призводить до пошкодження вихідних даних LATTICE), а `ExifImageWidth` / `ExifImageHeight` виключаються,
оскільки вони описують вихідний знімок — експорт із зміненим розміром інакше
заявляв би розміри, що суперечать розмірам самого растру.

Chloros також записує власні теги XMP `Chloros:*`, що описують, які дії було виконано з кожним продуктом
(наприклад, `Chloros:ProcessingLevel`, `Chloros:CalibrationApplied`,
`Chloros:VignetteCorrected`). Починаючи з версії 1.3.0, продукти Survey3 містять їх у кожному режимі обробки
режимі обробки; індексні продукти описують сам індекс (`Chloros:ProcessingLevel=index`,
формулу та те, чи було він обчислено на основі відбитої або випромінюваної потужності), замість того, щоб повторювати
теги вихідних необроблених даних; а продукти у папках, імена яких містять більше 260 символів, також зберігають свої метадані. Див. [Формати вихідних зображень](../output-image-formats.md#index-products).

## Перегляд журналу налагодження

### Перевірка наявності попереджень або помилок

1. Відкрийте вкладку **Журнал налагодження** <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

2. Прокрутіть повідомлення
3. Знайдіть жовті попередження або червоні помилки
4. Прочитайте рядки `[RUN-SUMMARY]` та будь-які підказки

3. Додайте до документації проєкту
4. Надішліть його до служби підтримки MAPIR, якщо виникли проблеми

Щоб надіслати повідомлення про проблему безпосередньо до MAPIR, скористайтеся піктограмою помилки (**Повідомити про помилку**) у верхній частині вкладки «Журнал налагодження» — див. [Повідомлення про помилку з вкладки журналу](monitoring-the-processing.md#reporting-a-bug-from-the-log-tab).

## Поширені проблеми з вихідними даними та їх вирішення

### Проблема: Відсутні вихідні файли

**Можливі причини:**

* Продукт не застосовується до цієї камери (наприклад, радіанс/відбивна здатність для камер RGB — про це зазначено в журналі)
* Відсутня необхідна референція (наприклад, коефіцієнт відбиття без цілі та без `.daq` випромінювання вниз)
* У налаштуваннях проєкту було вимкнено прапорець експорту продукту
* Під час експорту закінчився простір на диску

**Рішення:**

1. Перевірте підказки `[RUN-SUMMARY]` та рядки `[EXPORT-CHECK]` у журналі налагодження — вони пояснюють пропуски для кожної камери
2. Перевірте, чи встановлені прапорці експорту продукту в [Налаштуваннях проєкту](adjusting-project-settings.md)
3. Перевірте, чи було достатньо місця на диску
4. Повторіть обробку після усунення причини

### Проблема: Темні або світлі краї (віньєтування все ще помітне)

**Можливі причини:**

* Корекція віньєтування вимкнена
* Камера/об'єктив відсутні в базі даних профілів Chloros

* Екстремальне віньєтування, яке перевищує можливості корекції

**Рішення:**

1. Переконайтеся, що корекція віньєтування увімкнена в налаштуваннях проєкту
2. Перевірте, чи правильно визначено модель камери
3. Зверніться до служби підтримки MAPIR, якщо віньєтування не зникає

### Проблема: Неправильні кольори або значення

**Можливі причини:**

* Не виявлено калібрувальних мішеней
* Вибрано неправильну модель калібрувальної мішені
* Калібрування відбиття вимкнено
* Низька якість зображень мішеней

**Рішення:**

1. Перевірте, чи увімкнено калібрування відбиття
2. Перевірте повідомлення «Ціль виявлено» у журналі налагодження
3. Перевірте якість зображень мішеней
4. Повторіть обробку, позначивши правильні мішені

### Проблема: Значення NDVI здаються неправильними

**Очікувані діапазони NDVI:**

* **Вода, скелі, ґрунт**: від -0,1 до 0,2
* **Рідка/нездорова рослинність**: від 0,2 до 0,4
* **Помірна рослинність**: від 0,4 до 0,6
* **Здорова, густа рослинність**: від 0,6 до 0,9**Якщо значення виходять за межі цих діапазонів:**

1. Перевірте, чи було застосовано калібрування відбиття
2. Перевірте, чи було включено журнал датчика освітленості
3. Перевірте, чи були виявлені калібрувальні мішені
4. Переконайтеся, що була визначена правильна модель камери
5. Перегляньте час та умови зйомки цільових зображень
6. Якщо ви самостійно обчислюєте індекси на основі файлів відбиття, переконайтеся, що ви поділили значення на `Chloros:PixelScale` у файлі (див. вище)

## Використання оброблених зображень

### Для фотограмметрії / створення ортомозаїки

**Рекомендований робочий процес:**

1.**Імпортуйте відкалібровані зображення відбиття** у програмне забезпечення для фотограмметрії:
   * Pix4Dmapper
   * Agisoft Metashape
   * DroneDeploy
   * WebODM
2. **Збережіть метадані EXIF**: переконайтеся, що дані GPS збережені для геотагування
3. **Калібровані робочі процеси**: використовуйте зображення відбиття для наукової точності — відбиття LATTICE містить теги калібрування XMP, які зчитує Pix4D
4. **Обробіть індексні мозаїки**: створіть ортомозаїки NDVI з окремих індексних зображень
5. **Експорт геореферентованих файлів GeoTIFF**: для використання в ГІС-додатках

### Для ГІС-аналізу

**Рекомендований робочий процес:**

1.**Завантажте в QGIS, ArcGIS або подібні програми**

2.**Використовуйте 16-бітні TIFF-зображення** відбиття для багатосмугового аналізу (поділіть на `Chloros:PixelScale` у файлі)
3. **Використовуйте індексні зображення** (NDVI, NDRE) як готові до використання шари рослинності
4. **Растровий калькулятор**: об’єднайте діапазони для власного аналізу
5. **Експорт**: створіть класифікаційні карти, карти виявлення змін, карти стану рослинності

### Для безпосереднього аналізу / звітності

**Рекомендований робочий процес:**

1.**Використовуйте індексні зображення з кольорами LUT** для візуальних звітів
2. **Витяг статистичних даних**: середнє значення NDVI для кожного поля/ділянки
3. **Часові ряди**: порівняння індексів за кілька сесій
4. **Створення звітів**: включення карт, статистичних даних та візуалізацій***

## Архівування та резервне копіювання

### Рекомендована стратегія резервного копіювання

**Що слід зберігати:**

* ✅ **Оригінальні зображення у форматі RAW/JPG або необроблені знімки LATTICE** — архівуйте на окремому диску/у хмарі; необроблені дані є джерелом обробки, і все інше можна відтворити на їхній основі
* ✅ **Файли датчиків освітленості `.daq` / `.csv`** — необхідні для подальшого повторного розрахунку коефіцієнта відбиття
* ✅ **Оброблені результати** — зберігайте відкалібровані зображення та індекси
* ✅ **Папка проєкту** (`project.json` та супутні файли) — містить усі налаштування для повторної обробки, якщо це знадобиться
* ✅ **Журнал налагодження** — документує деталі обробки
* ✅ **Зображення калібрувальних мішеней** — для перевірки та повторної обробки

**Рекомендації щодо зберігання:**

* **Негайне резервне копіювання**: Зовнішній жорсткий диск
* **Довгострокове архівування**: Хмарне сховище (Google Drive, Dropbox тощо)
* **Критично важливі дані**: Зберігайте 2–3 копії в різних місцях***

## Усунення несправностей під час постобробки

### Повторна обробка з іншими налаштуваннями

Якщо результати не задовольняють:

1. Збережіть оригінальні зображення (ніколи не видаляйте їх)
2. Відкрийте той самий проєкт у Chloros
3. Налаштуйте параметри на панелі «Налаштування проєкту»
4. Проведіть обробку ще раз — результати зберігаються в тих самих папках продукту, тому файли з тими самими іменами з попереднього запуску будуть замінені

### Обробка підмножини зображень

Щоб повторно обробити лише певні зображення:

1. Створіть новий проєкт
2. Імпортуйте лише ті зображення, які потребують повторної обробки
3. Використовуйте той самий шаблон налаштувань
4. Обробіть менший набір даних
