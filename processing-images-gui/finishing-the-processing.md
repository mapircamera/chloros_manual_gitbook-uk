# Завершення обробки

Після того як Chloros завершить обробку, настав час переглянути результати, перевірити якість вихідних даних та підготувати оброблені зображення для використання у вашому робочому процесі. На цій сторінці ви знайдете покрокові інструкції щодо завершальних кроків та подальших дій.

## Позначення про завершення обробки

Після успішного завершення обробки ви побачите кілька індикаторів:

* ✅ **Смуга прогресу**: досягає 100% завершення
* ✅ **Журнал налагодження**: показує останні рядки `[RUN-SUMMARY]` із кількістю (зображень, груп камер, цілей, відкаліброваних зображень, записаних файлів)
* ✅ **Кнопка «Старт»**: знову стає активною (готова до наступного запуску обробки)
* ✅ **Вихідні файли**: Усі оброблені зображення збережені у вихідній папці проєкту (нижче)

{% hint style="warning" %}
**Цикл, під час якого не було записано жодного зображення, вважається невдалим.** Якщо ви запитували зображення, а цикл не записав жодного, Chloros повідомляє про це як про невдачу — `[RUN-SUMMARY]` вказує у назві журналу ймовірну причину (нічого не імпортовано, ціль не виявлено або всі запитувані продукти пропущено як непридатні). Еквівалент CLI завершується з ненульовим кодом. Навмисний запуск лише з метаданими (усі продукти експорту вимкнені, індекси відсутні) все одно вважається успішним. Див. [Довідку щодо CLI](../reference/cli-reference.md#a-run-that-writes-no-images-fails).
{% endhint %}

## Пошук оброблених зображень

### Відкриття папки вихідних даних

1. Клацніть на піктограму **Головного меню** <img src="../.gitbook/assets/image (1) (1) (1) (1).png" alt="" data-size="line"> (у верхньому лівому куті)
2. Виберіть **«Відкрити папку проєкту»**

3. Відкриється провідник файлів у каталозі проєкту
4. Знайдіть свій проєкт за назвою

### Дерево вихідних файлів

Файли зберігаються **у папці проєкту, згруповані за камерами, а потім за форматами файлів**:

```
<project>/
└── LATT-M3M-L41-F550/                  # one folder per camera
    ├── tiff16/
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one folder per selected index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

* **Папка камери**: `LATT-<sensor>-<lens>-F<filter>` для LATTICE (відповідає EXIF-даним знімка `Model`), `<model>_<filter>` для Survey3 (наприклад, `Survey3N_RGN`). Дві камери, що мають спільний сенсор і фільтр, але відрізняються об&#x27;єктивом, зберігаються в окремих деревах — віньєтування, поле зору та спотворення відрізняються.
* **Формат папки**: відповідає вашим налаштуванням формату експорту — `tiff16`, `tiff8`, `png8`, `jpg8`, або `tiff32` для TIFF (32-бітний, у відсотках). Дані про яскравість завжди зберігаються у форматі float32 і завжди розміщуються у папці `tiff32`.
* **Папки з даними**:
  * `Reflectance_Calibrated_Images/` — відкалібрований коефіцієнт відбиття
  * `Debayered_Images/` — лінійне дебейерування (LATTICE)
  * `Preview_Images/` — попередній перегляд на екрані (LATTICE)
  * `Radiance_Images/` — спектральна яскравість типу float32, Вт/м²/ср/нм (багатоспектральний режим LATTICE)
  * `Vignette_Corrected_Images/` **або** `Sensor_Response_Images/` — некалібрований запасний варіант для кадрів без еталонного значення відбивної здатності; на кожен цикл існує саме один із цих двох варіантів, який обирається налаштуванням корекції віньєтування
  * `<INDEX>_Index_Images/` — одна папка на кожен вибраний індекс (наприклад, `NDVI_Index_Images`)

{% hint style="info" %}
**Кожен експортований продукт зберігає ім’я вихідного файлу.**Експорт радіансної інтенсивності з `capture_..._raw.tif` все одно називається `capture_..._raw.tif` — він просто знаходиться в `tiff32/Radiance_Images/`.**Папка ідентифікує продукт, а не ім’я файлу**, тому пошук за `*radiance*.tif` нічого не знайде; замість цього шукайте за каталогом.
{% endhint %}

Не рахуйте за формулою — кількість вихідних файлів залежить від того, які продукти були ввімкнені та які застосовуються до кожної камери (наприклад, камери RGB не отримують даних про яскравість/відбиття). **Вбудований попередній перегляд Windows:**

1. Перейдіть до папки продукту (наприклад, `tiff16/Reflectance_Calibrated_Images/`)

4. Використовуйте клавіші зі стрілками для перегляду зображень

### Попередній перегляд у зовнішніх програмах перегляду зображень

**Рекомендовані програми перегляду:*** **QGIS** — безкоштовне програмне забезпечення для роботи з геоінформаційними системами (найкраще підходить для мультиспектрального аналізу з геореференцією)

* **Adobe Photoshop** — професійне редагування (підтримка формату TIFF)
* **GIMP** — безкоштовна альтернатива Photoshop
* **Windows Photos** - Базовий перегляд (може не підтримувати 16-бітний формат TIFF)

### Попередній перегляд у програмі перегляду зображень Chloros

Використовуйте вбудований переглядач зображень Chloros для розширеної візуалізації:

1. Клацніть на мініатюру зображення у файловому браузері
2. Зображення відкриється в основній області попереднього перегляду
3. Клацніть на вкладку **Image Viewer** <img src="../.gitbook/assets/icon_image-viewer.JPG" alt="" data-size="line"> у лівій бічній панелі
4. Використовуйте [Index/LUT Sandbox](../image-viewer-gui/index-lut-sandbox.md) для інтерактивного аналізу

Детальні інструкції див. у розділі [Переглядач зображень](../image-viewer-gui/opening-an-image-full-screen.md).

## Зчитування значень відбивної здатності пікселів (GIS / Pix4D / Скрипти)

Відбивна здатність зберігається у вигляді цілого числа DN, і **значення DN, яке відповідає ρ = 1,0, залежить від вихідної камери**:

| Джерело          | ρ = 1,0 дорівнює | Як визначити                                        |
| --------------- | ---------- | -------------------------------------------------- |
| LATTICE (M3C/M3M) | **32768** (запас до ρ 2,0) | У файлі проставляється тег XMP `Chloros:PixelScale=32768` |
| Survey3         | **65535** (обрізано при ρ 1,0)     | Тегів XMP `Chloros:*` немає — саме ця відсутність є сигналом |

**Прочитайте тег `Chloros:PixelScale` і розділіть на це значення**, замість того щоб припускати загальне значення 65535 — ділення відбивної здатності LATTICE на 65535 непомітно зменшує кожне значення вдвічі. Один крайній випадок за задумом не має тегу масштабу: знімок із 8-бітним джерелом, записаний як 8-бітний вихід, обрізається, а не перемасштабовується, і навмисно не отримує тегу масштабу — для отримання повної інформації скористайтеся повторним експортом у 16-бітний або 32-бітний формат замість ділення. Див. [Формати вихідних зображень](../output-image-formats.md).***

## Метадані, що передаються при експорті

Кожен продукт зберігає **блок GPS**вихідного знімка та його**під-IFD EXIF**, тому
експорт містить `FocalLength`, `FNumber`, `ExposureTime`, `ISO`, `DateTimeOriginal` та
`CameraSerialNumber`, а також геореференцію.

{% hint style="warning" %}
**Якщо ортомозаїка виходить у абсурдному масштабі, спочатку перевірте `FocalLength`.**
Pix4D обчислює відстань між точками на місцевості на основі фокусної відстані та висоти над рівнем моря. Без цього тегу
програма використовує вкрай неправильний масштаб — під час одного виміряного польоту з 49 знімками апельсиновий гай розміром 411 м × 160 м
апельсиновий гай реконструювався як 47,8 км × 13 км, що дало ортофотографію розміром 455 мегапікселів, яка складалася переважно з
порожнього простору. Повільне розбиття на фрагменти та несподівано великий розмір файлу є симптомами цієї проблеми, а не окремими
проблемами.

```bash
exiftool -FocalLength -GPSLatitude "YourProject/.../some_export.tif"
```
{% endhint %}

Не *всі* теги копіюються. Структурні теги IFD0 навмисно не копіюються (їхнє копіювання
призводить до пошкодження вихідних даних LATTICE), а `ExifImageWidth` / `ExifImageHeight` виключаються,
оскільки вони описують вихідний знімок — інакше експорт із зміненим розміром
заявляв би розміри, що суперечать розмірам його власного растру.

## Поширені проблеми з результатами та їх вирішення

### Проблема: Відсутні файли результатів

**Можливі причини:**

* Продукт не застосовується до цієї камери (наприклад, радіанс/відбивна здатність для камер RGB — про це зазначено в журналі)
* Відсутня необхідна референція (наприклад, коефіцієнт відбиття без об’єкта та без низхідного випромінювання `.daq`)
* У налаштуваннях проєкту було вимкнено прапорець експорту продукту
* Під час експорту закінчилося місце на диску

**Рішення:**

1. Перевірте підказки `[RUN-SUMMARY]` та рядки `[EXPORT-CHECK]` у журналі налагодження — вони пояснюють пропуски для кожної камери окремо
2. Перевірте прапорці експорту продуктів у [Налаштуваннях проєкту](adjusting-project-settings.md)
3. Переконайтеся, що на диску було достатньо вільного місця
4. Повторіть обробку після усунення причини

### Проблема: Темні або світлі краї (віньєтування все ще помітне)

**Можливі причини:**

* Корекція віньєтування вимкнена
* Камера/об&#x27;єктив відсутні в базі профілів Chloros
* Надзвичайно сильне віньєтування, яке не піддається корекції

**Рішення:**

1. Переконайтеся, що корекція віньєтування ввімкнена в налаштуваннях проєкту
2. Перевірте, чи правильно визначено модель камери
3. Якщо віньєтування не зникає, зверніться до служби підтримки MAPIR

### Проблема: Неправильні кольори або значення

**Можливі причини:**

* Не виявлено калібрувальних мішеней
* Вибрано неправильну модель калібрувальної мішені
* Калібрування відбиття вимкнено
* Низька якість зображень мішеней

**Рішення:**

1. Перевірте, чи увімкнено калібрування відбиття
2. Перевірте повідомлення «Мішень знайдено» у журналі налагодження
3. Перевірте якість зображень мішеней
4. Повторіть обробку, позначивши правильні мішені

### Проблема: Значення NDVI здаються неправильними

**Очікувані діапазони NDVI:*** **Вода, скелі, ґрунт**: від -0,1 до 0,2
* **Рідка/нездорова рослинність**: від 0,2 до 0,4
* **Помірна рослинність**: від 0,4 до 0,6
* **Здорова, густа рослинність**: від 0,6 до 0,9**Якщо значення виходять за межі цих діапазонів:**

1. Перевірте, чи було застосовано калібрування відбиття
2. Перевірте, чи було включено журнал датчика освітленості
3. Перевірте, чи були виявлені калібрувальні мішені
4. Переконайтеся, що було виявлено правильну модель камери
5. Перегляньте час та умови зйомки цільових зображень
6. Якщо ви самостійно обчислюєте індекси на основі файлів відбиття, переконайтеся, що ви поділили значення на `Chloros:PixelScale` у файлі (див. вище)

## Використання оброблених зображень

### Для фотограмметрії / створення ортомозаїки

**Рекомендований робочий процес:**

1.**Імпортуйте відкалібровані зображення відбиття** у програмне забезпечення для фотограмметрії:
   * Pix4Dmapper
   * Agisoft Metashape
   * DroneDeploy
   * WebODM
2. **Збережіть метадані EXIF**: переконайтеся, що дані GPS збережені для геотагування
3. **Калібровані робочі процеси**: використовуйте зображення відбиття для наукової точності — відбиття LATTICE містить теги калібрування XMP, які зчитує Pix4D
4. **Обробка індексних мозаїк**: Створіть ортомозаїки NDVI з окремих індексних зображень
5. **Експорт геореферентованих зображень GeoTIFF**: Для використання в ГІС-додатках

### Для ГІС-аналізу

**Рекомендований робочий процес:**

1.**Завантажте в QGIS, ArcGIS або подібну програму**

2.**Використовуйте 16-бітні зображення відбиття TIFF** для багатосмугового аналізу (поділити на `Chloros:PixelScale` файлу)
3. **Використовуйте індексні зображення** (NDVI, NDRE) як готові до використання шари рослинності
4. **Растровий калькулятор**: об’єднуйте діапазони для власного аналізу
5. **Експорт**: створюйте карти класифікації, виявлення змін, карти стану рослинності

### Для безпосереднього аналізу / складання звітів

**Рекомендований робочий процес:**

1.**Використовуйте індексні зображення з кольорами LUT** для візуальних звітів
2. **Витяг статистичних даних**: середнє значення NDVI для кожного поля/ділянки
3. **Часові ряди**: порівняння індексів за кілька сесій
4. **Створення звітів**: включення карт, статистичних даних та візуалізацій***

Якщо в майбутньому планується обробка подібних наборів даних:

1. **Збережіть шаблон проєкту** (якщо це ще не зроблено)
2. **Створіть новий проєкт**, використовуючи збережений шаблон
3. **Імпортуйте нові зображення**

4.**Обробіть**з ідентичними налаштуваннями для забезпечення узгодженості

### Пакетна обробка декількох сесій

Для декількох сесій/наборів даних:**Варіант 1: Графічний інтерфейс — кілька проєктів**

* Створіть окремий проєкт для кожної сесії
* Використовуйте узгоджені налаштування шаблону
* Обробляйте по одному

**Варіант 2: Chloros CLI (лише для Chloros+)**

* Автоматизуйте пакетну обробку
* Обробляйте кілька папок за допомогою скриптів
* Див. [Документацію CLI](../CLI.md) та [Довідник CLI](../reference/cli-reference.md)

**Варіант 3: Python SDK (лише для Chloros+)**

* Програмне керування
* Інтеграція з конвеєрами аналізу
* Див. [Документацію API](../api-python-sdk.md) та [Довідку по SDK](../reference/sdk-reference.md)

## Усунення несправностей під час постобробки

### Повторна обробка з іншими налаштуваннями

Якщо результати не задовольняють:

1. Збережіть оригінальні зображення (ніколи не видаляйте їх)
2. Відкрийте той самий проєкт у Chloros
3. Налаштуйте параметри на панелі «Налаштування проєкту»
4. Проведіть обробку ще раз — результати зберігаються в тих самих папках продуктів, тому файли з тими самими іменами з попереднього запуску будуть замінені

### Обробка підмножини зображень

Щоб повторно обробити лише певні зображення:

1. Створіть новий проєкт
2. Імпортуйте лише ті зображення, які потребують повторної обробки
3. Використовуйте той самий шаблон налаштувань
4. Обробіть менший набір даних
