# Налаштування параметрів проєкту

Перед обробкою зображень важливо налаштувати параметри проєкту відповідно до вимог вашого робочого процесу. Панель «Налаштування проєкту» (<img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line">) забезпечує повний контроль над калібруванням, параметрами обробки, мультиспектральними індексами та форматами експорту.

## Доступ до налаштувань проєкту

1. Відкрийте свій проєкт у Chloros
2. Клацніть на піктограму **Налаштування проєкту** <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line"> на лівій бічній панелі
3. На панелі «Налаштування проєкту» відображаються всі параметри конфігурації

<figure><img src="../.gitbook/assets/image (28).png" alt=""><figcaption><p>Панель «Налаштування проєкту» — відображення, виявлення цілей та обробка</p></figcaption></figure>{% hint style="info" %}
**Налаштування зберігаються автоматично** разом із вашим проєктом. Коли ви знову відкриваєте проєкт, усі налаштування відновлюються.
{% endhint %}

***

## Швидке налаштування для типових робочих процесів

### Налаштування за замовчуванням (рекомендовано для більшості користувачів)

Налаштування за замовчуванням добре підходять для типових робочих процесів Survey3 та LATTICE:

* ✅ **Корекція віньєтування**: Увімкнено
* ✅ **Калібрування відбиття / баланс білого**: Увімкнено (використовує мішені MAPIR та/або дані світлочутливого датчика DAQ)
* ✅ **Метод дебейєрингу**: Стандартний (Швидкий, Середня якість)
* ✅ **Формат експорту**: TIFF (16-бітний)
* ✅ **Усі продукти експорту**: Увімкнено (LATTICE автоматично зберігає розгортку у вигляді зображень з дебейєром, попереднього перегляду, радіансної яскравості та відбивної здатності)

Просто імпортуйте свої зображення та розпочніть обробку з цими налаштуваннями за замовчуванням.

***

## Огляд налаштувань проєкту

Панель «Налаштування проєкту» поділена на наведені нижче розділи. Два додаткові розділи — **DAQ Light Sensor**та**Array Alignment** — з’являються автоматично, якщо ваш проєкт містить відповідні файли. Повну документацію див. у розділі [Налаштування проєкту](../project-settings/project-settings.md).

### Відображення

* **Роздільна здатність ескізів зображень**: Роздільна здатність ескізів у сітці зображень. Варіанти:**За замовчуванням (512 пікселів)**,**1024 пікселів**,**2048 пікселів**,**Повна роздільна здатність**. Тільки для відображення — ніколи не впливає на обробку. Більші значення виглядають чіткіше при збільшенні, але завантажуються повільніше.

### Виявлення мішеней

Керує тим, як Chloros ідентифікує калібрувальні мішені на ваших зображеннях.

**Основні налаштування:*** **Мінімальна площа зразка для калібрування (px)**: Поріг розміру для виявлення мішеней (за замовчуванням:**25**, діапазон 0–10000)
* **Мінімальна кластеризація мішеней (0–100)**: Поріг схожості для групування областей мішеней (за замовчуванням:**60**)**Коли слід коригувати:**

* Збільште площу вибірки, якщо трапляються помилкові виявлення
* Зменште, якщо мішені не виявляються
* Налаштуйте кластеризацію, якщо мішені розділяються на кілька виявлень

{% hint style="info" %}
Ці параметри недоступні (зафарбовані сірим), коли вимкнено **калібрування відбиття / баланс білого** — при вимкненому калібруванні виявлення цілей взагалі не працює.
{% endhint %}

### Обробка

Основні параметри обробки зображень та калібрування.

**Ключові налаштування:*** **Корекція віньєтування**: Компенсує затемнення по краях об’єктива ✅ Рекомендовано
* **Калібрування відбивної здатності / баланс білого**: Калібрує зображення за допомогою виявлених мішеней (Survey3) та/або даних світлового датчика DAQ (LATTICE) ✅ Рекомендовано
* **Метод дебейєризації**: Алгоритм перетворення RAW у 3-канальний мультиспектральний формат
* **Мінімальний інтервал повторної калібрування**: Мінімальний час у секундах між використанням калібрувальних мішеней (за замовчуванням:**0** = використовувати всі, діапазон 0–3600)**Некалібровані резервні продукти:**Коли кадр неможливо відкалібрувати за відбивною здатністю (відсутня мітка або калібрування вимкнено), його експортують як один із двох резервних продуктів —**на кожен запуск існує саме один із цієї пари**, який обирається за допомогою перемикача корекції віньєтування:

* **Експорт відгуку датчика**: записує `Sensor_Response_Images` — використовується, коли корекція віньєтування**вимкнена*** **Експорт із корекцією віньєтування**: записує `Vignette_Corrected_Images` — використовується, коли корекція віньєтування**увімкнена**Поле вибору, яке не використовується, зафарбоване сірим кольором. Зняття позначки з активного поля повністю зупиняє запис цього файлу.**Продукти експорту LATTICE** (відображаються для кожного проєкту; застосовуються до знімків, зроблених за допомогою LATTICE):

* **Експорт з дебейєрингом**: лінійне зображення з дебейєрингом (`Debayered_Images`). Застосовується до RGB та мультиспектральних модулів.
* **Експорт попереднього перегляду**: попередній перегляд на екрані (`Preview_Images`). RGB = баланс білого (джерело освітлення DAQ, якщо доступне, інакше — «сірий світ») + гамма; мультиспектральні — розтягнення у фальшивих кольорах.
* **Експорт яскравості**: спектральна яскравість типу float32 (`Radiance_Images`, Вт/м²/ср/нм). Тільки для мультиспектральних модулів — не застосовується до мастерів RGB.
* ****Експорт коефіцієнта відбиття**: коефіцієнт відбиття типу uint16 (`Reflectance_Calibrated_Images`, DN 32768 = ρ 1,0), коли кадр охоплений показанням `.daq` для нисхідного випромінювання або цільовим об’єктом у кадрі. Тільки для мультиспектральних модулів.

Усі чотири параметри **увімкнені за замовчуванням**— один імпортований необроблений кадр LATTICE розподіляється між усіма увімкненими та відповідними продуктами за один цикл обробки. Поле**Експорт відбивної здатності** зафарбоване сірим кольором, коли калібрування відбивної здатності вимкнено. Параметри, які неможливо змінити через стан батьківського перемикача, завжди відображаються сірим кольором із підказкою, що вказує назву перемикача, який потрібно змінити.**Розширені налаштування:*** **Зсув часового поясу датчика освітленості**: Кількість годин від UTC для синхронізації часу датчика освітленості (за замовчуванням: 0, діапазон від −12 до +12)
* **Застосувати корекції PPK**: Використовує дані GPS/експозиційних контактів із файлів `.daq` (за замовчуванням: вимкнено)
* **Експозиційні контакти 1/2**: Призначає камери експозиційним контактам для конфігурацій із двома камерами

{% hint style="info" %}
**Рівень вхідних даних LATTICE встановлюється автоматично.** Знімки LATTICE містять інформацію про рівень обробки у метаданих XMP, і обробка завжди починається з необробленого кадру — у графічному інтерфейсі користувача нічого налаштовувати не потрібно. (Прапор CLI `--input-level` існує як опція для досвідчених користувачів, що дозволяє замінити налаштування для знімків із втраченими метаданими; див. [CLI Довідник](../reference/cli-reference.md).)
{% endhint %}

### Метод дебейєрингу

Наразі ми пропонуємо 2 методи дебейєрингу в Chloros:

#### Стандартний (Швидкий, Середня якість)

Стандартний дебейєр обробляє дані швидко, але демонструє колірний шум під час дебейєрингу, що призводить до менш точних і більш зашумлених зображень.

#### З урахуванням текстури (повільний, найвища якість) \[Тільки Chloros+]

Метод «З урахуванням текстури» використовує високоякісний алгоритм дебайєрингу з урахуванням країв у поєднанні з моделлю шумозаглушення на основі ШІ/машинного навчання, яка усуває майже весь шум, пов’язаний з дебайєрингом. Для роботи моделі потрібна пам’ять графічного процесора (VRAM): при **7 ГБ або більше VRAM** вона може обробляти кілька зображень одночасно; при обсязі менше 7 ГБ вона обробляє одне зображення за раз (що помітно уповільнює роботу). Див. [Динамічна адаптація обчислювальних ресурсів](../processing-architecture/dynamic-compute-adaptation.md).

{% hint style="info" %}
**Знімки LATTICE завжди використовують стандартну демозаїку.** Моделі Texture Aware, навченої на даних LATTICE, не існує, тому ця опція не пропонується для знімків LATTICE — однак знімки Survey3 у тому самому проєкті все ще можуть її використовувати.
{% endhint %}

### Індекс (мультиспектральні індекси)

Налаштуйте, які індекси рослинності слід обчислювати та експортувати. У випадаючому меню графічного інтерфейсу доступно **27 попередньо визначених формул індексів**.**Як додати індекси:**

1. Натисніть кнопку**«Додати індекс»**

2. Виберіть індекс із випадаючого меню (NDVI, NDRE, GNDVI тощо)
3. Налаштуйте параметри візуалізації (кольори LUT, діапазони значень)
4. Додайте кілька індексів за потреби

**Популярні індекси:*** **NDVI**: Загальний стан рослинності (найпоширеніший)
* **NDRE**: Раннє виявлення стресу разом з RedEdge
* **GNDVI**: Чутливий до концентрації хлорофілу
* **OSAVI**: добре працює на ділянках із видимим ґрунтом
* **EVI**: Ділянки з високим індексом листової поверхні (LAI)**Власні формули:**

* Створюйте власні формули мультиспектральних індексів за допомогою математичних операцій з діапазонами для всіх каналів зображення
* Зберігайте власні формули для повторного використання
* Власні формули є функцією Chloros+; їхня доступність залежить від рівня вашого тарифного плану

Щоб ознайомитися з усіма доступними індексами та формулами — включаючи інформацію про те, які назви доступні лише в графічному інтерфейсі, а які також працюють у CLI/SDK — див. [Формули мультиспектральних індексів](../project-settings/multispectral-index-formulas.md).

### Експорт

Керує форматом вихідного файлу.

**Доступні формати**(параметр:**Формат каліброваного зображення**, за замовчуванням**TIFF (16-біт)**):

* **TIFF (16-біт)**: Рекомендується для ГІС та наукового аналізу
* **TIFF (32-біт, відсотки)**: Значення з плаваючою комою
* **PNG (8-біт)**: стиснення без втрат для візуалізації
* **JPG (8-біт)**: найменші файли, стиснення з втратами

Результати записуються у папці проєкту, згруповані за камерою та форматом: `<project>/<camera>/<format>/<Product>_Images/`. Значення яскравості **завжди** записуються як float32 у папку `tiff32`, незалежно від цього параметра. Експортовані файли зберігають ім’я вихідного файлу — папка ідентифікує продукт. Див. [Завершення обробки](finishing-the-processing.md) для перегляду повної структури вихідних файлів.

{% hint style="warning" %}
**Зчитування значень відбивної здатності**: значення DN, яке означає ρ = 1,0, залежить від вихідної камери — LATTICE використовує 32768 (позначено як XMP `Chloros:PixelScale`), Survey3 використовує 65535. Зчитуйте значення тегу, а не припускайте, що воно є постійним. Див. [Формати вихідних зображень](../output-image-formats.md).
{% endhint %}

### Датчик освітленості DAQ

У цьому розділі перелічено всі файли DAQ з даними про сонячне випромінювання (`.daq` / `.csv`) у вашому проєкті, по одному рядку на файл, із зазначенням моделі датчика, імені файлу та **ограничення** дифузора, що застосовується до цього файлу.

* **Перевизначення корекції дифузора (усі файли)**: єдине випадаюче меню для всього проєкту. У режимі**Авто** (за замовчуванням) використовується записана корекція дифузора кожного файлу — якщо нічого не записано, передбачається сонячне світло, оскільки всі DAQ-файли MAPIR постачаються з коректором сонячного світла. Вибір обмеження замінює значення для кожного файлу: необроблені записи коригуються з його використанням, а записи, що вже містять обмеження, переорієнтуються (записана корекція скасовується, застосовується вибране обмеження).
* У рядках з’являються попередження, якщо записане обмеження було встановлено системою за замовчуванням, а не підтверджено оператором, а також якщо для обраного обмеження відсутній профіль для даної моделі пристрою (у такому випадку заміщення для цього файлу відхиляється).

Записи DAQ, зроблені на вкладці «Світлові датчики», автоматично додаються до відкритого проєкту, а імпортовані файли `.daq` / `.csv` з’являються тут одразу після їх додавання.

<figure><img src="../.gitbook/assets/image (32).png" alt=""><figcaption><p>Нижні налаштування проєкту — Індекс, Формат експорту, розділ «Данні з датчиків освітлення» та елементи керування шаблоном/папкою проєкту</p></figcaption></figure>### Вирівнювання масиву

Цей розділ з’являється **лише** тоді, коли хоча б одне зображення в проєкті містить трансформацію вирівнювання «модуль до модуля», яку масиви LATTICE накладають під час зйомки (`Chloros:Alignment*` XMP). Тут показано, скільки зображень містять теги та яка камера є еталонною, а також доступні такі елементи керування:

* **Застосувати вирівнювання масиву** (за замовчуванням: увімкнено): деформує кожен оброблений продукт (без бейєрингу / попередній перегляд / інтенсивність випромінювання / відбивна здатність / індекс) відповідно до спільної еталонної геометрії масиву. Вимкнено = експорт у власній геометрії датчика.
* **Обрізати до загального перекриття** (за замовчуванням: увімкнено): обрізати вирівняні експортовані дані до області, спільну для всіх модулів, щоб кожна смуга мала однакову площу. Вимкнено — зберігається повне поле датчика (чорне заповнення за межами джерела).
* **Передискретизація**:**Білінійна (згладжена, за замовчуванням)**,**Найближча (збереження точних значень)**— без змішування між пікселями, для суворого радіометричного аналізу — або**Кубічна (найчіткіша)**.***

## Збереження та завантаження налаштувань

### Збереження шаблону проєкту

Створіть шаблони для багаторазового використання, щоб забезпечити послідовність робочих процесів:

1. Налаштуйте всі необхідні параметри на панелі «Налаштування проєкту»
2. Прокрутіть до розділу **«Зберегти шаблон проєкту»** внизу
3. Введіть описову назву шаблону (наприклад, «Survey3N\_RGN\_Agriculture»)
4. Натисніть піктограму збереження

**Переваги:**

* Застосовуйте однакові налаштування у багатьох проєктах
* Діліться конфігураціями з членами команди
* Забезпечте узгодженість при повторних опитуваннях

### Завантаження шаблону в новий проєкт

Під час створення нового проєкту:

1. Виберіть **«Новий проєкт»** у головному меню
2. Оберіть шаблон проєкту в додатковому вікні вибору шаблонів
3. Усі налаштування з шаблону застосовуються автоматично

### Робоча папка

Налаштування **«Робоча папка»** визначає, де за замовчуванням створюються нові проекти:

* **Розташування за замовчуванням**: `C:\Users\[Username]\Chloros Projects`
* **Змінити розташування**: натисніть значок редагування та виберіть нову папку
* **Спільний доступ із CLI**: `chloros-cli` використовує ті самі налаштування папки проектів за замовчуванням
* **Коли змінювати**:
  * Мережевий диск для спільної роботи команди
  * Інший диск із більшим об’ємом пам’яті
  * Упорядкована структура папок за роком/клієнтом

## Налаштування PPK (Post-Processed Kinematic)

Якщо ви використовуєте реєстратори даних MAPIR із GPS для точного геопозиціонування:

### Необхідні умови

* Записник MAPIR DAQ із модулем GPS (GNSS)
* Файл журналу .daq із записами про контакти експозиції
* Камера, підключена до контактів експозиції записника DAQ під час сеансу зйомки

### Етапи налаштування

1. Помістіть файл журналу .daq у папку вашого проєкту
2. У налаштуваннях проєкту встановіть прапорець **«Застосувати корекції PPK»**

3. За необхідності встановіть**«Зсув часового поясу датчика освітленості»** (за замовчуванням: 0 для UTC)
4. Призначте камери контактам експозиції:
   * **Одна камера**: автоматично призначається до контакту 1
   * **Дві камери**: вручну призначте кожну камеру до відповідного контакту**Призначення контактів експозиції:*** **Контакт експозиції 1**: виберіть модель камери зі списку, що розкривається
* **Контакт експозиції 2**: виберіть другу камеру або «Не використовувати»
* Одну й ту саму камеру не можна призначити обом контактам

{% hint style="warning" %}
**Важливо**: Контакти експозиції необхідно правильно призначити відповідним камерам. Неправильне призначення призведе до неправильних даних геолокації.
{% endhint %}

## Розширені сценарії

### Проєкти з кількома камерами

Під час обробки зображень з декількох камер MAPIR в одному проєкті:

1. Chloros автоматично визначає модель кожної камери (як Survey3, так і LATTICE)
2. Кожній камері присвоюються відповідні профілі обробки, а також створюється власна структура папок для вихідних даних
3. PPK: вручну призначте кожній камері Survey3 відповідний контакт експозиції
4. Усі камери використовують однаковий формат експорту та індекси

**Приклади**: Survey3W RGN + Survey3N OCN — установка з двома камерами, або матриця LATTICE, що поєднує головну камеру RGB із вузькосмуговими модулями

### Таймлапс або багатодатові зйомки

Для повторних зйомок однієї й тієї ж ділянки з плином часу:

1. Створіть шаблон зі стандартними налаштуваннями
2. Використовуйте однакову конфігурацію калібрувальних мішеней під час кожного сеансу
3. Обробляйте кожну дату як окремий проєкт
4. Використовуйте однакові налаштування для отримання порівнянних результатів
5. Експортуйте у однаковий формат для часового аналізу

### Великі набори даних

Для проєктів із великою кількістю зображень (500+):

* Розгляньте можливість поділу на менші проекти за датою або територією
* Використовуйте паралельну обробку Chloros+ для прискорення отримання результатів
* Розгляньте можливість використання CLI або API для автоматизації пакетної обробки
* Налаштуйте мінімальний інтервал повторної калібрування, щоб скоротити час виявлення цілей

## Перевірка налаштувань

Перед початком обробки перевірте такі ключові налаштування:

* [ ] Модель камери правильно визначена у файловому браузері
* [ ] Увімкнено корекцію віньєтування
* [ ] Увімкнено калібрування відбиття
* [ ] Для Survey3: імпортовано та перевірено принаймні одне зображення калібрувальної мітки; для LATTICE: наявна мітка та/або запис `.daq` у напрямку до поверхні
* [ ] Додано необхідні мультиспектральні індекси
* [ ] Формат експорту відповідає вашому робочому процесу
* [ ] Налаштовано параметри PPK (якщо використовується файл .daq із подіями експозиції)
