# Налаштування параметрів проєкту

Перед обробкою зображень важливо налаштувати параметри проєкту відповідно до вимог вашого робочого процесу. Панель «Налаштування проєкту» <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line"> забезпечує повний контроль над калібруванням, параметрами обробки, мультиспектральними індексами та форматами експорту.

## Доступ до налаштувань проєкту

1. Відкрийте свій проєкт у програмі Chloros
2. Натисніть на піктограму **Налаштування проєкту** <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line"> на лівій бічній панелі
3. На панелі «Налаштування проєкту» відображаються всі параметри конфігурації

<figure><img src="../.gitbook/assets/image (28).png" alt=""><figcaption><p>Панель «Налаштування проєкту» — відображення, виявлення об’єктів та обробка</p></figcaption></figure>

{% hint style="info" %}
**Налаштування зберігаються автоматично** разом із вашим проєктом. Коли ви знову відкриваєте проєкт, усі налаштування відновлюються.
{% endhint %}

***

## Швидке налаштування для типових робочих процесів

### Налаштування за замовчуванням (рекомендовано для більшості користувачів)

Налаштування за замовчуванням добре підходять для типових робочих процесів із використанням Survey3
та LATTICE:

* ✅ **Корекція віньєтування**: Увімкнено
* ✅ **Калібрування відбиття / баланс білого**: увімкнено (використовує мішені MAPIR
та/або дані світлового датчика DAQ)
* ✅ **Метод дебейєрингу**: стандартний (швидкий, середня якість)
* ✅ **Формат експорту**: TIFF
(16-бітний) (TIFF
(8-бітний) для проектів, що повністю використовують 8-бітну глибину)
* ✅ **Усі результати експорту**: Увімкнено (LATTICE автоматично створює розгортку у формати з дебейєром, попереднього перегляду, радіансної яскравості та відбиття)

Просто імпортуйте свої зображення та розпочніть обробку з цими налаштуваннями за замовчуванням.

## Огляд налаштувань проєкту

Панель «Налаштування проєкту» поділена на наведені нижче розділи. Два додаткові розділи — **Світловий датчик DAQ**та**Вирівнювання масиву** — з’являються автоматично, якщо ваш проєкт містить відповідні файли. Повну документацію див. у розділі [Налаштування проєкту](../project-settings/project-settings.md).

### Відображення

* **Роздільна здатність мініатюр зображень**: Роздільна здатність мініатюр у сітці зображень. Варіанти:**За замовчуванням (512 пікселів)**,**1024 пікселі**,**2048 пікселів**,**Повна роздільна здатність**. Цей параметр впливає лише на відображення — він ніколи не впливає на обробку. Більші значення забезпечують чіткіше зображення при збільшенні, але завантажуються повільніше.

### Виявлення мішеней

Керує тим, як Chloros
ідентифікує калібрувальні мішені на ваших зображеннях.

**Ключові налаштування:*** **Мінімальна площа калібрувального зразка (px)**: Поріг розміру для виявлення мішеней (за замовчуванням:**25**, діапазон 0–10000)
* **Мінімальний коефіцієнт кластеризації мішеней (0–100)**: поріг схожості для групування областей мішеней (за замовчуванням:**60**)**Коли слід коригувати:**

* Збільште площу вибірки, якщо трапляються помилкові виявлення
* Зменште, якщо цілі не виявляються
* Відкоригуйте кластеризацію, якщо цілі розділяються на кілька виявлених об’єктів

{% hint style="info" %}
Ці параметри недоступні (зафарбовані сірим), коли вимкнено **Калібрування відбиття / баланс білого** — при вимкненому параметрі виявлення цілей взагалі не працює.
{% endhint %}

### Обробка

Основні параметри обробки зображень та калібрування.

**Ключові налаштування:*** **Корекція віньєтування**: компенсує затемнення по краях об’єктива ✅ Рекомендовано
* **Калібрування відбиття / баланс білого**: калібрує зображення за допомогою виявлених мішеней (Survey3
) та/або даних світлового датчика DAQ (LATTICE) ✅ Рекомендовано
* **Метод дебейєра**: Алгоритм перетворення RAW у 3-канальний мультиспектральний формат
* **Мінімальний інтервал повторної калібрування**: Мінімальний час у секундах між використанням калібрувальних мішеней (за замовчуванням:**0** = використовувати всі, діапазон 0–3600)**Некалібровані резервні продукти:**Коли кадр неможливо відкалібрувати за відбивною здатністю (відсутні мішені або калібрування вимкнено), його експортують як один із двох резервних продуктів —**на кожен прогін припадає саме один із пари**, який обирається за допомогою перемикача корекції віньєтування:

* **Експорт відгуку датчика**: записує `Sensor_Response_Images` — використовується, коли корекція віньєтування**вимкнена*** **Експорт із корекцією віньєтування**: записує `Vignette_Corrected_Images` — використовується, коли корекція віньєтування**увімкнена**Поле вибору, яке не використовується, зафарбоване сірим кольором. Зняття галочки з активного поля повністю зупиняє запис цього файлу.**Результати експорту LATTICE** (відображаються для кожного проєкту; застосовуються до знімків, зроблених за допомогою LATTICE):

* **Експорт з дебейєрингом**: лінійне зображення після дебейєрингу (`Debayered_Images`): видалено темне зміщення калібрувального набору, потім виконано демозаїкування, без плоского поля та розкладання — той самий файл, який знімок зберігає на рівні дебейєрингу — у природній орієнтації сенсора. Застосовується до модулів RGB
та мультиспектральних.
* **Експорт попереднього перегляду**: попередній перегляд на екрані (`Preview_Images`). RGB
= баланс білого (джерело світла DAQ, якщо доступне, інакше — «сірий світ») + гамма; мультиспектральний = розтягнення у фальшивих кольорах.
* **Експорт яскравості**: спектральна яскравість типу float32 (`Radiance_Images`, Вт/м²/ср/нм). Тільки для мультиспектральних модулів — не застосовується до RGB
-мастерів.
* **Експорт коефіцієнта відбиття**: коефіцієнт відбиття типу uint16 (`Reflectance_Calibrated_Images`, DN 32768 = ρ 1,0), коли кадр охоплює значення `.daq` для випромінювання, спрямованого вниз, або цільовий об’єкт у кадрі. Тільки для мультиспектральних модулів.

Усі чотири параметри **увімкнені за замовчуванням**— один імпортований необроблений кадр LATTICE розподіляється між усіма увімкненими та відповідними продуктами за один цикл обробки. Поле**Експорт відбивної здатності** зафарбоване сірим кольором, коли калібрування відбивної здатності вимкнено. Параметри, які неможливо змінити через стан батьківського перемикача, завжди зафарбовані сірим кольором із підказкою, що вказує на перемикач, який потрібно змінити.**Розширені налаштування:*** **Зсув часового поясу датчика освітленості**: Кількість годин від UTC для синхронізації часу датчика освітленості (за замовчуванням: 0, діапазон від −12 до +12)
* **Застосувати корекції PPK**: Використовує дані GPS/експозиційних контактів із файлів `.daq` (за замовчуванням: вимкнено)
* **Експозиційні контакти 1/2**: Призначає камери експозиційним контактам для конфігурацій із двома камерами

{% hint style="info" %}
**Рівень вхідних даних LATTICE встановлюється автоматично.** Знімки LATTICE містять інформацію про рівень обробки у метаданих XMP, і обробка завжди починається з необробленого кадру — у графічному інтерфейсі нічого налаштовувати не потрібно. (Прапор CLI
`--input-level` існує як можливість перезапису для досвідчених користувачів у разі знімків із втраченими метаданими; див. [Довідник CLI
](../reference/cli-reference.md).)
{% endhint %}

### Метод дебейєрингу

Наразі в Chloros
ми пропонуємо 2 методи дебейєрингу:

#### Стандартний (швидкий, середня якість)

Стандартний дебейєр обробляє дані швидко, але створює колірний шум під час дебейєрингу, що призводить до менш точних і більш зашумлених зображень.

#### З урахуванням текстури (повільний, найвища якість) \[Тільки для Chloros
+]

Метод «З урахуванням текстури» використовує високоякісний дебейер з урахуванням країв у поєднанні з моделлю шумозаглушення на основі ШІ/машинного навчання, яка усуває майже весь шум, пов’язаний з дебейерингом. Для роботи моделі потрібна пам’ять графічного процесора (VRAM): при **7 ГБ або більше VRAM** вона може обробляти кілька зображень одночасно; при обсязі менше 7 ГБ вона обробляє по одному зображенню за раз (що помітно повільніше). Див. [Динамічну адаптацію обчислень](../processing-architecture/dynamic-compute-adaptation.md).

{% hint style="info" %}
**Знімки LATTICE завжди використовують стандартну демозаїку.** Моделі Texture Aware, навченої на даних LATTICE, не існує, тому ця опція не пропонується для знімків LATTICE — знімки Survey3
у тому самому проєкті все ще можуть її використовувати.
{% endhint %}

### Індекси (мультиспектральні індекси)

Налаштуйте, які індекси рослинності слід обчислювати та експортувати. У випадаючому меню графічного інтерфейсу доступно **27 попередньо визначених формул індексів**.**Як додати індекси:**

1. Натисніть кнопку**«Додати індекс»**

2. Виберіть індекс із випадаючого меню (NDVI
, NDRE
, GNDVI
тощо)
3. Налаштуйте параметри візуалізації (кольори LUT, діапазони значень)
4. Додайте кілька індексів за потреби

**Популярні індекси:*** **NDVI**: Загальний стан рослинності (найпоширеніший)
* **NDRE**: Раннє виявлення стресу за допомогою RedEdge
* **GNDVI**: чутливий до концентрації хлорофілу
* **OSAVI**: добре працює з видимим ґрунтом
* **EVI**: регіони з високим індексом листової поверхні (LAI
)

**Власні формули:**

* Створюйте власні формули мультиспектральних індексів за допомогою математичних операцій над усіма каналами зображення
* Зберігайте власні формули для повторного використання
* Власні формули — це функція Chloros
+; їхня доступність залежить від рівня вашого тарифного плану

Усі доступні індекси та формули — включаючи інформацію про те, які назви доступні лише в графічному інтерфейсі (GUI), а які також працюють у командному рядку (CLI
) та SDK
— див. у розділі [Формули мультиспектральних індексів](../project-settings/multispectral-index-formulas.md).

### Експорт

Керує форматом вихідного файлу.

**Доступні формати**(параметр:**Формат каліброваного зображення**, за замовчуванням**TIFF
(16-біт)**):

* **TIFF
(16-біт)**: Рекомендується для ГІС та наукового аналізу
* **TIFF
(8-біт)**: 8-бітний TIFF
* **TIFF
(32-біт, у відсотках)**: Значення з плаваючою комою
* **PNG
(8-біт)**: Стиснення без втрат для візуалізації
* **JPG (8-біт)**: Найменші файли, стиснення з втратами

У списку вказано, які формати можуть містити зображення проекту: Chloros
не збільшує розрядність. Для всіх 8-бітних зображень доступні лише формати TIFF
(8-біт), PNG
(8-біт) та JPG (8-біт), а за замовчуванням використовується TIFF
(8-біт). У змішаному проєкті кожне зображення експортується з власною глибиною або нижчою. Значення Radiance залишається 32-бітним з плаваючою комою.

Вихідні файли записуються у папці проекту, згруповані за камерою та форматом: `<project>/<camera>/<format>/<Product>_Images/`. Радіанс **завжди** записується у форматі float32 у папку `tiff32` незалежно від цього параметра. Експортовані файли зберігають ім’я вихідного файлу — папка ідентифікує продукт. Мультиспектральні експортовані дані LATTICE також можуть записувати маски обмеження для кожного пікселя у папку `clamp_masks/`, розташовану поруч із папками продуктів. Див. [Завершення обробки](finishing-the-processing.md) для перегляду повної структури вихідних файлів.

{% hint style="warning" %}
**Зчитування значень відбиття**: значення DN, яке відповідає ρ = 1,0, залежить від вихідної камери — LATTICE використовує 32768 (позначено як XMP `Chloros:PixelScale`), Survey3
— 65535. Зчитуйте значення тегу, а не припускайте, що воно є постійним. Див. [Формати вихідних зображень](../output-image-formats.md).
{% endhint %}

### Датчик освітленості DAQ

У цьому розділі перелічено всі файли DAQ з нисхідним випромінюванням (`.daq` / `.csv`) у вашому проєкті, по одному рядку на файл, із зазначенням моделі датчика, імені файлу та **обмеження** дифузора , що застосовується для цього файлу.

* **Перевизначення корекції (усі файли)**: єдине випадаюче меню для всього проєкту.**Авто** (за замовчуванням) використовує записане для кожного файлу значення межі — якщо нічого не записано, припускається сонячне світло, але DAQ-U, DAQ-M та DAQ-E постачаються без межі, а Chloros
не може визначити, що саме підібрано, тому під час обробки з’являється попередження про припущену межу: виберіть ту межу, яка була підібрана. Вибір обмеження замінює налаштування для всіх файлів, крім DAQ-E-S, дифузор якого є частиною його калібрування: необроблені записи коригуються з його використанням, а записи, що вже містять обмеження, переорієнтуються (записана корекція скасовується, застосовується вибране обмеження).
* У рядках з’являються попередження, коли записаний ковпачок був припущеним значенням за замовчуванням концентратора, а не підтвердженим оператором, а також коли для обраного ковпачка немає профілю для цієї моделі пристрою (перезапис для цього файлу відхиляється).

Записи DAQ, зроблені на вкладці «Світлові датчики», автоматично додаються до відкритого проєкту, а імпортовані файли `.daq` / `.csv` з’являються тут одразу після їх додавання.

Цей розділ з’являється **лише** тоді, коли принаймні одне зображення в проєкті містить трансформацію вирівнювання між модулями, яку масиви LATTICE накладають під час зйомки (`Chloros:Alignment*` XMP). Тут показано, скільки зображень містять теги та яка камера є еталонною, за допомогою таких елементів керування:

* **Застосувати вирівнювання масиву** (за замовчуванням: увімкнено): деформувати кожен оброблений продукт (без бейєрингу / попередній перегляд / яскравість / відбивна здатність / індекс) відповідно до спільної еталонної геометрії масиву. Вимкнено = експорт у рідній геометрії датчика.
* **Обрізати до загального перекриття** (за замовчуванням: увімкнено): обрізати вирівняні експортовані дані до області, спільну для всіх модулів, щоб кожна смуга мала однакову площу. Вимкнено — зберігається повне поле датчика (чорне заповнення за межами джерела).
* **Передискретизація**:**Білінійна (згладжена, за замовчуванням)**,**Найближча (збереження точних значень)**— без змішування між пікселями, для суворого радіометричного аналізу — або**Кубічна (найчіткіша)**.***

## Збереження та завантаження налаштувань

### Збереження шаблону проєкту

Створіть шаблони для багаторазового використання, щоб забезпечити послідовність робочих процесів:

2. Прокрутіть до розділу **«Зберегти шаблон проєкту»** внизу
3. Введіть описову назву шаблону (наприклад, «Survey3N

\_RGN\_Agriculture»)
4. Натисніть піктограму збереження

**Переваги:**

* Застосовуйте однакові налаштування у багатьох проектах
* Діліться конфігураціями з членами команди
* Забезпечуйте послідовність при повторних зйомках

### Завантаження шаблону для нового проєкту

Під час створення нового проєкту:

1. Виберіть **«Новий проєкт»** у головному меню
2. Оберіть шаблон проєкту у вікні вибору шаблонів (за бажанням)
3. Усі налаштування з шаблону застосовуються автоматично

### Робоча папка

Параметр **«Робоча папка»** визначає, де за замовчуванням створюються нові проекти:

* **Розташування за замовчуванням**: `Documents\MAPIR\Chloros Projects` у папці «Документи» системи Windows

(зазвичай `C:\Users\[Username]\Documents\MAPIR\Chloros Projects`; ця папка слідує за папкою «Документи», якщо її переміщує OneDrive або роумінговий профіль)
* **Змінити розташування**: натисніть значок редагування та виберіть нову папку
* **Спільний доступ з CLI**: `chloros-cli` використовує те саме налаштування папки проєкту за замовчуванням
* **Короткі шляхи в Windows**: якщо не ввімкнено підтримку довгих шляхів у Windows

, папка проекту, довжина шляху до якої перевищує приблизно 130 символів, відхиляється перед обробкою — див. [Запуск обробки](starting-the-processing.md#the-project-folder-is-too-deep-for-this-computer)
* **Коли слід змінити**:
  * Мережевий диск для спільної роботи команди
  * Інший диск із більшим об’ємом пам’яті
  * Упорядкована структура папок за роком/клієнтом

## Налаштування PPK (Post-Processed Kinematic)

Якщо використовуються реєстратори даних MAPIR

з GPS для точного визначення геопозиції:

### Необхідні умови

* Реєстратор даних MAPIR

з модулем GPS (GNSS)
* Файл журналу .daq із записами про контакти експозиції
* Камера, підключена до контактів експозиції реєстратора даних під час сеансу зйомки

### Етапи налаштування

1. Помістіть файл журналу .daq у папку вашого проєкту
2. У налаштуваннях проєкту встановіть прапорець **«Застосувати поправки PPK»**

3. За необхідності встановіть**«Зсув часового поясу датчика освітленості»** (за замовчуванням: 0 для UTC)
4. Призначте камери контактам експозиції:
   * **Одна камера**: автоматично призначається контакту 1
   * **Дві камери**: вручну призначте кожну камеру відповідному контакту**Призначення контактів експозиції:*** **Контакт експозиції 1**: Виберіть модель камери зі списку
* **Контакт експозиції 2**: Виберіть другу камеру або «Не використовувати»
* Одну й ту саму камеру не можна призначити обом контактам

{% hint style="warning" %}
**Важливо**: Контакти експозиції повинні бути правильно призначені відповідним камерам. Неправильне призначення призведе до отримання неправильних даних геолокації.
{% endhint %}

## Розширені сценарії

### Проєкти з кількома камерами

Під час обробки зображень з декількох камер MAPIR

в одному проєкті:

1. Chloros

автоматично визначає модель кожної камери (як Survey3

, так і LATTICE)
2. Кожна камера отримує відповідні профілі обробки та власну структуру папок вихідних даних
3. PPK: вручну призначте кожній камері Survey3

правильний контакт експозиції
4. Усі камери використовують однаковий формат експорту та індекси

**Приклади**: двокамерна установка Survey3W

RGN

+ Survey3N

OCN

, або масив LATTICE, що поєднує основну камеру RGB

з вузькосмуговими модулями

### Таймлапс або зйомки з різними датами

Для повторних зйомок однієї й тієї ж території з плином часу:

1. Створіть шаблон зі своїми стандартними налаштуваннями
2. Використовуйте однакову конфігурацію калібрувальних мішеней під час кожного сеансу
3. Обробляйте дані за кожну дату як окремий проєкт
4. Використовуйте ідентичні налаштування для отримання порівнянних результатів
5. Експортуйте у однаковому форматі для часового аналізу

### Великі набори даних

Для проєктів із великою кількістю зображень (500+):

* Розгляньте можливість поділу на менші проєкти за датою або територією
* Використовуйте паралельну обробку в Chloros

+ для прискорення отримання результатів
* Розгляньте можливість використання CLI

або API

для автоматизації пакетної обробки
* Налаштуйте мінімальний інтервал повторної калібрування, щоб скоротити час виявлення мішеней
